# 필드의 다중 문구 보조 근거

2026-09-16. `pdf-field-review/2` 확장. 기존 v1 기록은 그대로 읽고 같은 형태로 내보낸다.
전체77%/기업25% 유지: 다중 근거의 저장·검토 기반을 추가했지만 분리 표의 수치 정규화는 아직 열지 않았다.

## 사용 흐름

1. ‘03 필드 검토’에서 기본 인용과 값이 있는 필드를 고른다.
2. ‘보조 문구 찾기’→같은 PDF 페이지의 다른 문구 선택→필드 검토로 돌아온다.
3. 표 머리글/단위/각주/주변 문맥 중 역할을 골라 추가한다. 최대4개이며 중복·다른 페이지·좌표 없는 문구·변조 인용은 거부한다.
4. 각 카드에서 원문 위치를 연다. 기본 원문 위치로 돌아와 값과 모든 보조 근거의 관계를 대조하고 사유와 함께 수정 기록을 남긴다.
5. 검토 이력 JSON/프로젝트 저장으로 보관한다. 기록 전 편집은 저장을 차단하며 자동 저장은 아니다.

기본 값과 기본 인용은 그대로 유지한다. 보조 문구를 연결했다고 `36`을 `36%`로 바꾸거나 사건 수를 역산하지 않는다.
역할과 같은 페이지 여부는 같은 표·시험·집단의 의미 관계를 입증하지 않는다. 이 기록은 사용자 기재이며 전문가 인증이 아니다.
다중 근거가 있는 관측값은 일괄 확인을 막고 필드별로 확인하도록 했다. 기본 인용 교체 전에는 보조 연결을 먼저 제거해야 한다.

## 구현과 연결

- `Value.supporting`: 같은 페이지의 별도 원문 ID/페이지/정확한 인용/역할. v2에서만 허용한다.
- 추가·제거를 기존 before/after 사유 이력에 기록한다. 제거된 연결도 과거 JSON 이력에는 남는다.
- 로컬 재검증에서 모든 보조 인용을 실제 source와 대조하고 현재/원래 값의 보조 span을 입력에 포함한다. 기존40문구/24KB 제한은 유지하며 초과 시 자동 잘라내지 않는다.
- AI 재검토의 `field_context_citations`는 **채택된 관측값의 확인/수정 필드만** 전달한다. 보류/미확인 필드나 제외 행은 보내지 않는다.
- 재검토 prompt2는 연결 역할을 미검증 사용자 주장으로 취급한다. 허위 결합·열/집단/단위 혼합을 살피되 값을 바꾸거나 승인하지 않는다. 기본 추출 prompt/output 계약은 이번에 바꾸지 않았다.
- Python/브라우저가 동일 요청 hash를 대조한다. 보조 근거가 없는 기존 요청 형태는 그대로다. 기존 prompt1 결과도 계속 읽는다.
- 필드 Markdown과 회의 Markdown에 보조 인용을 표시한다. 프로젝트 저장 DB 스키마는 변경하지 않았다.

공식 [Structured Outputs 안내](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했다.
출력 구조와 임상 의미의 검증은 분리하며 기존 CLI 로그인/모델 선택/호출 한도는 변경하지 않았다.
Sites 지침에 따라 기존 MUI/간격 체계를 재사용했고 새 사이트 배포는 하지 않았다.
