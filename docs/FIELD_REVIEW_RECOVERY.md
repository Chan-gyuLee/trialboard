# 저장한 필드 검토 이어하기

구현일: 2026-09-13. 기존 MUI/PDF 화면의 로컬 소스에 추가했다. 자동 저장·서버 저장·배포는 아니다.

## 사용 순서

1. 검토를 마치기 전에 필드 검토의 **이력 JSON**을 내려받는다. 미기록 편집은 먼저 확인·수정·보류로 기록한다.
2. 원본 PDF, 추출 원문 포함 메모 JSON, 원래 에이전트 결과, 재검증 결과도 필요한 경우 별도로 보관한다.
3. 새로고침하거나 다음에 접속하면 같은 원본 PDF를 연다. 파일명은 달라도 PDF 바이트 hash가 같아야 한다.
4. **저장한 검토 이어하기**에서 이력 JSON을 선택한다. 현재 검토가 있으면 교체 전에 확인을 요청한다.
5. 원래 값·현재 값·확인/수정/보류 상태·사유·시각·모델 실행 당시 쟁점이 복구된다. 새로운 확인 이력은 만들지 않는다.
6. 당시 재검증 결과는 아래에서 별도로 불러온다. 추가 수정 후에는 새 이력을 내려받아 다시 재검증한다.

에이전트 결과를 새로 불러오는 **추출 결과 불러오기**는 모든 필드를 미확인으로 시작한다.
기록을 유지하는 **저장한 검토 이어하기**와 목적이 다르다. 새 확인에는 원문 위치 열기·직접 대조 체크·사유가 다시 필요하다.
원문 메모, PDF 파일 자체, 미기록 편집, 화면 위치, 모델 원본/재검증 파일은 이력 JSON으로 복구하지 않는다.

## 검사와 한계

- `pdf-field-review/1`의 정확한 필드, PDF hash, 모든 원래/현재/과거 인용의 페이지·문구 ID·인용문을 검사한다.
- 이력 번호가 1부터 이어지고 각 before가 직전 after와 같아야 한다. 마지막 이력과 현재 값·상태가 같아야 한다.
- 확인/보류는 값을 바꾸지 않고 수정은 실제 변경이 있어야 한다. 수동 행의 원래 값은 모두 null이다.
- 과거 확인/수정도 현재 PDF에서 위치를 표시할 수 있어야 하며 값·정수/비율의 기본 형식 검사를 통과해야 한다.
- 승인·인증·재검증 완료 주장, 중복 ID/JSON 키, 추가 필드, 잘못된 날짜·Unicode·참조를 거부한다.
- 2,000,000 UTF-8 bytes, 12개 관측값, 필드당 이력 40개, 깊이 30/파서 노드 70,000 한도가 있다.
  다운로드 전에도 같은 복구 검사를 실행해 읽을 수 없는 백업을 제공하지 않는다. 한도 초과 시 Markdown은 별도 내보낼 수 있다.
- 실패하면 기존 검토를 유지한다. PDF 교체/언마운트 중 완료된 파일 읽기로 다른 자료를 덮어쓰지 않도록 세대 번호를 사용한다.

**내부 일관성은 진위 인증이 아니다.** JSON 전체를 일관되게 위조한 경우, 실제 검토자/검토 행위/시각을 판별하지 못한다.
원래 모델 값·실행 ID도 복구 파일에 적힌 미인증 기록이다. 모델 원본 파일과의 대조는 기존 로컬 재검증에서 수행한다.
임상 승인 false, 인증되지 않은 사용자, 재검증 필요 상태를 유지하고 복구 경고를 화면에 계속 표시한다.
표 머리글·각주·임상 문맥이나 추출기의 정확성 검증을 대신하지 않는다. 파일은 서버·AI에 전송하지 않는다.

## 이전 파일과 결과의 연결

복구 파일의 원래 `sourceName`과 `limitations`를 내부 exportMetadata로 보존한다. 내부 필드는 출력 계약에 추가하지 않는다.
과거 안내 문구가 현재와 달라도 원문 기록으로 보존하며, 현재 기능 안내는 화면/이 문서를 따른다.
따라서 파일명을 바꿔 연 PDF나 이전 안내 문구를 가진 백업도 당시 재검증 결과와 전체 내용 대조가 가능하다.
재검증 대조를 느슨하게 하거나 수정 이력을 무시하지 않는다. JSON 공백/키 순서 자체를 보존하는 것은 아니다.
