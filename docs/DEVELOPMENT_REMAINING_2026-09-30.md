## 실행 원칙

- 구현은 `scripts/dacon_worker.py`의 `trialboard_dacon` / `gpt-5.6-sol`만. 감독은 계획·검토·독립 검증을 하며 구현 코드를 대신 작성하지 않는다. 대회 공급자 장애 시 개인 공급자로 전환하지 않는다.
- 명시 승인 비밀파일을 `--dacon-key-file /Users/ryul/.config/trialboard/dacon-api-key`로만 사용한다. 값 출력·인증파일 탐색·Git/프런트엔드 복사 금지.
- 첫 사이클 A/B/C의 변경과 모든 기존 미추적 파일을 보존한다. 시작 시 경로별 지문/차이를 기록하고 단계별 증분을 대조한다. 한 workspace에 writer는 하나만 둔다.
- 기존 사용자 DB 자동 마이그레이션·삭제·재암호화 금지. 개발/회귀는 별도 합성 임시 DB에서 한다. 실제 서버 설정·실사용 계정·외부 서비스는 바꾸지 않는다.
- Git commit/push/배포/외부 연락/유료 서비스 추가/영상·TTS·이미지 호출/전역 설치는 제외한다. 필요한 로컬 의존성은 최소화하고 버전·락파일·라이선스·대안 검토를 기록한다.
- 백그라운드 감독은 세션과 실행기가 활성일 때 진행한다. 앱 종료·잠자기 뒤 무인 지속을 보장하지 않는다.
- [OpenAI 공식 설정](https://learn.chatgpt.com/docs/config-file/config-reference)의 Responses 공급자/API-key 환경 헤더 설정과 기존 실행기를 확인했다. 공식 문서가 대회 모델의 실제 가용성을 보증하는 것은 아니며 실제 worker 상태로 확인한다.

## 우선순위와 완료 기준

0. **잔여 전수 점검·설계:** 이전 최종보고서, 찬규 감사, 기술명세 §18을 현재 코드와 대조. 각 항목을 구현 가능/자료·전문가·사용자 선택 필요로 분리하고 아래 순서를 필요시 근거와 함께 세분화. 사용하지 않는 독립 유틸만 만들고 기능 완료로 처리하지 않는다.
1. **계정·역할·팀 경계:** 로컬 개발용 명시적 opt-in 다사용자 모드. 인증된 주체로 서버에서 역할/팀/프로젝트 권한을 검증하고 검색·파일·실행·내보내기·이력·캐시까지 우회 경로를 감사한다. 기존 무인증 로컬 모드는 안전한 루프백 개발용으로 명확히 분리하며 원격 우회 금지. 기본 비밀번호/프런트의 role 신뢰/임의 X-Team 헤더 신뢰 금지. 세션 만료·로그아웃·권한 철회·CSRF/Origin·IDOR·팀간 차단 테스트. 실제 운영 SSO/보안 인증 완료로 표현하지 않는다.
2. **문서·팀 작업장·협업:** 권한 적용 문서 카드/프로젝트 목록, 버전/중복 식별, 공동 검토 메모·검토 승인 이력, 동시 수정 충돌 검출, 역할별 초기 화면. 승인자는 실제 인증 주체이며 임상승인과 구분. 기존 로컬 checkpoint 호환 및 명시적 가져오기 경로 유지.
3. **자료 이용조건:** 원문 저장/검색/외부AI 전송/학습 각각 허용·금지·불명 상태, 정책 버전과 근거 저장. 불명은 외부 전송·학습 허용으로 취급하지 않음. 기존 public/model consent를 약화하지 않고 서버 실제 경로에 적용. 법적 이용권을 자동 판정하거나 현재 대회 API에 비공개 자료를 전송하지 않음.
4. **작업 큐·주기갱신·실패 재시도:** opt-in 예약, 취소/재개/기한/중복방지·lease·backoff·최대시도·동의/권한 재확인·비용상한. 401/403 및 명시거부는 무한 재시도 금지. 합성 시계/가짜 수집기로 검증하고 실제 예약이나 상시 daemon을 활성화하지 않음. 변경이 없어도 실패로 취급하지 않음.
5. **조건별 캐시·분리:** 수치뿐 아니라 단위·분모·집단·시점·자료버전·알고리즘/모델 버전·정책·팀 경계가 cache key/무효화에 반영됨을 검증. 권한 철회 후 캐시 hit로 우회 금지. 근거 없는 유사도 캐시 재사용 대신 정확한 구조화 조건부터 완성.
6. **다문서 연결·병합·변경 영향:** 시험/코호트/군/용량/분석집단/시점의 출처별 관측 보존, 확실한 일치만 자동 연결, 애매한 것은 후보/보류와 사람 확인. 충돌값 덮어쓰기 금지. 자료→관측→검토/설계→회의의 실제 저장된 의존성 확대, 버전별 stale 표시와 명시 재계산. 전체 그래프를 기록하지 않았다면 완전 영향 분석이라 부르지 않음.
7. **신규 약물 자료·한영/단위 사전·인용 검토:** 공개/사용허가 비민감 dossier 입력을 구조화하고 provenance·버전 보존. 사전은 출처/범위/모호성/단위변환 규칙과 검사를 갖춤. 인용문 원문 일치와 의미 뒷받침의 범위를 분리; 자동 임상적 합리성 확정 대신 검사 가능한 모순/정보부족/검토필요 상태를 반환.
8. **표·각주·OCR 및 추적 지표:** 가능한 기존 PDF 파이프라인에 표 머리글·셀·각주 연결과 좌표/증거를 보존. OCR의 실제 도구/데이터가 없으면 연결 계약·검토 UI만 완료로 속이지 않고 그 기능을 미완료로 기록. graph completeness는 명시한 분모/범위/누락 노드 기준으로만 계산.
9. **운영·평가 도구:** 팀별 비용 계수·실행 이력·변조 감지 가능한 감사 기록, 백업/복구/보존·삭제의 dry-run과 임시 DB 검증, 접근성/실패 UX/성능 측정. 보안 암호화는 검증된 라이브러리/키관리 설계와 명시 설정을 사용하고 실사용 DB는 건드리지 않음. 독립 정답집·시간 분할/누수 검사·평가기록 입력 도구를 마련하되 합성 정답을 전문가 정답으로 표시하지 않음.
10. **통합 검증·문서 갱신:** backend/full web/ruff/build, 새 경계 공격적 음성테스트, 실제 변경 UI 데스크톱/모바일 및 로컬 전체 흐름. 실패를 숨기거나 기존 검사를 완화하지 않는다. 새 기술명세를 작성하고 과거 명세·영상 원본은 보존. 항목별 완료·부분·막힌 사유·다음 조치를 기록한다.

## 코드만으로 완료할 수 없는 항목

검증된 최적 용량/PK-PD/적응형 임상설계, 학습된 tabular/질문 예측 모델의 성능, 임상적 불일치 합리성 판정, 전문가 정답/승인, 실제 회사 SSO·보존정책·운영 배포는 데이터/전문가/인프라 선택 없이는 완료할 수 없다. 기존 결정론적 계산/연구용 가정 비교와 평가 기반을 보강하되 없는 학습·임상 검증을 생성하지 않는다. 별도 권한·자료가 필요한 특정 항목만 정지하고 의존하지 않는 개발은 계속한다.

## 감독과 실행 한도

감독 `/root/dacon_product_supervisor`가 기존 맥락을 이어 실행한다. 전용 상태는 `DEVELOPMENT_REMAINING_STATUS_2026-09-30.md`, 실행 지시/QA는 `output/dacon-remaining-20260930/`에 보존. 부모가 SESSION_HANDOFF/NEXT_TASKS/COMPLETION_ESTIMATE를 관리한다.

이번 감독 배치는 최대24 worker 실행(수정 포함), 각1200초 이하. 이는 비용·오류 폭주 방지용 실행 경계이며 이 횟수 안에 모든 기능 완료를 보장하는 약속이 아니다. 한도에 이르면 남은 목록과 재개점을 보고한다. 429는 Retry-After 또는 최소60초 이후 해당 실행 최대1회 재개, 전체횟수 포함. 인증·총할당량·모델미지원 오류는 중지·보고하며 개인 fallback 없음. CLI 누적 입력/캐시 토큰을 실제 대회 차감량으로 단정하지 않는다.

단계마다 diff·계약·테스트를 감독이 독립 검사하고 통과 후 다음 단계 진행. 보안 기반이 실패하면 그 기반에 의존하는 기능을 완성 처리하지 않는다. 전체 추정은 착수 시79%(±10%p); 기존 가중치와 검증 근거로만 갱신하고 소프트웨어 완료와 임상 평가를 구분한다.
