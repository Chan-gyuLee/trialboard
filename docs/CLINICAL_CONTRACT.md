# 원문 지표·수치 역할 계약과 공개자료 개발 사례

2026-09-13. 프롬프트 `dose-evidence-review/3`, 엔진 `bounded-evidence-agent/3.2`, 지표 사전 `clinical-labels/1.1`.

## 이번에 달라진 점

원문에 `response` 또는 `adverse_event`가 문자 그대로 있어야 했던 합성 데모 계약을 확장했다. 원문 지표명은 바꾸지 않으며, 코드가 해석한 분류는 별도 `metric_mappings`에 원문 라벨·관측값 ID·사전 버전과 함께 저장한다. 분류 일치는 임상적 동등성이나 비교 가능성의 증명이 아니다.

관측값은 `value_kind`를 반드시 명시한다.

| 종류 | 저장하는 값 | 금지하는 처리 |
| --- | --- | --- |
| `event_count` | 직접 보고된 사건 수·분모, 있으면 보고 비율도 인용 | 비율의 숫자를 사건 수로 읽기, 근거 없는 수치 사용 |
| `reported_percentage` | `%`를 포함한 원문 비율, 보고된 분석집단·분모 | 비율×분모로 반응자 수 역산, 누락을 0으로 대체 |

`reported_rate`는 모든 구조화 응답에서 필수 필드지만 미보고 시 값·인용·원문 ID가 모두 null이다. 다른 결측 필드도 같은 방식이다. 공식 OpenAI Structured Outputs의 필수 필드 + nullable 계약을 적용했다.

비율만 있는 관측값의 용량·코호트·평가 기간·분모·집단·정의가 없으면 이를 미보고로 남긴 부분 초안을 보존할 수 있다. 반드시 미해결 쟁점과 `REPORTED_RATE_ONLY`를 남겨 비교 완료 상태로 만들지 않는다. 인용 불일치, 잘못된 수치/환자군 결합, 다른 시험의 관측값은 제외한다. 기존 사건 수 경로는 필요한 필드가 없으면 채택하지 않는다.

같은 용량과 지표라도 다른 코호트·분석집단·시점은 서로 다른 관측값으로 보존한다. 동일 그룹의 중복은 여전히 충돌이며 합산하거나 조용히 삭제하지 않는다. 지표 하위 유형이 다르면 별도로 비교 제한을 남긴다.

## 지원 범위와 한계

작은 명시적 사전만 지원한다: 합성 `response`/`adverse_event`, `overall response rate`, `objective response rate`, `adverse events`, `adverse reactions`, `treatment-related adverse events`, `treatment-emergent adverse events`. 대소문자·공백만 정리하고 원문은 그대로 둔다. `ORR`은 인용된 정의에 약어 확장이 명시된 경우에만 분류하며, overall/objective 및 서로 다른 안전성 지표는 별도 하위 유형으로 유지한다. 단순히 같은 response/AE 계열이라는 이유로 비교하지 않는다.

- 정수 토큰이 퍼센트, 소수, 부호 있는 숫자의 일부인지 검사한다. 이것만으로 모든 숫자의 임상 역할이 입증되지는 않는다.
- 사건 수와 비율을 함께 보고한 경우 표기 소수 자릿수의 반올림 범위 안에서 산술적으로 일치하는지 확인한다. 원문 수치를 교체하거나 분자를 역산하지 않는다.
- 비율·분모·환자군 결합은 현재 **`<rate>% (CI...) in the <n> <group> patients` 한 가지 영어 문장 형식**만 검사한다. 이 형식에서는 전체 모집 수를 분모로 잘못 사용하거나, 다른 군의 분모/비율 또는 CI 경계를 끼워 넣으면 제외한다.
- 지원하지 않는 형식은 `RATE_BINDING_UNVERIFIED`로 남긴다. 이를 실패 없는 범용 임상 NLP로 설명하지 않는다. 복잡한 표·각주·부정 표현·다국어·여러 시점·가중/모형 추정률·연속형/생존 지표는 범위 밖이다.
- 이 문장 패턴은 비교 가능한 환자군인지, 평가불가 환자가 있는지, 사건이 환자 단위인지 등을 증명하지 않는다. 모델 반론과 전문가 검토가 여전히 필요하다.
- 실제 임상 수치를 기존 합성 시뮬레이터에 자동 투입하지 않는다.

## 공개자료 사례의 출처와 주석

[FDA의 2024-06-12 selpercatinib 갑상선암 승인 안내](https://www.fda.gov/drugs/resources-information-approved-drugs/fda-approves-selpercatinib-ret-fusion-positive-thyroid-cancer)에서 개발자가 선택한 5개 문단을 고정했다. 2026-09-13 확인. 역사적 문서 추출 사례이지 현재 처방 안내가 아니다. 이 승인 요약은 용량 비교시험 문서가 아니므로 **용량 비교가 불가능하다고 보류하는지** 확인한다.

해당 본문은 LIBRETTO-001의 두 코호트에 대해 이전 치료 환자 41명의 ORR 85%, 전신치료 미경험 환자 24명의 ORR 96%를 보고한다. 총 65명은 두 군 전체이지 각 군의 분모가 아니다. 선택 문단에 반응자 수·실제 시험 투여 용량·ORR 평가 기간은 없다. DOR의 개월 수를 ORR 평가 기간으로 사용하면 안 된다. 다른 시험 LIBRETTO-121 문단도 입력에 남겨 시험 범위를 구분하는지 확인한다.

본문 출처: 위 FDA 문서. 구현/원문: `trialboard/agent/public_case.py`. 개발자 정답과 변형 오류는 `tests/test_clinical_contract.py`에 분리해 두며 **정답은 실제 모델에 보내지 않는다**. 전문가 주석·독립 검증·시험 계열 분리된 holdout은 아직 없다.

발췌 SHA-256: `89cb0ce158a97d4b70fb19e6a8c38211b61a2cecd2d51613e009f9d51244a383`. 이는 선택한 텍스트 배열의 canonical JSON hash이며, 원본 HTML 또는 PDF 바이트 hash가 아니다. `curated_public_excerpt`, `page=null`, 원문 URL·문단 locator를 표시한다. HTML을 가짜 PDF 1페이지로 표시하지 않는다. 원문 전체나 원문 버전의 완전성 검증으로 확대하지 않는다.

기존 sotorasib PDF 후보 URL은 이번 작업에서 HTTP 404로 다운로드하지 못해 사용하지 않았다. PDF 스킬의 원문 확인 절차를 시도했지만 해당 PDF의 표/페이지 시각 검증이나 신규 PDF 입력 검증을 완료한 것으로 주장하지 않는다. 기존 PDF 기능과 원문 스냅샷은 변경하지 않았다.

## 재실행

```bash
uv run pytest tests/test_clinical_contract.py
uv run trialboard-agent --public-example selpercatinib-2024 --provider codex \
  --allow-external --max-calls 2 --max-repairs 0
```

두 번째 명령은 실제 Codex/ChatGPT 사용량을 소비한다. 개인 API 키·대회 API로 자동 전환하지 않는다. 원문은 이미 고정되어 있어 실행 중 웹 검색/자료 다운로드는 하지 않는다. `output/agent/<run-id>.json`, `.md`, `.evaluation.json`을 새로 저장하며 기존 기록을 덮어쓰지 않는다.

확인 항목 7개: 입력 일치, 두 코호트 보존, 모든 추출 시도에서 사건 수를 만들지 않음, 용량·평가 기간을 만들지 않음, 다른 시험 미채택, ORR 확장 보존, 비교 보류. 성공 사례만 읽고 끝내지 않도록 하나라도 미통과하면 CLI exit 3, 기술 실패/예산 초과는 exit 1이다. 구조적으로 올바른 다른 표현을 보수적으로 실패 처리할 수 있으며, 이 점수는 임상 정확도 %가 아니다.

개발 정답은 테스트 실행 제어용 응답과 실제 모델 호출 결과를 분리한다. 퍼센트→건수 오류, 전체 모집 수/다른 군 분모 혼입, 신뢰구간 경계 혼입, 다른 시험 혼입, 사전의 하위 지표 충돌, 부분 결측, 지원하지 않는 문장, 중복, 정답집 입력 불일치를 회귀 검사한다.

다음은 PDF 표/문단의 문맥을 보존한 평가 사례를 추가하고, 같은 숫자가 반복되는 위치·표 머리글·각주·분석집단·평가 시점을 검사한 뒤 웹 필드 확인 UI에 연결하는 것이다. 독립 전문가 평가, 실제 모델 수정/주입 내성, 배포 서비스 연결은 아직 남아 있다.

재실행에서 발견한 문제: 모델이 정의의 값은 `overall response rate`, 인용은 `overall response rate (ORR)`로 반환했을 때 사전 `/1`은 이를 미지원으로 제외했다. 올바른 인용까지 검사하도록 `/1.1`에서 수정했다. 인용 없이 약어를 추측하거나 정의와 인용이 다른 경우는 여전히 거부한다. 위조한 약어 확장 인용도 원문 대조에서 제외하는 회귀 테스트를 추가했다. 첫 성공만 보고 반복 안정성을 주장하지 않는다.

OpenAI Docs 스킬의 [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs)과 [평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 반영해 nullable 계약과 항목별 개발 검사를 만들었다. 구조화 성공을 임상 의미 정확도로 간주하지 않으며 사람의 평가를 대체하지 않는다.
