# 등록 결과 중심 자동 검토

2026-09-16. 현재 로컬 구현/검증 기록이며 배포 기록이 아니다.

## 바뀐 흐름

약물 입력·전송 동의 → 모호한 범위만 확인 → 공개 조사·결과표 포함 AI 검토 →
PDF 보관 → 등록 결과 우선 처리 → 비교 준비 점검·KOL 질문·통합 보고서.
사용자 입력란이나 중간 실행 버튼을 늘리지 않았다. 상태 표시는 실제 작업 이벤트이며 모델 내부 사고 전문이 아니다.

- `registry-context/1`: 지표/집단/분모/기간/주석/원본 위치를 유지한 결과 입력 묶음 최대2개, 각18,000자.
  일반 출처는4,500자, 검토 출처는 최대8개. 지표 블록을 통째로 포함하거나 제외하며 숫자를 중간 절단하지 않는다.
  각 묶음의 행 수와 전체 입력 커버리지를 분리한다. 실제 사례30행은 두 묶음에 전부 포함했다.
- `source-spans/2`, `dose-context/2`: 결과 묶음의 확대된 입력 범위를 인용/선정/검증에 함께 적용.
  새 모델 호출에 prompt digest 저장. 등록 계획/실제 보고 결과/다른 시험 논문을 구분하도록 지시한다.
- 등록 설계의 allocation/masking 등을 입력으로 제공. 동일 NCT의 RANDOMIZED 등록에 비무작위라고
  해석한 일부 표현은 `CONTRADICTED_ALLOCATION_CLAIM`으로 보류한다. 모든 임상 오류를 잡는 검증기는 아니다.
- 분모는 하위 항목(class)별 보고값이 있으면 이를 우선한다. 특정 집단의 분모가 없을 때 전체 분모로 채우지 않는다.
  전체 분모는 별도 참고값이며 산포·원문 주석과 함께 화면/보고서/모델 입력에 보존한다.
- `registry-readiness/1`: 서로 다른 명시 용량, 정확한 지표/하위 항목/집단, 기간/단위/분모/값의 형식을 규칙 검사한다.
  통합집단을 분할하거나 비율에서 사건 수를 역산하지 않는다. SAE를 Grade ≥3로 바꾸지 않는다.
  현재 규칙으로 원본 스냅샷에서 파생한 평가이며 과거 AI 판단으로 소급 저장하지 않는다.
  항상 clinicalApproved=false/simulationExecuted=false. 전문가 승인이나 교차표 코호트 적합성 검증이 아니다.
- `posted-results-first/1`: 실제로 검증 통과한 AI_REVIEW 입력에 모든 결과 묶음이 포함되었고
  같은 원본 스냅샷에 결과가 있을 때만 PDF를 보관한 뒤 `PLAN_DOCUMENT_SAVED`로 진행한다.
  추가 PDF 결과 추출 모델 요청은 생략한다. 그렇지 않으면 기존 추출 경로를 유지한다.
  기존 저장된 추출 결과/보류 이력을 새 정책으로 덮어쓰지 않는다.

## 실제 실행과 실패도 함께 기록

Chrome 새 입력 sotorasib → NSCLC 범위 확인 → NCT04933695, run
`2bc2945b-6d02-48f9-b269-3cada28748e7`: 약48초/79이벤트,81출처/8인용쟁점/7KOL 질문.
등록 결과24행·안전성6행, SAP43페이지/40페이지 보관. 조사2회26,190토큰 + PDF 추출1회2,080토큰.
PDF 관측0개/NEEDS_EVIDENCE. 원래 실행은 결과 우선 생략 경로 추가 전이므로 이를 새 경로의 실모델 완주로 소개하지 않는다.

실행에서 묶음1의18개 미포함을 전체 누락으로 잘못 해석한 문제를 발견했다. 전체 커버리지 표시를 수정한 후
별도 AI_REVIEW 진단1회17,343토큰에서 그 오류가 사라진 것을 확인했다. 원래 저장 기록은 수정하지 않았다.
그 진단에서는 RANDOMIZED 시험을 비무작위로 해석하는 새 오류가 발견됐다. 이후 등록 설계 입력과 위 보류 규칙을
추가해 합성 회귀검사를 통과했다. **마지막 수정은 추가 유료 모델로 재검증하지 않았다.**
이번 작업 총4요청/보고45,613토큰. 인용 문자 일치가 임상 해석의 정확성을 보장하지 않는 실제 사례다.

현재 규칙에서 같은 실제30행은 효능 비교 후보 미충족/안전성 후보 있음/NEEDS_EVIDENCE.
통합 용량 ORR만으로 용량별 효능을 만들지 않았다. 비교 설계나 시뮬레이션은 실행하지 않았다.

새 결과 우선 경로는 실제 저장 자료를 복사한 별도 임시 DB에서 검증:
PLAN_DOCUMENT_SAVED, 결과 출처2개, PDF43페이지, 모델0회, 중복 prepare 동일 결과, 원래 DB 기록 불변.
이는 새 브라우저→새 모델 전체 경로 검증과는 구분한다.

## 남은 핵심 작업

1. 근거 부족을 해결할 후속 조사와 AI 제안 가정을 구분한 복수 설계 인계. 현재 user_declared_hypothetical을
   AI가 사용자 선언인 것처럼 채우면 안 된다. 임상 승인과 연구용 가상 계산을 분리한다.
2. 결과 지표별 의미 단위 인용/600자 구간 경계, 별칭/코호트·기간의 의미 연결 및 모델 해석 품질 평가.
3. 다른 약물·등록 결과 없는 사례·실패/취소/복구·최신 모바일/키보드 QA, 제한된 실모델 재평가.
4. 독립 임상/통계 평가, 전체 실자료 시연 영상. 전자동 설계 완료/임상 검증 완료라고 소개하지 않는다.

현재 전체 계획 추정78%/기업 도입25%, 오차 최소±10%p 유지. 이번은 연결 품질 보완이지 임상 검증 확보가 아니다.
