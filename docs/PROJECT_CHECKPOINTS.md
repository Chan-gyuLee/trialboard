# 로컬 프로젝트 통합 저장·복구

2026-09-16. 제안서 전체 계획 추정 약75%, 기업 도입25% 유지. 임상 정확도와 무관하다.

## 사용 방법

1. 첫 화면의 **저장한 프로젝트 이어서** 또는 **자료 검토 → PDF 원문 확인**으로 이동한다.
2. PDF를 열고 원문 메모·필드 검토·설계를 진행한다. 작성 중 설계의 빈칸도 보관 가능하다.
3. 상단 프로젝트 이름과 비민감 자료 저장 동의를 확인한 뒤 **프로젝트 저장**을 누른다.
4. 이후 **새 버전 저장**은 기존 버전을 덮어쓰지 않고 v2, v3를 추가한다.
5. 재시작 후 최근 버전 목록 → **검사하고 프로젝트 열기**. PDF를 다시 업로드할 필요가 없다.
6. 과거 버전에서 작업을 분기하려면 **별도 프로젝트로 복사 저장**한다. 최신 버전을 덮어쓰지 않는다.

서비스는 기존 `--enable-evidence-scout` 옵션으로 활성화한다. 배포·클라우드 계정 기능이 아니다.

## 저장 범위와 제한

- PDF 원본 bytes/SHA-256, 추출 원문·원문 메모, 필드 확인·수정·보류 이력, 작성 중 설계,
  현재 결과에 연결된 설계 비교/KOL 메모, 필드 검토에 인계한 최초 에이전트 원문 JSON.
- 검색 맥락과 선택 공개 문서의 기존 DB ID를 연결한다. 서버는 검색 영수증의 NCT·적응증,
  공개 문서인 경우 조사 맥락과 다운로드 영수증의 PDF hash를 대조한다.
  이것은 동일 코호트·분석집단·임상 적용 가능성 검증이 아니다. 연구 DB 전체를 복제하는 기능도 아니다.
- 저장은 명시적 동의가 필요하며 자동 저장하지 않는다. 저장 후 변경은 다시 저장해야 한다.
- 필드/회의의 미기록 편집과 원문 메모 미기록 입력은 저장을 차단한다.
  설계/검토 변경으로 비교 결과가 오래됐으면 재계산 전 저장하지 않는다. 이전 결과를 조용히 버리지 않는다.
- AI 재검토/재검증 패널의 임시 상태, 수동으로 로컬 계산기에만 연결한 첨부 파일,
  실시간 실행 이벤트 화면의 임시 상태, CSV/별도 브리핑 탭은 포함하지 않는다.
  수동 첨부 원본이 빠진 복구는 결과 열람 가능하지만 재계산 시 다시 첨부해야 한다.
- 암호화·다중 사용자 인증·팀 동기화·규제 적합 전자서명·DB 삭제/백업 UI는 없다.
  공개·사용 허가된 비민감 자료만 사용한다. DB 파일 복사는 앱/서버 종료 후 별도로 수행한다.
- 최근100개 버전 표시, 최대100프로젝트/프로젝트당100버전/저장총량1GiB.
  PDF5MiB·40페이지, bundle32MiB, 요청48MiB. 한도 도달 시 자동 삭제하지 않는다.

## 구현과 검증 경계

`project_pdfs`는 PDF hash 중복 제거, `project_checkpoints`는 append-only 애플리케이션 기록이다.
SQLite 트랜잭션의 expected_revision 대조로 오래된 화면의 저장을409로 차단한다.
DB를 직접 편집할 수 있는 사용자를 막는 보안 감사 원장이나 저자 인증은 아니다.

서버는 PDF bytes/hash, 원문/필드 계약, bundle 크기·기본 링크를 검사한다.
브라우저 복구는 저장 PDF를 실제 재추출한 후 원문 전체/좌표·필드 이력·초안 digest·회의 report key를
기존 strict reader로 검사한다. 검사를 모두 통과한 다음에만 기존 작업을 교체한다.
추출기 변경 시 원문 좌표가 달라질 수 있어 조용히 보정하지 않고 복구를 거부한다.
기록 복구는 새 검색·모델 호출·계산·전문가 확인을 수행하지 않는다.
