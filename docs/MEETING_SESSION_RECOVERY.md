# 회의 파일 하나로 전체 검토 복구

2026-09-14. 같은 PDF와 기존 회의 JSON으로 당시의 필드 검토·설계·비교 결과·KOL 수정 이력을 함께 복구한다.
새 저장 형식은 만들지 않는다. `trialboard-meeting-packet/1`의 계산 보고서에 이미 포함된 검토 이력을 사용한다.

## 사용 방법

1. 저장할 때 사용했던 원본 PDF를 연다.
2. ‘필드 검토’ → ‘회의 파일로 전체 검토 복구’에서 `trialboard-meeting.json`을 선택한다.
3. 현재 작업 교체 안내를 확인한다. 검증에 성공하면 ‘설계 비교·KOL’의 회의 화면으로 이동한다.
4. 기존 답변/담당자/다음 행동을 읽고 새 기록을 추가한 뒤 회의 JSON을 다시 내려받는다.

필드 검토 JSON을 따로 먼저 불러올 필요가 없다. 기존 ‘회의 JSON 이어하기’는 현재 검토와 일치하는
회의 파일만 읽는 동작을 유지한다. 전체 복구는 현재 검토까지 교체하는 별도의 명시적 동작이다.

## 포함 범위와 검증

- 당시 필드의 원래 값·현재 값·확인/수정/보류·사유·이력을 원문 SHA-256과 인용 위치에 대조한다.
- 설계/검토 hash, 비교 결과 구조, KOL 메모의 보고서 결합과 수정 이력을 모두 검사한 뒤 한 번에 적용한다.
- 일부 이력만 먼저 적용하지 않는다. 실패·PDF 교체·읽기 중 취소/구성 해제 시 기존 작업을 교체하지 않는다.
- 결과 확인은 내부 일관성 검사다. 새 AI 실행·새 계산·작성자 인증·임상 승인은 아니다.
- PDF 원본, 원문 확인 메모, 미기록 필드/회의 편집, 로컬 계산용 첨부 파일, 다른 가정 초안은 복구하지 않는다.
- PDF 원문 메모는 이 동작의 교체 대상도 아니다. PDF 교체/제거 때는 별도의 기존 경고를 따른다.
- 현재 세션 교체는 검토/설계/KOL 기록을 초기화한다. 일반 검토/추출 파일로 교체할 때도 기존 설계 세션을 재사용하지 않는다.
- 외부 전송·자동 저장 없이 브라우저에서 읽는다. 최대 회의 파일24 MiB, 내부 검토2 MB 등 기존 제한을 유지한다.
- 미기록 필드 편집이 있으면 검토 메모/이력 JSON 내보내기를 잠근다. 변경 기록 또는 편집 취소 후 저장한다.

## 검증 현황

신규9개 검사: 전체 세션 왕복, 수정 이력 추가 후 재복구, 다른 PDF, 누락/잘못된 이력/인용,
승인 위조, 결과/회의 hash 불일치, 미지원 형식 거부. 전체 웹456개·Python387개·production build 통과.
기존 합성 시연 파일도 복구 → 내보내기 → 복구를 통과했다: 관측값4개, 계산4개, 질문8개, 메모이력1개 동일.
이는 코드 경로 검사이며 실제 브라우저 클릭 검증은 아니다. 다른 Chrome 창으로 대상이 전환되어 UI 조작을 중단했다.

남은 화면 검사: 전체 복구 버튼/교체 취소/실패 후 기존 작업 유지, KOL 수정·다운로드·재복구,
미기록 편집의 내보내기 잠금, 좁은 화면·키보드 이동. UI 재개 전 대상 탭 확인이 필요하다.
