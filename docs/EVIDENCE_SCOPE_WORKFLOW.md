# 출처에서 관측값 적용 범위까지

2026-09-16. 연구용 검토 기능이며 임상 승인·같은 코호트의 자동 인증이 아니다.

## 추가한 흐름

1. PDF 상단에 저장된 프로젝트의 약물·시험·문서 출처를 표시한다. ‘이 PDF의 수집 근거로 돌아가기’는 기존 수집/조사/출처 ID를 검사하고 그 기록을 연다. 새 검색·모델 호출은 없다. 최근에 다른 검색을 했더라도 PDF의 저장 맥락을 우선한다.
2. 에이전트 검토의 ‘핵심 문구 후보 찾기’는 PDF 전체 추출 문구에서 로컬 키워드로 후보를 찾는다. 용량·반응·안전성·집단·시점·약물·시험별 필터와 선택 이유를 제공한다. 분야별 상위 20개이며 임상적 관련성 순위나 완전한 표 추출이 아니다.
3. 선택한 후보와 같은 페이지의 앞뒤 2개 또는 6개 문구를 그대로 전송한다. 최대 40문구/24KB 본문, 기존 32KiB 요청 제한을 유지한다. 한도를 넘으면 자동 생략 대신 전송을 막는다. 전송 문구 확인·명시적 동의 후 기존 Codex 로그인 경로를 사용한다. 후보 선택으로 원문 확인 메모나 사용자 확인 기록을 만들지 않는다.
4. 필드 검토와 설계 입력에서 시험·적응증·코호트·분석집단·시점·용량·지표·분모·정의를 나란히 대조한다. 값 클릭으로 해당 관측값/필드/원문 위치로 이동한다. 미보고·확인 전·보류·인용 오류·사용자 기록을 구분한다.
5. 적용 범위 JSON은 PDF 지문과 현재 검토 지문을 포함한다. 질문 Markdown과 회의 Markdown에도 범위 대조를 붙인다. 기존 회의 JSON 스키마는 유지하며 검색 맥락은 프로젝트 체크포인트에서 보존한다.

## 한계와 보존

- 같은 NCT 문구, 같은 필드 값, 사용자 확인은 임상적으로 비교 가능한 집단이라는 증명이 아니다. 치료 차수와 자료마감일은 아직 별도 필드가 아니며 확인 질문으로 남긴다.
- 문구 차이는 정확한 문자열 차이일 뿐 임상적 불일치 판정이 아니다. 대조표는 기존 계산 차단을 해제하지 않는다.
- 표의 단위·열 제목·각주가 별도 문구로 잘리면 지원되는 수치를 확보하지 못할 수 있다. 숫자에 임의의 단위를 붙이거나 비율에서 사건 수를 역산하지 않는다.
- 후보 선택과 인계 전 임시 실행은 프로젝트에 저장되지 않는다. 실행 JSON을 보관하고 필드 검토에 인계한 뒤 프로젝트 새 버전을 저장한다.
- 저장된 `RUNNING` 조사 기록은 시작과 마지막 기록 후 각각 5분이 지난 경우에만 명시적 정리할 수 있다. 현재 서버에 실행 중인 조사가 있으면 거부한다. 부분 자료를 보존하고 `CANCELLED`/`RECOVERED` 이력을 남기며 늦은 쓰기를 막는다. 프로세스 강제 종료·자동 재시도·중단 지점 재개는 아니다. 단일 로컬 서버용이다.

## 검증 범위

새 자동 검사는 출처 ID/시험/약물/적응증 일치, 잘못된 인용, 필드 보류, 빈/중복 선택, 문맥 확장과 한도, 지문 결합, 중단 기록 보존·멱등성·늦은 쓰기 방지·동의/Origin 거부를 다룬다.
임상 전문가 정답·독립 평가·범용 표 해석의 검증을 대신하지 않는다.

실제 UI 실행 결과와 진행률은 최신 `SESSION_HANDOFF.md`, `COMPLETION_ESTIMATE.md`를 따른다.
