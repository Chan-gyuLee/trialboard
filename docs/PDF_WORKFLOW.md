# PDF 원문 확인 — 2026-09-13

## 이번 결과

고정된 FDA 페이지 이미지만 보던 것에서, 사용자가 선택한 텍스트 PDF를 직접 열어 문구를 찾고 원문 위치를 확인하는 단계로 확장했다. **임상 수치 자동 추출이나 AI 검토를 완성한 것은 아니다.** PDF 스킬의 렌더링·대조 절차에 따라 실제 원문 페이지와 강조 위치를 육안 확인했다.

로컬 소스에 구현했으며 기존 Sites 미리보기는 재배포하지 않았다. 이번 변경의 Git 커밋·push도 아직 하지 않았다.

## 실행과 사용

Node 24 환경에서:

```bash
cd web
npm ci
npm run dev
```

`http://127.0.0.1:5173` → 자료 검토 → **PDF 원문 확인**.

1. 공개 또는 사용 허가된 PDF 한 개를 선택한다. PDF 서버 업로드는 없으며 Python API도 필요하지 않다.
2. 페이지를 이동하고 현재 페이지의 문구를 검색한다. 추출 순서가 실제 읽기 순서나 표의 열 관계를 보장하지 않는다.
3. 문구를 누르면 같은 페이지의 원문 canvas에 근사 영역이 강조된다.
4. 질문과 적용 범위/추가 확인 메모를 적고, 원문과 문구를 대조했다는 체크를 한다.
5. 확인 메모를 추가하고 Markdown 또는 추출 원문 포함 JSON을 내려받는다.

같은 문구를 다시 저장하면 기존 메모가 갱신된다. 다른 PDF를 성공적으로 열면 이전 메모는 초기화된다. 실패/취소 시 이전 문서는 유지한다. 화면 메뉴를 바꿔도 메모리 상태는 유지하되 새로고침·제거하면 사라진다. 자동 저장이나 인증된 검토자 이력은 없다.

## 계약과 경계

`pdf-evidence/1`: 파일 이름·SHA-256·바이트 수·추출기 버전, 페이지별 크기·회전·상태, PDF.js text item의 원문·인덱스·근사 영역.

`pdf-evidence-review/1`: 위 자료와 선택 문구별 질문·메모·사용자 확인 시각. 확인 상태는 `USER_ATTESTED_VISUAL_MATCH`, 의미 상태는 항상 `NOT_ASSESSED`다. 원문 존재, 사용자 시각 대조, 임상 의미 지지를 구분한다. 임상 필드/Claim/DesignClause와 Python 엔진 연결은 다음 단계다.

- 좌표: 회전 적용 viewport 기준 좌상단 정규화 영역. 글꼴 ascent와 text item 너비로 만든 근사치이지 정확한 글리프 마스크가 아니다.
- 세로쓰기·RTL·기울어진 좌표·페이지 밖 위치는 현재 좌표 미지원으로 남기며 해당 문구 확인을 막는다.
- 텍스트 없는 페이지는 `NO_TEXT`, 혼합 문서는 `PARTIAL_NO_TEXT`. 문서 내용 또는 근거가 없다는 판정이 아니다.
- 메모 내보내기는 문서 hash·item·문구·페이지·좌표·상태의 일치를 다시 검사한다. Markdown은 PDF/사용자 문자열의 HTML·링크 문법을 이스케이프한다.
- JSON은 추출 문구 전체를 포함하지만 PDF 바이트는 포함하지 않는다. 원본 PDF는 별도로 보관해야 한다.

## 제한·보안

5 MiB, 40페이지, 20,000 text item, 250,000자, 문서당 메모 100개. 읽기 20초, 페이지 렌더링 10초를 제한하고 취소/실패 시 worker 정리를 요청한다. 페이지 canvas는 약 200만 픽셀 이내로 제한한다. 1,600만 픽셀 초과 이미지는 생략될 수 있으므로 불완전한 원문을 확인 완료로 표시하지 말라는 안내를 넣었다.

이 제한은 악의적 압축 PDF에 대한 완전한 CPU/메모리 격리나 기업 보안 검증이 아니다. 브라우저의 메인 스레드가 장시간 막히면 타이머도 지연될 수 있다. 초기 범위는 허가된 공개/비민감 문서이며 환자 식별정보·기업 기밀자료는 받지 않는다.

PDF.js 6.3.289를 고정했다. worker·CMap·기본 글꼴·디코더는 로컬/동일 사이트 자산으로 제공한다. 파일 내용은 서버로 보내지 않는다. PDF 링크/양식 동작/스크립트 실행 UI는 만들지 않았고 XFA는 비활성화했다. 문서의 내장 지시문은 명령으로 실행하지 않는다. 다만 PDF 파서 라이브러리 자체의 위험은 별도 유지보수 대상이다.

## 검증

- Python 108개 테스트와 Ruff 통과. 기존 API/엔진은 수정하지 않았다.
- 웹 90개 테스트: 기존 61개 + PDF 관련 29개. 파일 서명·용량, 회전/crop 좌표, 미지원 좌표, 없는 텍스트, 참조 무결성, 내보내기, 취소/시간 초과/암호/손상 오류, 실제 원문 추출 포함.
- TypeScript와 production build 통과. 기존 MUI directive 및 주 번들 500 kB 초과 경고는 남아 있다. PDF는 별도 지연 로딩 chunk다.
- 로컬 FDA 승인서한 9페이지와 가이드라인 12페이지 전체에서 텍스트 추출 성공. 각 PDF SHA-256을 고정값과 비교했다.
- 승인서한 PDF p.4와 가이드라인 PDF p.9를 원문에서 다시 렌더링하여 선택 문구의 강조 위치가 맞는지 육안 확인했다. 이는 브라우저 UI 전체 QA가 아니다.
- 실제 브라우저 파일 선택·메모 조작·키보드/스크린리더/모바일 검증, 스캔/한국어/복잡한 표의 광범위한 실문서 검증은 아직 남아 있다.

```bash
cd web
node --test tests/*.test.mjs
npm run build
node scripts/check-pdf.mjs
```

마지막 명령은 기존 로컬 PDF 스냅샷과 PDF.js의 선택적 Node canvas 의존성이 필요하다. 원본은 수정하지 않고 무시된 `output/pdf-qa/`에 확인용 PNG를 만든다. 새 clone에 스냅샷이 없으면 실제 PDF 테스트 2개만 명시적으로 skip한다. 준비 URL/hash는 [진행 기록](PROGRESS.md) 및 `trialboard/evidence/build.py`를 따른다.

참고한 1차 문서: [PDF.js 예제](https://mozilla.github.io/pdf.js/examples/), [PDF.js API](https://mozilla.github.io/pdf.js/api/), 설치된 패키지의 `types/src/display/api.d.ts`와 text layer 구현. 최신 배포판의 실제 타입을 확인해 loading task 소유권과 자원 해제를 맞췄다.

## 다음

임상 필드(용량·사건 수·분모·집단·시점)와 선택한 원문을 연결하는 편집/확인 계약을 만들고, 확인된 필드만 CSV/Python 검토 엔진에 전달한다. LLM은 그 계약 위에서 추출 초안을 보조하도록 추가한다. 지금의 문구 체크를 임상 필드 검증 완료로 간주하지 않는다.
