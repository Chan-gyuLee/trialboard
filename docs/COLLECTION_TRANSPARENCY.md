# 공개 수집 범위와 실시간 표시 · 2026-09-17

후속 변경: [쿨 블루 UI·추가 수집](COOL_THEME_AND_RETRIEVAL.md)에서 NCT/AI후속 검색을2페이지/40건으로 확대했다.
아래 요청당20건·33초 기록은 이전 구현/검증 당시 설명이다. 전문 검토 미완료라는 한계는 그대로다.

## 왜 빨랐는가

현재 수집기는 전체 웹/문헌 크롤러가 아니라 제한된 공개 API 수집기다.
ClinicalTrials.gov의 선택 시험, Europe PMC를 통한 PubMed 문헌, Drugs@FDA를 조회한다.
문헌 요청은 최대 3개를 병렬로 실행하고 요청당 20건만 가져온다. FDA는 최대 3신청,
신청별 최신 12문서, 등록 첨부는 앞 12항목, 전체 출처는 100개로 제한한다.
논문은 초록/서지정보, PDF는 우선 링크를 저장한다. PDF 다운로드·텍스트 처리는 별도 단계다.
원본 응답 스냅샷, 출처별 버전/해시, 조사-출처 연결과 검색 색인은 SQLite에 실제 저장한다.
이것은 약물 전체 지식 DB나 체계적 문헌고찰의 완료가 아니다.

점검한 기존 실행 `2437fe2e-cdf3-4018-b397-ec067f6312cf`: 초기 수집 약2.94초,
조사/AI 약35.42초, 80출처 = 초록64 + 서지3 + PDF링크12 + 등록본문1.
약물명 검색595건 중20건만 수신. 최종 AI 검토 입력8개. 별도 PDF 처리와 혼동하지 않는다.

## 바꾼 것

- 검색 요청/응답에 채널·검색어·수신/전체 응답 건수·부분수집 상태를 기록하고 화면에 표시.
- 출처 종류별 DB 집계와 AI 계획/검토 입력 ID 및 인용 구간 수를 별도로 기록.
- 이전에는 응답마다 마지막6개 출처만 전송했다. 이제 실제 출처를 중복 ID 없이6개 단위로 모두 전달한다.
  이는 실제 저장 목록의 알림이며 문헌을 하나씩 읽는 가상 작업이 아니다. 병렬 검색 간 출처 귀속을 꾸며내지 않는다.
- 실행 기본 탭에 조사 현황(검색 경로/검색어/최근 출처 제목/AI 후속 조사 이유) 표시.
- DB/초록/PDF링크/AI입력 수를 분리. AI 대기 중 마지막 알림 이후 시간 표시. 가짜 사고 과정·작업 없음.
- 결과에도 실제 수집 범위를 펼쳐 볼 수 있게 추가. 서로 겹치는 검색 hitCount는 합산하지 않는다.
- 새 저장 이벤트는 검증한 상세 수치와 출처 카드로 재생. 옛 기록에 없는 상세는 미기록 처리하며 최종 결과를 앞 시점에 끌어오지 않는다.
- 발표용 재생 옵션: 기록당2.5초. 실제 실행/기록 timestamp는 수정하지 않는다. 실제 작업에 지연을 넣지 않는다.
- 임상 전문/검색량/모델 입력 한도는 이번에 확대하지 않았다.
