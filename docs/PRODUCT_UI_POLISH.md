# 데모 촬영용 제품 UI 정리 · 2026-09-26

## 범위

실제 React/MUI 제품 화면을 수정했다. 영상용 가짜 결과나 새 임상 기능을 만들지 않았다.
Sites 디자인 지침을 참고해 기존 컴포넌트·로컬 API·저장 구조를 유지하고, 공통 디자인 규칙을 적용했다.
이번 요청은 로컬 제품 UI 개선이며 Git 업로드·사이트 배포·영상 재렌더는 수행하지 않았다.

## 바뀐 화면

- 공통: 흰 사이드바, 쿨 그레이 배경, 블루 액션, 네이비 결과 헤더. 버튼·입력·탭·카드·여백 정리.
- 입력: 약물 입력창을 중심으로 동의·보유자료 진입·시작을 정렬. 데이터 전송 동의 조건은 유지.
- 실행: 현재 작업을 강조하고 실제 수신 출처/초록/PDF 링크/AI 입력을 같은 기준선에 정렬.
  저장 기록은 ‘기록 재생’으로 유지한다. 상태 신호 애니메이션은 진행 표시일 뿐 가짜 작업 이벤트가 아니다.
- 공개 브리핑: 결론·수집 수·비교 가능성·인용 쟁점·전문가 질문 최대3개를 구획화.
- 필드 검토: 파일 관리와 복구 상세·적용 범위 표를 접어서 원문 대조 영역을 정리.
  파일 교체가 성공하면 파일 관리가 접힌다. 실패/미기록 편집 경고는 계속 드러난다.
- 설계 비교: 가정 설명·설계 사유를 펼침으로 정리, 대안2개의 참여자 수·계산 빈도를 한 화면에 배치.
  원문 근거·가정·수치 오차·보류·임상 권고 아님 표시는 유지한다.
- KOL: 회의 브리핑 헤더, 질문·답변 기록 수, 질문 목록과 메모 편집 공간.
  첫 진입 시 첫 질문을 선택하지만 답변/담당자/확인은 생성하지 않는다. 기존 선택·메모는 보존한다.
- 대표 합성 설계 사례: 근거 차이→계산 결과→회의 의제를 동일한 디자인 체계로 정리.

## 검증

- 1920×1080, 1440×1000, 390×844 화면 검사. 측정한 화면에서 가로 넘침·브라우저 실행 오류 없음.
- 약물 입력·동의 전 시작 차단/동의 후 활성화, 저장 검토 열기, 과거 작업 재생 확인.
- 대표 MOC의 실제 로컬 계산, PDF 합성 검토 복구→설계 계산→KOL 진입 확인.
- KOL 메모 입력·이력 기록·결과/회의 탭 왕복 후 내용 보존 확인. 실제 사용자 DB에는 저장하지 않음.
- 1080p에서 PDF 연결 설계 결과의 두 비교 카드가 MOC 하단 바 위에 들어오는지 위치 검사.
- 웹 테스트 1011개 통과, 외부 참고 PDF가 없는 선택적1개 테스트 skip. TypeScript/Vite 빌드 및 Ruff 통과.
- 새 모델 API 호출0. 실제 공개 기록 읽기와 합성 데이터 로컬 계산만 사용했다.
- 기존 큰 번들/MUI 빌드 경고는 남아 있다. 모든 접근성·임상 데이터·브라우저 조합을 검증한 것은 아니다.

QA 스크립트: `tmp/qa-product-polish.mjs`. 캡처·결과: `output/product-polish/` (Git 제외).
스크립트는 기존 로컬 Playwright 설치를 사용하며 제품 설치 의존성이 아니다.

## 영상에 사용할 흐름

1. 첫 화면에서 약물 입력.
2. 실제 작업 기록의 근거 수집/추가 조사 장면. 재생 사용 시 재생임을 명시.
3. 공개 근거 브리핑: 확인된 쟁점과 미확인 범위.
4. **별도 합성 사례**로 전환: 원문 대조→가정별 계산→KOL 질문.
5. 최신 화면을 캡처해 기존 Remotion 장면 교체.

저장된 공개 조사와 별도 MOC 계산을 하나의 실제 약물 자동 설계 성공처럼 연결하지 않는다.
대표 사례 고정, 새 UI 캡처 기반 영상 교체, 내레이션·최종 사용자 시청은 후속 작업이다.
제품 전체 구현율은 기존 약79%(±10%p)의 계획 추정을 유지한다. UI 개선은 임상 검증 완료가 아니다.
