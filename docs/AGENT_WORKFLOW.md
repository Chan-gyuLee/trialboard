# 제한된 근거 검토 에이전트 — 2026-09-13

최신 후속 작업: [원문 지표·수치 역할 계약](CLINICAL_CONTRACT.md). 프롬프트 `/3`·엔진 `/3.2`에서 원문 지표 라벨/코드 분류와 보고 비율/사건 수를 분리하고 FDA 공개 본문 사례를 추가했다. 아래 `/1`·`/2` 호출 기록은 당시 결과로 보존한다. 새로운 필수 필드 때문에 과거 출력 JSON을 새 스키마로 자동 읽거나 덮어쓰지 않는다.

## 현재 상태

**추출 → 코드 검증 → 모델 반론 → 수정 → 검토 초안/보류**의 실행 엔진에 공식 Codex CLI의 ChatGPT 로그인 실행 경로를 추가했다. 사용자 지시에 따라 개인 API 키가 아니라 현재 Codex 구독 사용량으로 개발한다. 대회 키는 사용하지 않는다. 아래 스크립트 데모와 실제 호출 검증을 구분한다. 어느 쪽도 임상 성능 검증이 아니다.

이번 작업은 Python CLI 엔진에 한정했다. 기존 PDF/CSV 웹, FastAPI `/api/reviews`, Sites 설정은 변경하지 않았다. 웹 버튼이나 원격 사이트에서 에이전트가 실행되는 상태는 아니다. 이전 PDF 변경을 포함한 작업 트리는 아직 커밋/push 전이다.

## 구현한 흐름

1. 질문·약물·적응증·시험과 원문 조각을 입력받는다.
2. 추출 모델이 관측값의 12개 필드를 원문 인용과 함께 반환한다: 약물, 적응증, 시험, 코호트, 용량, 지표, 사건 수, 분모, 분석집단, 관찰기간, 지표 정의, 보고 비율. `/3`부터 관측값의 `value_kind`로 직접 보고된 사건 수인지 보고 비율인지 명시한다.
3. 코드가 스키마·원문 조각 ID·정확한 인용·값의 문자 일치·정수/분모·요청 범위·중복·결측·비교 문맥을 검사한다.
4. 통과 후보가 있으면 반론 모델이 같은 원문과 후보를 대조한다. 구체적인 반론은 관측값과 원문 조각 ID, `observation_error` 또는 `comparison_limitation` 범위를 명시해야 한다. 전자는 해당 관측값을 제외한다. 후자는 원문에 근거한 관측값 초안을 보존하고 비교 판단을 보류한다. 잘못된 참조는 범위와 무관하게 실패 처리한다.
5. 오류/결측/반론을 다음 추출 요청에 전달하여 최대 두 번 수정한다. 수정한 결과도 코드 검사와 반론을 다시 거친다.
6. 결과와 시도별 후보·쟁점·모델 반론, 호출 수/사용량, 프롬프트 버전/hash, 입력 hash, 엔진 버전·실행 환경·예산을 JSON에 남긴다. 같은 데이터로 읽기용 Markdown을 만든다.

반론 역할은 같은 모델을 다른 지시로 호출하는 구조다. 독립 임상 전문가가 검증한 것으로 취급하지 않는다. `accepted`는 문자·수치 검사와 현재 모델의 관측값 오류 반론에서 제외되지 않은 초안일 뿐, 임상적 근거 승인이나 비교 가능성 확정이 아니다. 비교 제한이 있으면 관측값을 보존하더라도 결과는 보류다. 반론 범위의 분류 자체도 모델 오류 가능성이 있다.

| 종료 상태 | 의미 |
| --- | --- |
| `DRAFT_FOR_EXPERT_REVIEW` | 설정된 검사와 모델 반론에서 남은 쟁점이 없는 초안. 사람의 전문 검토 필요 |
| `PARTIAL_ABSTENTION` | 수정 한도 이후에도 근거 결측·문맥 차이·반론이 남음. 문제 없는 관측값 초안과 미해결 항목을 분리 |
| `FAILED` | API·응답 형식·실행 시간 등의 기술 실패. 실제 자료의 근거 부족으로 둔갑시키지 않음 |
| `BUDGET_EXCEEDED` | 호출/토큰 예산 한도. 미완료 후보를 채택하지 않음 |

## 네트워크 없는 실행 제어 데모

```bash
uv sync
uv run trialboard-agent --demo normal
uv run trialboard-agent --demo repair
uv run trialboard-agent --demo missing
uv run trialboard-agent --demo persistent
```

| 사례 | 스크립트가 제공하는 상황 | 확인한 결과 |
| --- | --- | --- |
| normal | 2개 용량의 반응/이상반응 집계 | 2회 호출, 초안 4개 |
| repair | 첫 추출의 분모만 20에서 200으로 잘못 반환 | 코드가 발견 → 오류 피드백 → 수정 → 재검증, 4회 호출 |
| missing | B군 이상반응 원문 없음 | 없는 값을 만들지 않고 6회에서 부분 보류 |
| persistent | 매번 잘못된 분모를 반환 | 6회에서 부분 보류, 해당 관측값 제외 |

모든 데모는 `SCRIPTED_TEST_DOUBLE` / `scripted-fixture-not-a-model`로 표시한다. 실제 API 실패를 이 데모로 대체하는 fallback은 없다. 데모의 수정은 스크립트로 예정된 응답이며 AI가 스스로 오류를 발견·수정했다는 증거가 아니다.

보고서는 `output/agent/<run-id>.json`과 `.md`에 새로 생성하며 기존 파일을 덮어쓰지 않는다. 파일 권한은 소유자 읽기/쓰기로 제한한다. Git에서 제외되는 로컬 산출물이며 DB 감사로그나 서버 저장 기능은 아니다. 보고서에는 입력 원문이 포함되므로 공유 시 주의한다.

## 실제 모델 연결

기본값은 `--provider codex`. 공식 `codex exec`가 현재 ChatGPT 로그인을 사용하며 인증 정보를 꺼내지 않는다. 비밀키를 제외한 대회 계약, 개발용 실행 제한, 향후 전환 방침은 [모델 사용 방침](MODEL_ACCESS.md)에 기록했다. 대회 규격은 받았지만 아직 adapter 구현·실제 호환성 검증·키 설정·호출은 하지 않았다.

가상자료로 실제 추출·반론을 실행하려면:

```bash
uv run trialboard-agent --live-example normal --provider codex \
  --allow-external --max-calls 2 --max-repairs 0
```

이 명령은 `--demo`와 달리 실제 사용량을 소비한다. CLI `0.154.0`의 ChatGPT 로그인이 필요하다. 별도 API 키는 필요 없다. 정확한 모델 ID가 필요하면 계정에서 사용할 수 있는 `TRIALBOARD_CODEX_MODEL`을 명시하며, 미지정 시 보고서에 CLI 기본 모델 ID를 확인하지 못했다고 표시한다.

별도 개인 API 경로인 `--provider openai`를 **명시적으로 선택할 때만** 필요한 환경 변수:

- `TRIALBOARD_OPENAI_API_KEY`: 사용자가 사용할 권한이 있는 키. 채팅/Git/브라우저에 노출하지 않고 로컬 실행 환경에 설정.
- `TRIALBOARD_OPENAI_MODEL`: Structured Outputs를 지원하고 해당 계정에서 사용 가능한 정확한 모델 ID. 비용·계정 접근을 확인하지 않고 임의 기본 모델을 선택하지 않는다.

선택 원문 전송과 사용량 소비에 동의한 경우에만 실행한다. 아래는 현재 기본 Codex 개발 경로다.

```bash
uv run trialboard-agent --pdf-export path/to/trialboard-pdf-evidence.json \
  --asset '원문 약물명' --indication '원문 적응증' --study '원문 시험명' \
  --question '이번에 검토할 질문' --provider codex --allow-external --max-calls 4
```

PDF 웹에서 사용자가 확인한 문구의 JSON 내보내기를 입력으로 받는다. 확인 문구와 같은 페이지의 앞뒤 두 text item만 원문 범위로 포함하며 사용자의 메모는 모델 입력에 넣지 않는다. 이 범위에 분모나 환자군 정의가 없으면 추가 원문이 필요하다. 원본 PDF 자체를 보내지 않는다.

파일 hash·문구·페이지·확인 상태가 export 내부에서 일치하는지 검사한다. **원본 PDF 바이트를 여기서 다시 읽어 hash를 검증하지는 않는다.** 입력 출처 상태는 `user_pdf_export_unverified`다. 문서 전체를 검토한 결과로 확대 해석하지 않는다.

직접 구성한 `AgentInput` JSON은 `--input path/to/request.json --allow-external`로 실행할 수 있다. 입력 계약은 `trialboard/agent/models.py`의 `AgentInput`, 생성 가능한 JSON Schema는 `AgentInput.model_json_schema()`를 따른다.

## 실행 한도와 API 계약

- 입력 파일 2 MB, 원문 조각 최대 40개·조각당 2,000자·합계 UTF-8 24,000바이트, 출력 관측값 최대 12개.
- 최대 6회 호출·2회 수정, 실행 전체 보고된 토큰 예산 200,000, 전체 120초. `--max-calls`와 `--max-repairs`로 더 줄일 수 있다.
- 개인 Responses API에는 호출당 출력 최대 4,000토큰을 전달한다. **Codex CLI에는 이에 대응하는 강제 상한을 확인하지 못해 4,000토큰을 프롬프트 목표로만 전달**한다. Codex 사용량은 구독 잔여량이 아니며 로컬 예산은 절대 소비량 상한을 보장하지 않는다.
- 호출 전 요청/스키마의 보수적 여유분과 출력 한도를 예약 계산하고, 응답의 사용량을 기록한다. 모델별 토큰화/과금 차이와 실패한 호출의 과금 때문에 **달러 비용의 절대 상한을 보장하지 않는다.** 실제 사용에는 모델 요금·예산 및 계정 측 지출 통제를 확인해야 한다.
- 개인 Responses adapter: HTTP 요청 100,000바이트·응답 256,000바이트 한도, HTTP timeout 30초와 전체 실행 timeout. 자동 HTTP 재시도·redirect·환경 proxy 상속 없음. `store:false`, JSON Schema strict 출력, 모델 도구 없음. `store:false`는 제공사 정책 전체의 무보존 보장이 아니다.
- Codex adapter: 프롬프트와 schema 합계 100,000바이트, stdout/stderr 합계 1,000,000바이트, 저장된 ChatGPT 로그인만 허용, 외부 도구 비활성화, schema 지정 JSON 출력, timeout/취소 시 프로세스 그룹 종료와 임시 폴더 정리. CLI 자체 재시도는 별개이며 `max-calls`는 CLI turn 수다. raw stderr와 추론 이벤트는 보고서에 저장하지 않는다.
- refusal·incomplete·JSON 오류·사용량 누락은 실패로 분리한다. 에러 응답의 원문이나 키를 보고서/로그에 넣지 않는다.
- 원문·이전 모델 출력·피드백은 비신뢰 데이터로 전달한다. 모델에게 문서 속 명령을 따르지 말라고 지시하고 실행 도구 자체를 제공하지 않는다. 이는 실제 모델 대상의 프롬프트 주입 내성 검증을 대신하지 않는다.

## 의도적으로 제한한 것

검토기는 보수적인 문자 일치를 사용한다. `/3`부터 실제 ORR 및 일부 안전성 지표의 원문 라벨을 별도 사전으로 분류하고 보고 비율을 보존한다. 단, 작은 사전과 한 가지 비율-환자군 문장 패턴만 지원한다. 번역·광범위한 동의어·단위 정규화, 복잡한 표의 열 관계는 여전히 다루지 못한다. 다양한 실제 PDF에서는 보류가 많을 수 있다. 정확한 지원 범위는 [현재 계약](CLINICAL_CONTRACT.md)을 따른다.

문자 일치는 수치의 역할이나 인용의 의미를 입증하지 않는다. 같은 문장 안에서 의미를 잘못 연결한 오류는 코드가 놓칠 수 있다. 모델 반론으로도 놓칠 수 있으므로 사람 확인과 독립 평가가 필요하다.

아직 없는 기능: 자율 근거 검색, 전문적인 후보 설계 생성, 통계 방법 선택·계산 연결, 실시간 웹 실행, 영구 저장/인증, 전문가 평가. 기존 합성 시뮬레이션에는 실제 문서에서 뽑은 값을 자동 투입하지 않는다.

## 검증 및 다음 순서

이번 단계는 **Python 195개** 전체 회귀 테스트(기존 155개 + Codex 35개 + 반론 범위 5개), Ruff·lockfile·diff 공백 검사를 통과했다. FastAPI/Starlette 관련 기존 deprecation warning 2개가 남아 있다. 웹 코드는 변경하지 않았으며 웹 90개 통과는 이전 단계의 결과다. 개인 HTTP adapter는 메모리 transport로 계약만 검사했고 실제 호출은 Codex ChatGPT 경로에서만 수행했다.

### 2026-09-13 실제 Codex smoke 실행

모두 `synthetic_fixture` 입력이며 실제 약물 데이터나 임상 정확도 평가가 아니다. 각 실행은 추출 1회·반론 1회, `max-calls=2`, `max-repairs=0`으로 제한했다. CLI는 `0.154.0`, 모델 ID는 CLI 기본값으로 정확한 ID 미확인이다. 버전 간 단일 사례 관찰이며 통계적 성능 비교로 해석하지 않는다.

| 같은 결측, 범위 분리 후 | `/2` | 3개 보존; 없는 B군 이상반응을 만들지 않음 | `PARTIAL_ABSTENTION` | [수정 후 기록](../output/agent/7596ff58-6e80-494e-9dfb-0e0abd9b7f1f.json) |

`/2` 재실행에서는 B군 이상반응 결측, 실제 용량·투여 일정 부재, 구체적인 평가 기준/집단/기간 부재를 `comparison_limitation`으로 분리했다. 원문 관측값은 보존하지만 용량 비교를 승인하지 않는다. 정상 사례의 `/1` 초안 상태도 임상 비교 승인이라는 뜻은 아니며 `/2`에서는 확인 질문이 비교 제한으로 승격될 수 있다. 정상 사례의 `/2` 재실행은 아직 하지 않았다.

위 3개 보고서의 합계는 입력 61,223·출력 3,406토큰이다. 이는 이번 작업 전체 사용량이나 구독 잔여량이 아니다. 연결 디버깅에도 최초 1회 실행과 단문 진단 2회를 사용했다. 최초 실행은 의도적으로 비활성화한 기능의 CLI 시작 알림을 알 수 없는 이벤트로 분류해 채택하지 못했고 사용량을 보존하지 못했다. 단문 진단 2회는 입력 17,444·출력 30토큰으로 확인했다. 이를 제외한 것처럼 전체 사용량을 보고하지 않는다. 총 9회 CLI 모델 turn을 시작했으며 CLI 내부 요청/재시도 수와는 다르다.

최초 실패 보고서도 `output/agent/6be378fc-334b-4211-bf8b-d121b5e8b66c.json`에 남아 있다. CLI 시작 알림의 정확한 유형만 식별하도록 수정했고, 다른 오류·도구 이벤트는 계속 실패 처리한다. 이 로컬 보고서들은 Git에서 제외되므로 새 clone에는 없으며 원문을 포함한다. 개인 API 키·대회 API·비공개 PDF는 사용하지 않았다.

### 실제 모델에서 발견한 과잉 보류

첫 결측 사례에서는 모델이 “B군 이상반응이 없어 두 용량을 비교할 수 없다”는 올바른 지적을 했지만, 기존 엔진은 이를 관측값 오류로 처리해 원문과 일치하는 두 관측값까지 제외했다. 결측을 꾸며내지는 않았으나 근거 보존에는 부적절했다.

이를 반영해 `Concern.scope`를 필수화하고 프롬프트·엔진을 `/2`로 올렸다. 관측값 오류와 비교 제한을 분리하고, 비교 제한만 있는 경우 원문 관측값은 유지하며 판단은 보류한다. 해당 회귀 테스트에 더해 실제 모델 재실행을 별도로 기록한다. 과거 `/1` 보고서는 덮어쓰지 않으며 새 계약으로 자동 마이그레이션하지 않는다.

다음 순서:

1. 승인된 공개 자료의 정답·결측·충돌 평가 세트를 만들고 평가 모델 ID를 고정한다.
2. 실제 원문 지표/단위 표현과 canonical 필드를 분리하고, 원문 라벨·값·수치 역할·문맥을 함께 검증하는 계약으로 확장한다.
3. 추출 정답·실제 모델의 수정 전후·반론 범위 분류·잘못된 보류·문서 프롬프트 주입을 사람이 평가한다. 지금 실제 모델의 자율 수정 성능은 미검증이다.
4. 필요한 문맥이 잘리는 문제를 평가해 표/문단 단위 근거 묶음과 범위 확인 UI를 도입한다.
5. 그 뒤 웹의 명시적 원문 전송 동의/실행·실패 상태와 연결한다. 개인 Codex 로그인을 서버에 공유하지 않고, 승인된 API 실행 경로와 권한 정책을 별도로 준비한다.
