# TrialBoard 기술 명세서

**현재 구현 기준 · 2026년 9월 29일 · 제품 버전 0.1.0**

> 임상 근거를 수집·원문과 대조하고, 검토한 자료에 연결된 가상 설계 대안을 계산·비교하여 다음 전문가 회의의 질문과 기록으로 이어가는 연구용 작업공간.
>
> 이 문서는 앞으로 만들고 싶은 기능이 아니라 **현재 로컬 코드에서 확인한 구현**을 설명한다. 실제 모델 기능, 결정론적 규칙·계산, 합성 시연, 아직 구현하지 않은 기능을 구분한다. 임상 성능 인증이나 출시 준비 완료를 뜻하지 않는다.

## 1. Git 반영 상태와 기준 버전

**후속 업데이트:** 사용자가 UI만 공유하도록 요청하여 `3d1c977`(web/src 17개 파일)을 원격 main에 푸시했고 원격/로컬 HEAD 일치를 확인했다. 이 명세서·README·후속 문서는 로컬에만 보존한다. 아래 1.1–1.2는 푸시 전 점검 기록이다.

## 2. 제품 범위와 현재 가능한 일

### 2.1 대상 업무

임상개발·임상약리·통계·자료 검토 담당자가 용량 비교에 필요한 근거를 정리하고, 서로 다른 가정의 설계 대안을 검토하며, KOL(Key Opinion Leader) 회의를 준비하는 업무를 지원한다.

현재 구현은 크게 두 흐름과 한 개의 별도 시연 경로다.

```text
A. 약물명 / NCT 번호
   → 등록 시험 찾기·범위 확인
   → 공개 자료 수집 → AI 후속 검색 계획 → 추가 검색 → 인용 브리핑
   → 공개 PDF 준비·관측 추출 또는 근거 부족 보류 → 저장·원문 검토 인계

B. 공개·사용 허가된 PDF / A에서 인계받은 PDF
   → 추출 초안 → 원문 필드 확인·수정·보류
   → 근거 재검증 → AI 비교 초안 또는 사용자 설계 가정
   → 사용자 확인 → 로컬 계산 → 변경 비교 → KOL 메모 → 프로젝트 저장·복구

C. 별도 MOC 합성 사례
   → 합성 근거 오류 확인 → 고정 합성 가정의 실제 계산 → 규칙 기반 회의 의제
```

**A의 자료가 언제나 B의 설계 입력으로 충분한 것은 아니다.** 원문이 이미지 표이거나 결과가 없거나 용량별 분석집단을 맞출 수 없으면 보류한다. C는 A의 실제 약물 효과를 예측하는 경로가 아니다.

### 2.2 기능 상태표

| 기능 | 현재 상태 | 중요한 경계 |
|---|---|---|
| 약물·개발 코드·NCT 입력 | 구현 | 모든 약물의 별칭·적응증을 완벽하게 해석하는 엔진 아님 |
| 등록 시험 탐색·시작점 선정 | 구현 | 문구·용량 신호 기반 우선순위, 임상 적합성 승인 아님 |
| 공개 근거 DB 구축 | 구현 | 한 실행 최대100개 제한 수집, 전체 문헌고찰 아님 |
| AI 후속 검색·인용 브리핑 | 실제 모델 연결 | 한도 내 검색·자료만 검토, 전문 전체 검토 아님 |
| 작업 과정 실시간 표시 | 구현 | 실제 도구·단계 이벤트, 모델의 비공개 사고과정 아님 |
| 공개 PDF 확보·선택 페이지 처리 | 구현 | 허용 출처·크기·쪽수 제한, OCR 없음 |
| 관측값 구조화 추출·반론·수정 루프 | 구현 | 제한된 수치·문장 계약, 전문가 검증 전 초안 |
| 사용자 필드 검토·변경 이력 | 구현 | 로컬 사용자의 확인, 인증된 전문가 서명 아님 |
| PDF 근거 연결 AI 설계 초안 | 실제 모델 연결 | 표본수2안·민감도2–3가정, 확정 프로토콜 아님 |
| 가정별 설계 계산·변경 비교 | 구현 | 고정 균등배정·독립 이항 모형, 성공률 예측 아님 |
| KOL 질문·회의 메모 | 구현 | 공개 브리핑은 AI 질문, 합성/계산 의제는 규칙 기반 |
| 로컬 프로젝트 버전·복구 | 구현 | 단일 로컬 SQLite, 팀 실시간 협업 아님 |
| CSV 집계표 검토 | 구현 | 정해진 입력 계약·명시적 비교 기준, 범용 문서 이해 아님 |
| 완전 자율 실제 약물 설계 | 미완성 | 다문서·임상 연결·실자료 종단 검증 필요 |
| 기업 SaaS·인증·권한·협업 | 미구현 | 인터넷 공개 서비스로 사용하지 않음 |

## 3. 아키텍처와 기술 스택

### 3.1 구성

```text
브라우저: React / MUI / PDF.js
   ├─ 로컬 파일 읽기·PDF 렌더·필드 검토·가정 편집
   ├─ fetch 스트림으로 서버 작업 이벤트 수신
   └─ Vite 개발 프록시 /api
                ↓
로컬 API: FastAPI / Uvicorn (127.0.0.1:8000)
   ├─ 공개 커넥터 → ClinicalTrials.gov / Europe PMC / openFDA
   ├─ 모델 어댑터 → 대회 Responses API (기본)
   ├─ 근거 재검증·설계 비교 → Python / NumPy
   └─ 저장 → SQLite + FTS5 + PDF BLOB + JSON 계약
```

대규모 에이전트 프레임워크나 벡터 DB 기반 구조가 아니다. **직접 구현한 제한형 오케스트레이터와 명시적 데이터 계약**을 사용한다. 검색은 외부 공개 API와 SQLite FTS5가 중심이며, 검색 후보의 임상 연관성을 자동 인증하지 않는다.

아래는 이번 로컬 검증 환경 및 lockfile 기준이다. 최신 버전 추천 목록이 아니다.

## 4. 사용자 흐름과 화면

### 4.1 자동 공개 조사

1. 약물명·개발 코드·NCT 번호 중 하나를 입력한다.
2. 공개 검색·외부 AI 전송에 관한 동의를 확인한다.
3. 시험·적응증이 모호하면 범위를 확인한다. 단계마다 별도 실행 버튼을 누르게 하지 않는다.
4. 실행 화면에서 현재 단계, 경과 시간, 실제 검색어, 도착 출처, 수집 범위, 모델 대기 상태를 확인한다.
5. 완료 화면에서 결론의 범위, 부족한 자료, 인용 쟁점, 다음 질문을 확인한다.
6. 저장 기록 재열기·작업 기록 재생·원문 검토로 이동한다.

출처 수, 확보 초록, PDF 링크, AI 검토 입력 수는 별도 지표다. PDF 링크를 찾았다는 것과 PDF 본문을 읽었다는 것을 같은 완료 상태로 표시하지 않는다.

### 4.2 자료 검토 작업공간

- CSV 집계표 경로와 PDF 원문 경로를 분리한다.
- PDF는 페이지·인용 영역과 구조화 필드를 대조한다.
- 추출값은 처음부터 확인 완료로 취급하지 않는다.
- 필드 확인·수정·보류, 검토 이력 복구, 설계 비교·KOL 탭으로 이어진다.
- 자료 교체·화면 종료·미기록 편집이 있을 때 손실 경고 또는 저장 차단을 적용한다.

### 4.3 결과 표현

- 공개 조사의 ‘결론’은 판단 가능 범위와 추가 근거 필요 여부다. 권장 용량을 주는 결과가 아니다.
- 설계 결과는 추가 모집 인원, 가정상 선택/보류 빈도, 가정상 한계 초과 군 선택 빈도, Monte Carlo 오차를 보여준다.
- 입력 수정 후 재계산하면 직전 실행과 입력·지표 차이를 비교한다.
- 직전 실행 비교는 현재 탭 메모리 기준이다. 모든 계산 이력이 자동 영구 보관되는 기능과 구분한다.
- 원문·가정·실제 계산·MOC·저장 기록 재생을 구분한다.

9월26일 로컬 UI 수정은 공통 여백·버튼·체크박스·지표 정렬, 파일 관리 접기, 결과 카드 및 KOL 영역 배치를 정리한 작업이다. 해당 변경은 아직 원격 main에 없다.

### 4.4 CSV 집계표 입력 계약

UTF-8 CSV 최대256KiB·데이터500행을 받는다. 열은 `asset, indication, study, dose, metric, events, total, population, window, definition`이다. 지원 지표는 반응·이상반응·감량·중단이다.

한 약물·적응증·시험의 자료인지, 사건 수·분모가 유효한 정수인지, 용량별 지표가 빠졌는지, 중복 행·분석집단·관찰기간·정의가 충돌하는지 결정론적으로 점검한다. 원래 행 번호와 원문 행을 남기고 담당자·추가 확인 항목을 만든다. LLM 호출이나 환자 수준 분석은 하지 않는다. `TABLE_CHECKS_PASSED`도 원본 임상 보고서의 진위·정확성이 검증됐다는 뜻은 아니다.

## 5. 공개 근거 조사 에이전트

### 5.1 자료 출처

| 출처 | 현재 읽는 정보 | 제한 |
|---|---|---|
| ClinicalTrials.gov API v2 | 시험 식별자, 적응증, 중재·군, 등록 설계, 결과표, 공개 프로토콜/SAP 링크 | 등록 설계와 관측 결과를 구분 |
| Europe PMC REST | `SRC:MED` 범위 문헌 검색, PMID·제목·초록·메타데이터 | UI에서 PubMed 검색으로 표기하나 실제 HTTP 커넥터는 Europe PMC |
| openFDA Drugs@FDA | 약물 신청·규제 문서 메타데이터 및 링크 | 약물 수준 문서가 특정 시험 결과임을 보장하지 않음 |
| 허용된 공개 PDF 호스트 | CT.gov CDN 및 accessdata.fda.gov의 제한된 PDF 경로 | 임의 URL 크롤링·우회 다운로드 아님 |

### 5.2 실행 순서

1. 선택 시험의 등록정보를 가져와 원본 JSON 스냅샷을 저장한다.
2. 등록부 인용 PMID, NCT 검색, 약물명 검색, FDA 경로를 수집한다. 일부 독립 검색은 비동기로 병렬 수행한다.
3. 모델이 읽을 우선 출처 최대6개와 추가 검색어 최대2개를 제안한다.
4. 서버가 검색어를 해당 약물에 묶어서 실제 공개 문헌 API에 요청한다. 모델이 임의 URL을 실행하지 않는다.
5. 등록정보·시험번호·용량 관련 신호를 이용해 최종 검토 입력을 선정한다.
6. 원문 구간에 `anchor_id`를 부여한다.
7. 모델은 구간 ID를 선택하고 한국어 쟁점·질문을 작성한다. **인용문은 서버가 원문에서 복사**한다.
8. 인용·시험 설계 주장 검사를 통과한 브리핑과 검색·호출 기록을 저장한다.

모델 호출은 정상 공개 조사 경로에서 계획1회 + 브리핑1회다. 이후 PDF 추출은 별도 호출 경로이며, 전체 사용량을 ‘항상 두 번’으로 고정해서 설명하면 안 된다.

### 5.3 검색·검토 한도

| 항목 | 현재 제한 |
|---|---|
| 최초 등록 시험 검색 | 최대20건 |
| 일반 문헌 검색 | 검색별20건 |
| NCT·AI 후속 검색 | 최대2페이지·40건 |
| 등록부 인용 PMID 조회 | 앞의20개 |
| 한 조사에 저장하는 출처 | 최대100개 |
| 최종 AI 브리핑 입력 | 최대8개 출처 |
| AI 쟁점 / 질문 | 각각 최대8개 |
| 공개 조사 API 작업 시간 | 최대240초 |
| 조사 모델 호출별 출력 | 최대3,000토큰 요청 |

검색 종료 이유도 기록한다: 결과 끝, 페이지 한도, 출처 한도, 다음 커서 없음, 새 자료 없음, 요청 실패. 중복 ID는 병합하고, 연결 근거와 원본 스냅샷 참조를 보존한다. 이는 연구 DB의 제한된 수집이지 전 세계 근거를 빠짐없이 모았다는 뜻이 아니다.

### 5.4 등록 결과표와 비교 준비 상태

효능·안전성 결과를 군·분모·평가 시점·지표 정의와 함께 보존한다. pooled 결과를 용량별로 나누거나 등록 목표 인원을 실제 분석 분모로 대체하지 않는다.

결과표가 이미 검토 입력에 들어갔고 선택 PDF가 계획 문서라면 중복 관측 추출을 생략할 수 있다. 이 분기는 ‘프로토콜을 읽어서 관측 결과를 만들었다’고 표시하지 않는다.

### 5.5 작업 상태 가시화

브라우저는 SSE 형식의 응답 스트림에서 단계·검색어·수신 출처·검토 입력 ID·경과 시간을 받는다. 서버 heartbeat와 UI 경과 표시를 사용한다. 대기 애니메이션을 새로운 작업 완료 이벤트로 위장하지 않는다.

저장 실행 재생은 기록을 다시 보여주는 기능이며 새 검색·새 모델 호출이 아니다. 실시간 ‘생각’으로 보이는 부분은 **작업 상태와 사용자용 근거 설명**이지 모델 내부 사고과정이 아니다.

## 6. PDF 처리와 관측값 추출

### 6.1 PDF 처리

- PDF.js로 브라우저에서 렌더링·텍스트 추출·근사 좌표 계산을 수행한다.
- SHA-256으로 원본 파일을 식별한다.
- 최대5MiB, 최대200쪽 문서 탐색, 한 번의 검토 연결은 최대40쪽이다.
- 긴 문서는 문구 기반 페이지 선정 또는 사용자 지정 페이지 범위를 사용한다.
- 원래 쪽수를 유지하고 전체 쪽수·선택 쪽수·생략 쪽수·텍스트 없는 쪽수를 구분한다.
- 브라우저 PDF 글꼴·CMap·WASM 자산을 빌드에 포함한다.
- 암호 PDF·지원하지 않는 XFA 문서 등을 거부한다.
- 서버에서 허용한 공개 PDF를 다운로드하면 바이트·지문·출처 영수증을 캐시한다.

**OCR은 구현하지 않았다.** 그림으로 된 표가 화면에 보여도 텍스트·수치 자동 추출이 가능하다는 의미가 아니다. 처리 실패·후보 없음·페이지 한도는 각각 표시하며, 없는 값을 추측하지 않는다.

### 6.2 구조화 입력과 출력

모델 입력 `AgentInput`에는 약물·적응증·시험·질문과 원문 구간이 들어간다.

- 원문 최대40구간, 구간당 최대2,000자, 합계 UTF-8 최대24,000바이트.
- 각 구간: ID, 원본 digest, 페이지 또는 locator, 원문 텍스트.
- 관측값 출력 최대12개.
- 관측값마다 `event_count` 또는 `reported_percentage` 유형을 명시한다.
- 각 필드는 값·인용문·원문 구간 ID를 함께 가진다. 미보고는 `null`이다.

관측값의 12개 필드:

| 구분 | 필드 |
|---|---|
| 대상 | `asset`, `indication`, `study`, `cohort`, `dose` |
| 지표·수치 | `metric`, `events`, `denominator`, `reported_rate` |
| 해석 맥락 | `population`, `window`, `definition` |

보고 비율에 분모를 곱해 사건 수를 역산하지 않는다. 비율만 보고된 경우 그 사실을 보존하고 비교 제한으로 남긴다.

### 6.3 제한형 에이전트 루프

```text
추출 → 코드 원문 검증 → 모델 반론
                 ├─ 관측값 오류 → 예산 내 수정 → 재검증
                 ├─ 비교 제한 → 올바른 관측값은 보존, 비교 판단 보류
                 └─ 초안 → 사람의 원문 검토
```

엔진 기본 상한은 호출6회·수정2회·120초·보고 토큰 예산200,000이다. 웹 엔드포인트는 사례별로 더 작은 한도를 적용한다. 예산은 실행 제어 장치이지 실패 요청까지 포함한 실제 과금의 절대 상한 보장은 아니다.

`Concern.scope`는 관측값 자체 오류(`observation_error`)와 비교에 필요한 조건 부족(`comparison_limitation`)을 나눈다. 비교 불가능하다는 이유만으로 원문과 일치하는 모든 관측값을 버리지 않는다.

## 7. 원문 대조·수정·재검증

### 7.1 사용자 검토

필드마다 원래 값과 현재 값, 인용 위치, 상태, 변경 사유·이력을 보관한다.

| 상태 | 의미 |
|---|---|
| `unreviewed` | 아직 원문 확인 전 |
| `confirmed` | 표시된 원문과 직접 대조했다고 사용자가 기록 |
| `corrected` | 수정값·근거·사유 기록 |
| `held` | 판단 보류, 미기록 값을 자동 채택하지 않음 |

AI 추출을 가져와도 미확인부터 시작한다. 원문 위치를 표시하고 대조 여부와 사유를 남기는 절차가 있다. 확인은 사용자의 진술이며 전문가 자격·실명·임상 승인을 인증하지 않는다.

### 7.2 보조 인용·비율 정규화

- 주 인용과 별도 보조 인용을 연결할 수 있다. 필드당 보조 인용은 최대4개다.
- 원문 문자열과 해석된 비율을 구분한다.
- 같은 줄의 인접 `%`와 같은 제한된 경우를 명시적 확인으로 처리한다.
- 표 머리글·각주·복잡한 셀 관계 전체를 자동으로 해석하지 않는다.
- 필드 검토 계약 v1/v2/v3로 보조 인용·정규화 이력을 구분하며 잘못된 형식 하향 변경을 거부한다.

### 7.3 코드 재검증과 AI 재검토

Python 재검증은 원본 PDF·원문 export·필드 검토 기록·필요한 원본 모델 결과를 다시 결합한다. 원문 hash, 인용, 수치, 분석 문맥, 이력과 현재값 일관성을 검사한다.

별도 AI 재반론은 현재 검토값을 비판적으로 읽고 관측값 오류와 비교 제한을 반환한다. 기존 값을 조용히 고치거나 사용자 승인을 대신하지 않는다. CLI 실행·결과 파일 가져오기 경로가 있으며, 이번 OpenAPI 목록에 독립 재반론 HTTP 엔드포인트가 있는 것은 아니다.

다른 원문·다른 검토 버전의 결과는 재사용하지 않는다. 비교 단계에서는 관련 보류·오류·문맥 불일치가 해결되지 않으면 계산을 막는다.

### 7.4 현재 의미 검증의 한계

인용의 문자 일치와 수치 산술 일치는 **그 수치가 올바른 환자군·시점·임상 의미에 연결됐음을 완전히 증명하지 않는다.** 지표 사전·영어 비율 결합 규칙의 지원 범위가 좁다. 복잡한 표, 광범위한 동의어, 생존·연속형 결과, 다국어·각주 연결은 추가 작업이 필요하다.

## 8. AI 설계 초안 제안

### 8.1 입력·선결 조건

- 검토한 PDF와 원문 export, 필드 검토 기록, 필요 시 최초 추출 결과.
- 비교 목표와 군당 최대 모집 인원.
- 비교 가능한2–4개 군, 근거 관측값 ID, 반응/이상반응 정보 및 문맥.
- 명시적 외부 모델 전송 동의.

제안 전 코드가 원문·검토 이력·관측값을 재검증한다. 근거 부족 또는 해결되지 않은 비교 제한이 있으면 모델을 호출하지 않고 보류할 수 있다.

### 8.2 출력

- `PROPOSED`: 서로 다른 표본수2안, 민감도 시나리오2–3개, 이유, 참고 관측값 ID, 추가 질문.
- `NEEDS_EVIDENCE`: 설계·가정 배열을 비우고 필요한 정보를 설명한다.
- 모델 호출1회, 출력 최대6,000토큰, 경로 전체120초 제한.
- 출처는 `ai_proposed_hypothetical`로 보존한다.

확률·안전성 한계·효용 가중치는 **AI가 제안한 연구용 가정**이다. 인용은 문제 맥락을 뒷받침하며 그 확률 숫자를 검증된 추정치로 바꾸지 않는다.

### 8.3 사람 확인과 계산 분리

‘초안 가져오기’는 승인이나 계산 실행이 아니다. 사용자가 현재 입력을 확인해야 계산할 수 있다. 확인 digest는 표본수·확률·근거·seed 등 현재 입력을 결합하며, 입력이 바뀌면 재확인이 필요하다.

서버는 계산 시점에도 근거와 확인 상태를 다시 검사한다. digest는 입력 일치 장치이지 전자서명·인증된 승인 기록이 아니다.

## 9. 설계 비교·시뮬레이션

### 9.1 세 계산 경로를 구분한다

| 경로 | 입력의 출처 | 용도 |
|---|---|---|
| 기본 합성 검토 `/api/reviews` | 고정 합성 레코드와 편집 가능한 가정 | 오류·결측·비교 흐름 시연 |
| 조사 뒤 별도 가상 탐색 `exploration` | 고정 합성 규칙 라이브러리 | 표본수3안×가정3종, 공개 근거를 계산 모수로 사용하지 않음 |
| PDF 연결 비교 `/api/design-comparisons` | 검토 관측값의 연결 + 사용자 또는 AI가 제안하고 사람이 확인한 가정 | 근거 연결 상태를 검사한 제한형 설계 비교 |

세 경로 모두 실제 계산을 하지만, 실제 약물의 참효과를 추정한 결과라고 주장하지 않는다.

### 9.2 PDF 연결 비교의 입력 한도

| 항목 | 제한 |
|---|---|
| 용량군 | 2–4개 |
| 설계안 | 2–4개, 서로 다른 군당 표본수 |
| 시나리오 | 1–6개 |
| 군당 모집 인원 | 2–500명 |
| 반복 수 | 100–20,000회 |
| 전체 계산량 | 군 수 × 설계 수 × 시나리오 수 × 반복 수 ≤1,000,000 |
| seed | 0–2³²−1 |

기본 합성 API의 반복 상한은100,000회이며 별도 전체 계산량 제한을 적용한다. PDF 연결 경로의20,000회 상한과 혼동하지 않는다.

### 9.3 계산 방법

각 군에서 가정한 반응확률·이상반응확률로 독립 이항 표본을 생성한다. 관측 이상반응률이 설정 한계 이하인 군만 후보로 두고 다음 효용이 가장 큰 군을 선택한다.

```text
utility = 관측 반응률 − adverse_event_penalty × 관측 이상반응률
```

- 같은 효용이면 균등한 무작위 동률 처리를 한다.
- 적격 군이 없으면 선택을 보류한다.
- 가정한 참확률 기준 최선 군 또는 적절한 보류와 일치한 빈도를 계산한다.
- 가정한 참 안전성 한계를 초과한 군을 선택한 빈도를 별도로 계산한다.
- 빈도별 Monte Carlo 표준오차는 `sqrt(p × (1−p) / 반복 수)`다.
- 전체 입력과 seed를 hash해 PCG64 난수 스트림을 만들므로 실행 순서에 의존하지 않는 재현성을 확보한다.
- Python/NumPy 버전·입력·엔진 digest를 결과에 남긴다.

### 9.4 출력·해석

대안별 총 모집 수·추가 인원, 군 선택 빈도, 선택 보류 빈도, 가정상 최선 선택/보류 빈도, 가정상 안전성 한계 초과 군 선택 빈도와 오차를 제공한다. 기준안 대비 차이 및 입력 변경 전후 비교를 표시한다.

계산 결과는 `HYPOTHETICAL_COMPARISON_ONLY`, 차단 결과는 `BLOCKED_EVIDENCE_LINK`로 구분한다. `clinical_approval=false`, `recommended_plan_id=null`, 계산 단계 `model_calls=0`를 유지한다.

### 9.5 구현하지 않은 통계·임상 범위

PK/PD 모형, DROID/MERIT, 적응형 배정·중간중단, 검정력·제1종 오류 기반 표본수 산정, 생존 결과, 결측·탈락·모집 기간, 임상적으로 검증된 효용함수, 확정 프로토콜·최적 용량 추천은 없다.

Monte Carlo 오차가 작다고 임상적 불확실성이 작다는 뜻은 아니다. 관측 비율을 미래 시험의 참확률로 자동 전환하지 않는다.

## 10. KOL 회의·내보내기·복구

### 10.1 질문 생성 방식

- 공개 조사 브리핑: 인용된 자료를 토대로 모델이 쟁점·질문을 작성한다.
- 설계 비교·MOC: 근거 차단 사유, 추가 모집 부담, 가정별 계산 차이를 규칙 기반 질문으로 만든다.
- 규칙 기반 질문을 AI의 임상 전문가 추론 결과로 설명하지 않는다.

### 10.2 회의 기록

질문별 답변·검토 메모·담당자·다음 행동과 수정 이력을 보관한다. 기록은 특정 계산 결과 `reportKey`에 연결한다. 다른 계산 결과의 메모를 조용히 재사용하지 않는다.

회의 자료는 Markdown과 JSON으로 내보낸다. 검토·설계·계산·회의 파일을 현재 PDF와 대조하여 복구할 수 있다. 기록 전 편집은 저장·내보내기를 막거나 명시적 기록을 요구한다.

담당자 이름은 사용자가 입력한 라벨이다. 사용자 계정·접근 권한·실시간 공동 편집·전자결재 기능이 아니다.

### 11.2 프로젝트 checkpoint

포함: PDF 원본, 원문 추출·메모, 필드 검토 이력, 작성 중 설계, 연결된 비교 결과·KOL 메모, 인계한 원본 에이전트 JSON, 선택한 조사 맥락.

저장은 명시적 동의·버튼 동작이다. 자동 저장이 아니다. 다음 저장은 새 revision을 추가한다. `expected_revision`을 SQLite 트랜잭션에서 검사하여 오래된 화면의 저장을409 충돌로 차단한다. 과거 버전에서 별도 프로젝트로 복사할 수 있다.

제한: 최대100프로젝트, 프로젝트당100버전, 저장총량1GiB, PDF5MiB, bundle32MiB, 프로젝트 요청48MiB. 한도를 넘었다고 기존 기록을 자동 삭제하지 않는다.

### 11.3 복구와 제외 범위

복구는 PDF를 다시 읽고 원문·좌표·필드 이력·digest·회의 결과 연결을 검사한 뒤 적용한다. 복구 자체는 새 모델 호출·새 계산·새 전문가 확인이 아니다.

미기록 입력, 패널의 일시적 진행 상태, 일부 수동 계산 첨부, CSV 작업 전체, 모든 과거 계산의 자동 타임라인은 통합 저장 대상이 아니다. 일부 수동 첨부가 빠진 결과는 열람할 수 있어도 재계산하려면 재첨부가 필요하다.

추출기 변경으로 좌표가 달라지면 복구를 거절할 수 있다. 범용 자동 마이그레이션·DB 백업/삭제 UI·복구 운영 정책은 없다. hash는 내용 일치 확인이지 서버 관리자에 대한 변조 방지나 작성자 인증이 아니다.

### 13.4 요청 경계·응답 오류

- POST는 `application/json`만 허용한다. 파일 바이트가 필요한 일부 경로는 base64와 원문·검토 JSON을 전달한다.
- 일반 POST 본문32KiB, 설계/제안24MiB, 프로젝트48MiB 등 경로별 한도가 있다. 개별 PDF·원문 계약 한도를 추가 적용한다.
- 모델 작업 슬롯은 프로세스당1개, 계산 슬롯은2개다. 서버 여러 프로세스에 걸친 분산 한도는 아니다.
- 잘못된 입력은422, 버전 충돌409, 허용되지 않은 Origin403, 크기 초과413, 용량 초과429 등으로 구분한다.
- 외부 모델의 인증·한도·출력 계약 실패는 안전한 코드로 변환한다. 원본 에러에 들어갈 수 있는 키·민감 본문을 그대로 응답하지 않는다.
- SSE 종료·취소·heartbeat와 결과 계약을 검사하며, 실패한 실행을 정상 완료로 바꾸지 않는다.

대회 어댑터는 임의 공급자 자동 전환·자동 재시도를 하지 않는다. 응답 quota 헤더는 허용된 숫자만 ‘추정치’로 보존한다. 응답 성공, 스키마 검증 성공, 임상적 타당성은 각각 다른 단계다.

### 14.2 주요 상태

| 객체 | 상태 |
|---|---|
| 공개 조사 | `RUNNING`, `COMPLETE`, `PARTIAL`, `CANCELLED`, `FAILED` |
| 추출 에이전트 | `DRAFT_FOR_EXPERT_REVIEW`, `PARTIAL_ABSTENTION`, `FAILED`, `BUDGET_EXCEEDED` |
| AI 비교 초안 | `PROPOSED`, `NEEDS_EVIDENCE` |
| 설계 비교 | `HYPOTHETICAL_COMPARISON_ONLY`, `BLOCKED_EVIDENCE_LINK` |

취소·시간 초과·검증 차단 시 이미 수집한 자료와 확인된 단계는 가능한 범위에서 보존한다. 저장 기록 재열기만으로 외부 호출을 재실행하지 않는다. 모델이 반환한 내부 추론 내용을 작업 이벤트나 보고서에 노출하지 않는다.

## 15. 보안과 데이터 경계

현재는 **로컬 개발/연구용 서비스**다. 다음 조치는 있지만 기업용 보안·개인정보 처리 체계가 완성됐다는 뜻은 아니다.

### 구현한 경계

- CLI 서버는 `127.0.0.1`에만 바인딩하며 공개 host 옵션을 제공하지 않는다.
- 로컬 Origin·TrustedHost·CORS·본문 크기·읽기 시간을 검사한다.
- 응답에 `no-store`, `nosniff`를 적용한다.
- 외부 전송·로컬 영구 저장에 명시적 동의를 사용한다.
- 키는 서버에서만 읽고 브라우저·Git·보고서에 넣지 않는다.
- 명시 키 파일은 POSIX 소유자 전용 권한을 검사한다.
- 공개 문서 다운로드는 호스트·경로 허용 목록, 크기·응답 검사로 제한한다.
- 모델에 문서를 비신뢰 데이터로 전달하며 임의 도구 실행 권한을 주지 않는다.
- 출처·필드·제안·계산에서 승인 상태 위조와 잘못된 ID/hash를 검사한다.

### 아직 없는 것

계정 인증, 역할별 권한, 테넌트 격리, 저장 암호화, 조직별 외부 전송 정책, 감사 로그 위변조 방지, 전자서명, 운영 백업/복구, 중앙 사용량 관리, 인터넷 서비스 보안 검증.

따라서 현재 버전에 비공개 임상시험 자료·환자 개인정보를 투입하는 운영을 권장하지 않는다. 공개·사용 허가된 비민감 자료로 한정한다. 로컬 Origin 제한은 인증을 대신하지 않으며, 프롬프트 주입에 대한 완전한 방어 성능도 검증하지 않았다.

## 16. 설치·실행·운영

### 16.1 설치

현재 GitHub 코드로 실행할 때:

```bash
git clone https://github.com/ryullee-hideandseek/trialboard.git
cd trialboard
uv sync --locked
npm --prefix web ci
```

macOS에서 검증했다. Windows/Linux/WSL의 전체 기능 동등성은 별도 확인이 필요하며 개인 Codex CLI 경로에는 POSIX 제약이 있다.

### 16.2 서버와 UI

터미널1:

```bash
uv run python -m trialboard.api \
  --enable-designs \
  --enable-agent-demo \
  --enable-pdf-agent \
  --enable-evidence-scout \
  --prompt-dacon-key
```

키는 비표시 프롬프트에 입력한다. 합성 계산·기본 화면만 볼 때는 `--prompt-dacon-key`를 빼고 실행할 수 있지만 실제 모델 기능은 사용할 수 없다. 서버를 시작하는 것만으로 모델을 호출하지 않는다.

터미널2:

```bash
npm --prefix web run dev
```

| 주소 | 역할 |
|---|---|
| `http://127.0.0.1:5173` | 제품 UI |
| `http://127.0.0.1:8000` | API |
| `http://127.0.0.1:8000/docs` | OpenAPI 탐색 |

`--enable-designs`는 계산, `--enable-pdf-agent`는 선택 PDF 모델 실행, 둘의 조합은 AI 설계 제안을 활성화한다. `--enable-evidence-scout`는 수집·조사·프로젝트 저장을 켠다.

### 16.3 빌드와 배포 경계

```bash
npm --prefix web run build
```

TypeScript 검사 후 `web/dist`를 생성한다. **정적 빌드 폴더만 호스팅해도 현재 모델·DB 기능이 그대로 운영되는 구조는 아니다.** 개발용 Vite 프록시·localhost 연결·기능 경계에 의존한다. 외부 서비스 배포에는 서버 구성, 인증, 비밀 관리, DB 정책, 브라우저 연결 정책의 별도 설계가 필요하다.

### 17.2 자동 검사 범위

- 근거 hash·버전·문맥 충돌, 분모 오류·결측·중복.

- AI 초안 가져오기·확인·변경 후 무효화·계산 차단.

- 실제 대회 모델을 이용한 공개 조사·후속 검색·인용 브리핑 실행 기록.

## 18. 남은 개발과 우선순위

### 우선순위1 — 실제 자료에서 연결을 입증

1. 사용 허가된 실제 사례 하나의 원문·정답·누락·충돌을 고정한다.
2. 검색→원문 확보→관측값 검토→설계 초안 또는 적절한 보류→KOL 기록까지 전 과정을 확인한다.
3. 각 결과를 원문·입력·가정·모델 버전·실패 기록에 연결한다.
4. 원문 열기·수정→재계산·메모 저장→복구를 실제 UI 동작으로 확인하고 영상에도 구분해서 담는다.

### 우선순위2 — 정보 추출의 실용성

- 이미지 표 OCR과 표 머리글·각주·셀 관계 복원.
- 다문서의 시험·코호트·용량·분석집단·시점 연결.
- 등록부·논문·CSR·프로토콜 간 불일치의 의미 분류.
- 단위·지표·다국어 표현 확장 및 잘못된 자동 연결에 대한 평가.

### 우선순위3 — 설계·검증 확장

- 통계 전문가와 가정·비교 지표·효용·보류 규칙 검토.
- 실제 업무 범위에 맞는 추가 설계 유형 선택.
- 독립 전문가 평가 및 사전 고정한 시간 분할 평가.
- 검정력·PK/PD·적응형 설계는 현재 모형과 별개로 설계·검증해야 한다.

### 우선순위4 — 기업 파일럿 기반

- 계정·역할·팀 프로젝트·공동 검토·승인 권한.
- 안전한 서버 운영, 저장 암호화·백업·삭제·보존 정책.
- 비밀키·팀별 비용·작업 큐·재시도 및 중단 복구 정책.
- 문서 변경 영향 분석·전체 실행 이력·검증된 감사 기록.
- 접근성·성능·다브라우저·다OS·오류 UX 검사.

기능 확장의 기준은 ‘더 많은 화면’이 아니라 **실무자가 근거를 확인하고 다음 결정을 준비할 수 있는지**다.

### 시연 보완안 — 숫자 대조와 설계 비교의 역할 분리

팀 피드백처럼 두 기능은 명확히 다르다.

| 기능 | 보여줄 질문 | 현재 엔진이 하는 일 |
|---|---|---|
| 근거 대조 | 같은 10건인데 왜 20%와25%가 다른가? | 분모·분석집단·시점·원문 연결을 확인. 단순 LLM 산수 교정이 아님 |
| 설계 비교 | 모집을80명에서160명으로 늘리는 것이 어떤 가정에서 도움이 되는가? | 같은 가정으로 두 표본수의 선택/보류·안전성 한계 초과 군 선택 빈도·오차를 계산 |

**제안하는 다음 영상 사례이며 아직 추가 구현·렌더하지 않은 구성:**

1. ‘효과 차이가 작을 때도 환자를 두 배로 늘려야 할까?’라는 질문으로 시작한다.
2. 두 용량군·총80/160명 대안과 명시한 가정을 보여준다.
3. 효과 차이 작음 / 효과 차이 큼 / 독성 우려 증가의 합성 시나리오를 동일한 계산 틀에서 비교한다.
4. 실제 계산 결과에서 추가 인원 대비 선택/보류 빈도 차이와 오차를 보여준다. 인원 증가가 반드시 무의미하거나 반드시 유익하다는 결론을 미리 정하지 않는다.
5. ‘어떤 가정을 더 확인해야 이 결정을 할 수 있는가?’를 근거·KOL 질문에 연결한다.

현재 엔진으로 조건별 계산은 가능하지만 새 사례의 입력·출력은 아직 고정·검증하지 않았다. 실제 약물의 관측 근거와 미래 가정을 연결하려면 추가 원문 검토와 전문가 평가가 필요하다. 투여 일정 변경·병용·중간중단·PK/PD 비교까지 확장하는 시연은 현재 엔진 밖이므로 별도 개발 없이 표현하지 않는다.

## 19. 영상 제작 프로젝트와 제품의 구분

별도 로컬 `video/`에 React/Remotion 영상 코드가 있고, 현재 출연형 v4는 약3분54초다. 가상 발표자 이미지·임시 음성·제품 캡처·모션 그래픽을 조합한다.

- 영상의 화면 강조·확대·카메라 이동은 제품 기능이 아니다.

- 영상 소스·원본 소재·렌더 결과는 제품 Git 전달에서 제외되어 있다.
- 스토리보드·전사문 공유 파일은 로컬 `output/share/TrialBoard_Storyboard_20260928/`에 있으며, 이 기술 명세서는 그 영상 설명과 별개로 현재 제품 코드를 다룬다.
