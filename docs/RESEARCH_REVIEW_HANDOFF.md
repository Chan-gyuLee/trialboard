# 공개 조사 → 원문 검토 직접 연결

2026-09-22 · 기존 로컬 제품 흐름 확장. 새 검색/대회 모델 호출/영상 변경/배포 없음.

## 사용자가 할 수 있는 것

자동 조사 결과의 `한눈에 보는 결과` 아래에 다음 검토 단계를 표시한다.
완료된 PDF 추출 기록에 관측값이 있고 원문이 40페이지 이하이면
`추출 근거로 검토 이어가기`로 PDF·원본 추출 결과·질문·조사 맥락을 함께 연다.
별도로 PDF나 추출 JSON을 내려받아 다시 업로드할 필요가 없다.

필드 검토에는 사용자 확인/미확인/보류/미보고 상태와 `다음 미확인 값` 버튼을 추가했다.
용량, 분모, 사건 수 등부터 원문 위치를 열어 대조할 수 있다. 보고된 필드의 탐색 순서일 뿐,
임상 중요도 점수·필수 자료 충분성 판정·자동 확인·임상 승인 기능이 아니다.
미보고 수치나 설계 확률을 만들어 채우지 않는다. 보고 비율 등 선택 항목의 미보고도 개수에 포함된다.

검토 후 기존 `설계 비교·KOL`의 AI 초안 경로를 이용한다. 원본 추출 기록은 자동 연결되지만
외부 모델 전송 동의, AI 가정 확인, 로컬 계산 동의는 기존 규칙대로 별도다.

## 데이터 및 실패 처리

- `GET /api/research/runs/{run}/automation`: 저장된 추출 기록을 재확인.
- `GET /api/research/runs/{run}/documents/{source}/cached?sha256=…`: 특정 저장 버전만 읽는다.
- 캐시 없음/다른 출처/다른 지문/손상은 오류로 끝낸다. 새 다운로드·다른 버전 선택·모델 재시도 없음.
- 최대 5,000,000 bytes로 응답을 읽고 PDF 지문·byteLength를 대조, PDF.js로 문구를 다시 추출.
- 기존 `importAgentReport`가 입력 hash·원문 문구·페이지·관측값 계약을 검사한 뒤에만 화면을 교체.
- 모든 필드는 미확인, 사용자 확인 이력은 빈 배열. 확률/표본수는 빈 입력 상태를 유지.
- 기존 작업이 있으면 교체 전 확인. 실패·취소 때 기존 PDF/검토/설계/회의는 유지.
- 기존 프로젝트 저장에 PDF·원본 추출·필드 검토·질문·조사 출처가 함께 들어가며 새로고침 뒤 복구 가능.
- 프로젝트 출처 확인도 run/source/digest 정확히 일치하는 영수증을 찾는다. 여러 버전 중 첫 행에 의존하지 않는다.

준비 카드와 필드 진행 패널은 Sites의 작업 중심 화면 원칙에 따라 다음 행동을 전면에 둔다.
기존 React/MUI와 로컬 Python/SQLite 구조를 유지했다. DB 스키마 추가/외부 배포 없음.

## 지원하지 않는 범위

계획 문서만 저장된 경우, 관측값 0개, 미완료 추출, 출처 미연결, 40페이지 초과 원문은
직접 인계 대신 이유와 원문 처리 기록으로 안내한다. 긴 문서의 부분 페이지 추출을
40페이지 뷰어에 억지로 넣거나 페이지 번호를 바꾸지 않는다.

등록부 결과표→PDF 필드 검토 변환, 다문서 자동 결합, 긴 PDF 검토,
약물명만으로 임상 설계까지 전자동 완주, 독립 임상 정확도 검증은 아직 아니다.
최근 로컬 조사 6건에는 저장된 automation 기록이 없었다. 과거 기록에 새 추출을 자동 실행하지 않았다.

  코드 변경 없이 최종 전체 재실행은710통과. 이 이슈는 해결한 것으로 취급하지 않는다(기본 dacon 경로와 별개).
- 새 웹 검사 17개: 정상/비어 있는 근거/긴 PDF/실패 상태/변경된 보고서/캐시 누락/잘못된 지문/
  크기 초과/파싱 문구 불일치/취소/진행 큐/프로젝트 호환성.
- Python: 정확한 캐시 조회·미확보 시 무다운로드·손상 차단·복수 버전 프로젝트 저장.
- 브라우저1440×1000/390×844: 합성 조사 결과→실제 PDF 파싱→미확인 44값→원문 위치→제안 패널 연결.

  PDF 파서·캐시 API·프로젝트 API/SQLite·화면 연결은 실제 구현을 사용했다.
