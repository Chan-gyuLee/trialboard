# 실제 공개 PDF 대조와 텍스트 누락 대응 · 2026-09-22

## 결론

실제 원문에는 결과표가 있지만 텍스트 추출에는 나타나지 않는 사례를 확인했다.
등록정보 수집이나 텍스트 추출 성공을 임상 근거 확보로 간주하면 안 된다.
이번 작업은 개발자의 원문 화면 대조와 기능 회귀 검사다. 독립 임상 전문가 평가·정답률 검증은 아니다.

## 실제 자료에서 확인한 사항

1. [NCT03600883 공개 API](https://clinicaltrials.gov/api/v2/studies/NCT03600883)를 조회한 스냅샷에는
   `resultsSection`이 없었다. 마지막 게시 갱신일은2026-06-30이었다. 이는 이번 응답의 관측이며,
   관련 결과가 다른 논문·문서에도 없다는 뜻이 아니다. 이 등록정보에서 용량별 결과를 만들지 않았다.
2. [Amgen의 2023 ODAC 제출자료](https://www.fda.gov/media/172698/download)는146쪽/5,663,303바이트로
   현재 수집 한도를 초과한다. FDA 호스팅과 FDA 작성은 다르다. 이 파일을 잘라서 원본인 것처럼 넣거나 한도를 우회하지 않았다.
3. [FDA 작성 ODAC 자료](https://www.fda.gov/media/172696/download)는51쪽/3,005,656바이트였다.
   실제 PDF33쪽의 CodeBreaK 200 효과 표는 sotorasib/docetaxel 분모171/174, ORR28%/13%이다.
   PDF35쪽의 안전성 표는 분모169/151, 전체 원인 TEAE any grade138/139명(82%/92%)이다.
   자료마감일2022-08-02는 관찰기간이 아니다. 이 비교를 sotorasib의 두 용량 비교로 바꾸면 안 된다.
   이 회의자료를 최종 규제 결정으로 해석하지 않는다.
4. FDA 자료의33·35쪽은 렌더링하면 표를 읽을 수 있지만, PDF.js와pdfplumber 텍스트 추출은 모두0개였다.
   PDF.js 탐색에서 텍스트를 얻지 못한 페이지는7,10,14,16,23,24,25,26,27,32,33,35,39,40,45였다.
   두 추출기의 일치가 임상적 의미 검증은 아니다. 실제 페이지 이미지를 별도로 보고 문제를 확인했다.

선택 사실·열/분모 대조 기록: `tests/fixtures/fda-codebreak200-audit.json`.
원본 SHA-256: `0e2c73e81b0aea8bf433ef9ec8233ac386287fa6a211d79568fe0552eed9fd48`.
해당 기록은 모델 입력이나 앱의 자동 생성 답변에 넣지 않는다. 원본 PDF는 Git에 포함하지 않았다.

## 제품 변경

- 직접 파일 열기도 최대200쪽 PDF를 지원한다. 40쪽 이하는 기존 전체 페이지 계약을 유지한다.
- 긴 PDF는 기존 키워드 탐색으로 최대40쪽을 연결한다. AI 의미 선택·전체 전문 검토가 아니다.
- 탐색한 범위의 **텍스트 미확보 페이지**를 구체적인 쪽수로 표시한다. OCR을 실행했다고 주장하지 않는다.
- ‘다른 원문 페이지 검토하기’에서 `19-22, 33, 35` 같은 원래 PDF 쪽수를 지정할 수 있다.
- 새 범위를 읽기 전에 기존 작업 교체를 확인한다. 성공한 경우에만 메모/필드/설계/회의를 새로 시작한다.
  현재 기록이 필요하면 먼저 프로젝트로 저장해야 한다. 동의 거절·범위 오류·읽기 실패는 기존 자료를 보존한다.
- 같은 파일 지문·실제 전체 쪽수·선택 범위를 확인하고, 원문 쪽수를 다시 매기지 않는다.
- 프로젝트 복구는 저장된 선택 범위를 다시 읽는다. 복구 후 텍스트 미확보 안내는 그 범위에 한정한다.
  전체 탐색 결과를 영구 보관하는 기능으로 확대하지 않는다.
- 이미지 전용 페이지는 원문 표시가 가능하지만 문구·좌표가 없어 텍스트 확인 메모를 자동 생성할 수 없다.
  관측·분모·비율을 채워 넣거나 설계로 자동 승격하지 않는다.

기존 쿨 블루 화면과 MUI를 유지했고, PDF 스킬에 따라 실제 원문 렌더링을 대조했다.
파일/텍스트/시간 한도는 유지한다. OCR·vision 표 해석·다문서 비교는 아직 미구현이다.

## 검증

- 실제 FDA PDF의 업로드→51쪽 탐색→읽지 못한15쪽 표시→33·35쪽 지정→원문 표 렌더링.
- 41쪽 선택 거절·교체 확인 취소·텍스트 확인 버튼 비활성화 확인.
- 별도 임시 SQLite에 저장→새로고침→33·35쪽 복구. 실제 사용자 DB 변경 없음.
- 1440×1000 및390×844: 콘솔 오류0, 모바일 가로 넘침0. `output/public-pdf-audit/` 참조.
- 웹1012개(실제 PDF 고정지문 검사1개 포함)/Python725개, Ruff/build 통과. 모델 호출0.
- 원본 파일이 없는 환경에서는 공개 PDF 검사1개를 skip한다. 네트워크 다운로드는 테스트가 수행하지 않는다.
  `TRIALBOARD_PUBLIC_AUDIT_PDF=/path/to/file.pdf`를 설정하면 고정지문/실제 페이지를 검사한다.
- QA 스크립트: `tmp/qa-public-pdf.mjs`, 테스트: `web/tests/public-pdf-audit.test.mjs`.

## 남은 핵심

실제 수치 원문 대조는 했지만 이미지 표의 자동 추출→검토→설계 완주는 못 했다.
다음은 원문 페이지 이미지·셀 위치·집단 머리글·각주를 함께 보존하는 OCR/vision 추출의 별도 계약과 실패 처리다.
그 후 같은 문서에서 추출값을 대조하고, 근거 부족 보류와 설계 제안을 실제 호출로 평가해야 한다.
전체79%(±10%p)/기업 운영25% 추정을 유지한다. Git push/사이트 배포 없음.
