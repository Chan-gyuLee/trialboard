1. 신약개발에서의 에이전트 활용의 필요성과 배경
□ 해결하려는 문제
임상시험 설계는 적응증의 자연사, 표준치료, 바이오마커, 환자 이질성, 평가변수, 통계적 특성 및 규제 기준을 함께 고려하는 다학제 의사결정입니다. ICH E8(R1)은 환자와 의료인을 포함한 이해관계자의 의견을 반영하고, 분야별 전문가가 설계를 검토할 수 있어야 한다고 제시합니다[1]. 따라서 질환 전문가(Key Opinion Leader, KOL)의 판단이 필요하지만, 적합한 전문가를 확보하고 반복적으로 자문받는 데 많은 시간과 비용이 소요됩니다.
임상시험 근거는 ClinicalTrials.gov, protocol, 통계분석계획(Statistical Analysis Plan, SAP), 결과 논문 및 규제기관 심사문서에 분산되어 있습니다. ClinicalTrials.gov는 구조화된 등록정보와 일부 시험의 protocol·SAP 등을 제공하지만[2], 모든 시험에서 원문이 공개되는 것은 아닙니다. 또한 동일 시험에서도 문서 시점에 따라 환자군, 치료군, 평가변수 및 분석계획이 달라질 수 있습니다.
따라서 선행시험을 설계 근거로 활용하려면 동일 시험의 문서를 식별하고, 버전과 시점을 정렬하며, 설계·변경·결과를 비교 가능한 형태로 정리해야 합니다. 현재는 연구자와 전문가가 이 작업을 반복하고 있어 시간이 많이 들며, 변경 사항이나 상충하는 결과를 놓칠 위험도 있습니다.
용량 최적화는 이러한 문제를 잘 보여주는 사례입니다. 표적항암제에서 최대내약용량(Maximum Tolerated Dose, MTD)을 후기 임상 용량으로 선택하면 추가 효능 없이 독성, 감량 및 치료 중단이 증가할 수 있습니다. FDA의 Project Optimus와 2024년 최종 가이드라인은 PK/PD, 유효성, 안전성, 내약성 및 노출–반응 관계를 종합하고 복수 용량을 비교하도록 권고합니다[3,11]. 식품의약품안전처도 2025년 관련 가이드라인을 발표하였습니다[4].
□ 목표와 에이전트 기반 접근
본 연구에서는 분산된 임상시험 근거를 연결하고 복수의 설계안을 비교·검토하는 멀티 에이전트 시스템 Trial Board를 개발하고자 합니다. Trial Board는 KOL의 판단을 대체하지 않습니다. 반복적인 근거 조사와 초기 설계를 지원하고, 근거가 부족하거나 상충하는 쟁점을 KOL 검토 질문으로 정리하는 것을 목표로 합니다.
장기적으로는 임상시험 설계 전반을 지원하지만, 본 연구의 구현 범위는 단일 경구 표적항암 소분자의 단독요법과 dose-escalation 이후 Phase Ib/II 용량 최적화로 제한합니다. First-in-human 시작용량, NOAEL/HED/MABEL, 병용요법, biologic·ADC·세포유전자치료제 및 환자별 처방은 제외합니다.
Trial Board는 규제 승인 가능성이나 실제 임상 성공률을 예측하지 않습니다. 성능은 근거 포괄성, 인용 정확도, trial lineage 완전성, 충돌·결측 탐지율 및 적절한 판단 보류율로 평가합니다. 시뮬레이션 재현성과 전문가 검토 준비시간의 변화는 보조 지표로 측정합니다.
2. 에이전트 설계 및 설계의 독창성과 창의성
□ 근거 기반 설계 및 사전검토 시스템
Trial Board의 전체 흐름은 다음과 같습니다. 사용자 입력 → 문제 분해 → 근거 탐색 → 근거 정규화 → 복수 설계안 생성 → 정량 시뮬레이션 → 반론·인용 검토 → 수정 또는 판단 보류 → KOL 승인
Orchestrator는 별도의 전문가 역할을 맡지 않고, 각 Agent의 입력·허용 도구·완료 조건·실패 상태를 관리하는 상태기계(state machine)로 구현합니다. 실제 판단은 다음 다섯 Agent가 수행합니다.
1. 근거탐색 Agent는 선행시험과 규제문서를 수집하고, 동일 시험의 등록정보·protocol·SAP·결과 논문·심사문서를 연결합니다. 문서 버전, 환자군, 치료군, 평가변수 및 결과의 변경 이력을 trial lineage로 구축합니다.
2. 임상설계 Agent는 질환 특성, 표준치료, 바이오마커, 환자군 및 PK/PD 근거를 바탕으로 최소 두 개의 설계안을 생성합니다. 분자 식별자와 단위는 RDKit과 규칙 기반 검증기로 확인하며, 각 설계 조항에는 근거·가정·대안·미확정 사항을 기록합니다. SPIRIT 2025 항목은 protocol synopsis에 필요한 항목과 추후 full protocol에서 보완할 항목으로 구분합니다[5].
3. 통계설계 Agent는 DROID와 MERIT 등을 참고하여 용량 선택 규칙과 표본수 후보를 구성합니다[6,7]. Monte Carlo simulation은 고정된 R/Python 함수로 수행하며, 용량선택확률, 잘못된 선택률, 독성 초과확률, 기대 표본수 및 중도중단확률을 비교합니다. LLM은 계산을 직접 수행하지 않습니다.
4. 반론검토 Agent는 각 설계안의 실패 가능성, 모집 가능성, 환자 부담, 과학적·통계적 취약점 및 규제상 쟁점을 검토합니다. 수정 후에도 해결되지 않은 문제는 추가 데이터 요구사항 또는 KOL 질문으로 전환합니다.
5. 인용검증 Agent는 주장과 수치가 원문 근거와 일치하는지 확인합니다. FDA·식품의약품안전처·ICH 문서의 상태, 발행일, 버전, 적용 범위와 원문 위치를 보존하며[3,4,12], FDA 심사문서에서는 신청자 자료와 심사자 판단을 구분합니다.
최종 승인은 Agent가 아니라 Human Gate가 담당합니다. 근거가 부족하거나 상충하면 시스템은 결론을 강제하지 않고 판단 보류(abstention) 상태를 반환합니다.
□ 차별성
최근 실사용데이터(real-world data, RWD)를 활용해 임상시험 설계를 지원하는 멀티 에이전트 연구가 보고되었습니다[8]. 따라서 여러 역할의 LLM을 배치하는 것만으로는 충분한 차별점이 되기 어렵습니다.
Trial Board의 첫 번째 차별점은 검색 결과를 요약하는 데서 끝나지 않고, 시험의 설계·변경·결과를 연결한 trial lineage를 구축한다는 점입니다. 두 번째는 하나의 설계안을 제시하지 않고 복수 설계안을 동일한 시뮬레이션 조건에서 비교하고 반례를 찾는다는 점입니다. 세 번째는 해결하지 못한 문제를 숨기지 않고 판단을 보류한 뒤 추가 자료와 KOL 질문으로 전환한다는 점입니다.
또한 Agent의 차이는 프롬프트상의 역할이 아니라 사용하는 도구와 검증 규칙으로 구현합니다. 기존 연구는 LLM을 이용한 protocol·SAP 검토 가능성을 보였지만, 제한된 시험 집합에서 평가되었고 문서 버전 오류도 확인되었습니다[9]. Trial Board는 식별자, 단위, 버전 및 출처 검사를 결정적 검증 단계(deterministic gate)로 두고 근거, 도구호출, 계산결과와 수정이력을 남깁니다.
□ 구조화 산출물과 오류 복구
핵심 산출물은 Trial Evidence Card와 trial lineage, Design Decision Matrix, Assumption & Conflict Ledger, Dose Evidence Map, Simulation Report, Regulatory Traceability Matrix, Protocol Diff 및 KOL Question List입니다. 모든 주장은 `claim_id–source_id–원문 위치–도구 버전–검증 상태`로 연결합니다.
워크플로 상태는 `COLLECT→NORMALIZE→PROPOSE→SIMULATE→VERIFY→REVISE→ACCEPT/ABSTAIN`으로 제한합니다. 주요 실패 상태는 식별자 중의성, 단위 불일치, 출처 부재, 문서 버전 충돌, 적용 범위 외, 근거 상충 및 외부 API 실패입니다. API 오류는 고정된 cache 또는 대체 공식 출처로 복구하고, 과학적 상충은 임의로 하나를 선택하지 않고 함께 제시합니다.
3. 기술적 실현 가능성
□ 검증된 기반과 4주 MVP
예선 단계에서 Python CLI, 6개 데이터 schema, JSON/JSONL 산출물과 SQLite evidence store를 구현하였습니다. 현재 저장소에는 trial record 30건, 원문 위치를 확인한 claim 7건, dose evidence 24행 및 명시적 missing-data 6건이 있습니다. 5개 개발 사례의 protocol·SAP 8건과 sotorasib FDA 심사문서 1건은 hash로 고정하였으며, 데이터 구조·출처·판단 보류를 검사하는 로컬 테스트 18개가 통과하였습니다. 이 결과는 현재 구축한 자료와 규칙에서의 동작 확인이며 일반적 정확도를 의미하지 않습니다.
본선 1주차에는 전문가 이중주석과 Citation Verification Agent를 완성합니다. 2주차에는 Evidence Scout를 다섯 사례로 확장하고 임상설계 및 규제 추적 기능을 연결합니다. 3주차에는 Dose Evidence Map, Monte Carlo simulation, 반론검토와 UI를 통합합니다. 4주차에는 protocol family가 겹치지 않는 hold-out 평가, fault injection, 비용·지연 최적화 및 시연을 완료합니다.
구현에는 Python, Pydantic, RDKit, pandas 또는 polars, SciPy·statsmodels 및 필요한 경우 R을 사용합니다. 시연 UI는 Streamlit으로 구현합니다. 원문·구조화 근거·LLM 응답은 content hash와 수집일로 고정하고, 각 실행의 모델·프롬프트·도구 버전·random seed를 manifest에 기록합니다. 별도의 fine-tuning 없이 structured output과 tool calling을 사용합니다.
□ 데이터와 도구 통합
- ClinicalTrials.gov API v2와 PubMed/Europe PMC에서 시험 등록정보, 공개 첨부문서 메타데이터 및 관련 논문을 수집합니다[2].
- FDA, Drugs@FDA, DailyMed, ICH 및 식품의약품안전처에서 승인·라벨·심사·규제 문서를 수집합니다.
- PubChem, ChEMBL, UniProt 및 Open Targets는 후보물질–표적–질환 식별을 보조하고, RDKit은 구조와 식별자를 검증합니다.
- NumPy, SciPy, statsmodels 또는 R은 모델 적합과 반복 시뮬레이션에 사용합니다.
외부 Agent skill이나 adapter는 라이선스, commit hash, 입출력 구조 및 오류 처리 방식을 확인한 뒤 필요한 기능만 채택합니다. ADMET과 docking 결과는 임상설계 근거로 사용하지 않고 후보물질 식별의 보조 정보로만 사용합니다.
□ 현실적 범위와 fallback
범용 PDF 이해, 실제 환자 전자의무기록, 전체 치료영역 및 자동 IND 문서 생성은 제외합니다. 공개 protocol이 없으면 등록정보와 논문으로 Evidence Card를 만들고, 원문 protocol 미확보를 결측으로 표시합니다. 외부 API가 중단되면 사전에 고정한 demo snapshot으로 동일한 결과를 재현합니다.
4. 에이전트 평가 적절성
□ 평가 원칙과 데이터 셋
임상시험 설계에는 복수의 합리적 대안이 존재하므로 최종 추천과 기존 protocol의 일치율만으로 평가하기 어렵습니다. 본 연구에서는 근거 탐색, 사실 추출, trial lineage, 정량 계산, 설계 판단, 오류 복구 및 사람 검토 효율을 단계별로 평가합니다.
1. Development Pilot은 5개 사례의 protocol·SAP 8건과 40개 주석 항목으로 구성합니다. 항목은 환자군, 치료군, 일차 평가변수, 용량 선택 규칙, 안전성 중단 규칙, 분석집단, estimand·intercurrent event 및 결측자료 처리입니다. 현재는 주석 양식만 구축된 상태이며, 전문가 합의 정답이 완성되기 전에는 성능을 주장하지 않습니다.
2. Held-out Extraction Set은 개발 사례와 protocol family가 겹치지 않는 10개 이상의 사례와 200개 이상의 원자적 정답 항목으로 구성합니다. 두 전문가가 Agent 출력을 보지 않고 독립적으로 주석한 뒤 합의하며, `answerable`, `not stated`, `conflicting`, `wrong document version`을 구분합니다.
3. Dose Simulation Set은 효능 포화, 완만한 증가, 비단조 효능, 고용량 독성 증가 및 효능–독성 상충 시나리오로 구성합니다. 알려진 생성 모수와 비교하여 각 설계의 operating characteristics를 평가합니다.
4. Historical/Fault Set은 sotorasib 후향 근거감사와 40–60개의 인위적 오류로 구성합니다. 단위 1,000배 오류, 잘못된 식별자, cohort denominator 변경, 오래된 SAP, FDA 심사자와 신청자 발화 혼동, API 오류 및 근거 없는 문장을 포함합니다.
5. Human-use Pilot에서는 임상·통계·신약개발 경험자가 동일 사례를 일반 검색, 단일 LLM+RAG 및 Trial Board로 검토합니다. 검토시간, 중요 쟁점 누락, 근거 확인 성공률, 사용성 및 신뢰도 과대평가 여부를 측정합니다. 소규모 결과는 임상적 일반화가 아닌 prototype 내부검증으로 해석합니다.
□ 평가 지표와 기준선
핵심 지표는 초록과 동일하게 5가지로 구성됩니다.
- 근거 포괄성: 기준 근거집합 대비 source coverage, Recall@5 및 nDCG@10을 측정합니다.
- 인용 정확도: claim–evidence precision, 실재 출처 비율, 문서 버전 및 발화 주체 귀속 정확도를 측정합니다.
- Trial lineage 완전성: 필수 문서·버전·변경·결과 노드와 연결 관계의 recall 및 F1을 측정합니다.
- 충돌·결측 탐지율: gold conflict와 missing item에 대한 precision·recall을 측정합니다.
- 적절한 판단 보류율: 답변 가능 여부 정답을 기준으로 abstention precision·recall과 판단을 내린 사례의 정확도를 함께 측정합니다.
보조 지표로 추출 macro-F1, critical dose·arm·unit error, 시뮬레이션 unit test 통과율, interval coverage, random seed 재현성 및 전문가 검토시간을 사용합니다. 목표값은 citation precision 0.95 이상, held-out macro-F1 0.90 이상, critical dose·arm·unit error 0건으로 두되 신뢰구간과 오류 사례를 함께 보고합니다.
기준선은 단일 LLM, 동일 자료를 사용하는 LLM+RAG, 주요 Agent를 제거한 ablation 및 전체 Trial Board입니다. 이를 통해 성능 변화가 Agent 수가 아니라 구조화 근거, 결정적 검증, 시뮬레이션 및 수정 반복에서 발생하는지 확인합니다.
5. AI 활용 투명성 및 연구 윤리
□ 제안서 작성과 개발에서의 AI 활용
본 제안서 작성과 feasibility 개발에서는 AI를 아이디어 정리, 반대 논거 탐색, 구현 범위 조정, 출처 점검, 주석 schema 및 fault test 설계에 사용하였습니다. 작성자는 공식기관 원문과 DOI를 다시 확인하여 최종 주장과 참고문헌을 선택하였습니다. AI가 추출한 초안은 silver data로 구분하며 전문가 정답과 분리합니다.
본선에서는 model·provider·version, system prompt hash, tool commit, 검색 query, source URL·수집일, 중간 산출물, 계산 seed 및 수정 이력을 실행별 manifest에 기록합니다. 개인정보와 영업비밀은 외부 API에 전송하지 않고 공개자료 또는 비식별·합성 데이터만 사용합니다.
□ 과학적 타당성과 오남용 방지
LLM의 임상·약리 주장은 공식 규제문서, 원 논문 또는 데이터베이스 record에 연결되지 않으면 채택하지 않습니다. 분자 식별과 단위는 규칙 기반 검증기로 확인하고, 시뮬레이션은 unit test와 benchmark로 검증합니다. 상충하는 근거는 평균내지 않고 출처별로 제시합니다. 최종 protocol synopsis는 전문가 승인 전까지 연구용 초안으로 표시합니다. 
ClinicalTrials.gov가 제공하는 sponsor protocol·SAP 원문은 분석용 cache에만 저장하고 재배포하지 않습니다. 공개 산출물에는 URL, hash, 권리 메타데이터 및 최소한의 파생사실만 남깁니다.
Trial Board는 환자별 진단·치료·투약, 자동 임상시험 승인신청, 유해물질 합성경로 생성 및 신규 독성물질 최적화를 제공하지 않습니다. 저작권이 있는 원문을 대량 재배포하지 않으며, 데이터·코드·외부 도구의 라이선스와 출처를 기록합니다.
6. 본선 시연 시나리오
□ 4분 시연 기준 타임라인
시연에서는 sotorasib의 초기 용량탐색, 960 mg 가속승인, CodeBreaK 100 Phase 2 Part B의 240 mg·960 mg 무작위 비교 및 후속 FDA 판단을 하나의 근거 이력으로 연결합니다[13,14]. 실제 자료는 후향 근거감사에 사용하고, 합성 PK/PD 시나리오는 설계의 정량적 특성을 검증하는 데 사용합니다.
0:00–0:40 근거 수집
NCT03600883과 sotorasib 식별자를 입력하면 ClinicalTrials.gov, FDA 심사자료, PubChem 및 공개 논문 snapshot을 불러옵니다. source hash와 문서 시점을 표시하고, 의도적으로 삽입한 AUC 단위와 cohort denominator 오류를 검출합니다.
0:40–1:30 근거 정규화
PK, 유효성, 안전성 및 내약성 근거를 표준화하고 각 주장에 원문 위치를 연결합니다. 공개자료에 없는 patient-level covariate, dose intensity 및 일부 protocol·SAP 정보를 결측으로 표시합니다. FDA 문서에서는 신청자 자료와 심사자 판단을 구분합니다.
1:30–2:30 경쟁 설계 비교
임상설계 Agent가 240 mg·960 mg 무작위 평행군 비교안과 추가 용량을 포함한 탐색안을 제시합니다. 통계설계 Agent는 효능 포화, 완만한 증가 및 고용량 우월 시나리오에서 용량선택확률, 독성 초과확률 및 기대 표본수를 계산합니다.
2:30–3:20 반론검토와 수정
반론검토 Agent는 공개 aggregate 자료만으로 최적 용량, 240 mg 비열등성 또는 정확한 표본수를 확정할 수 없음을 지적합니다. 또한 개인 수준 내약성 자료와 검증된 PD surrogate가 부족하다는 점을 표시합니다. 해결되지 않은 쟁점에는 `INSUFFICIENT_EVIDENCE_HUMAN_REVIEW_REQUIRED` 상태를 반환합니다.
3:20–4:00 최종 결과
화면에는 trial lineage, Evidence Ledger, 노출–PD–독성 그래프, 설계별 operating characteristics, 규제 추적성, Protocol Diff 및 KOL Question List를 표시합니다. 결론뿐 아니라 근거, 계산, 검증 및 수정 이력을 함께 보여줍니다. 
7. API 및 GPU 관련 예상 소요 규모
□ Agent 구동을 위한 최소 조건
시연 1건의 목표 상한은 LLM 호출 8–15회, 외부 API 호출 20–40회, 입력 50k–120k tokens 및 전체 실행시간 2–5분입니다. 외부 API의 rate limit을 준수하고 사전 cache를 사용합니다. LLM은 계획·추출·비판·설명에 사용하고, 구조 처리와 통계 계산은 로컬 도구가 수행합니다. 비용은 호출 수, token 수 및 cache hit rate로 관리합니다.
RDKit, parsing, Emax·logistic fitting 및 수천 회 Monte Carlo simulation은 CPU 8–16 core와 RAM 16–32 GB에서 수행할 수 있으며 GPU는 필수가 아닙니다. 로컬 7–8B 모델을 보조적으로 사용할 경우 12–24 GB VRAM GPU 1장을 선택사항으로 둡니다. 대형 모델 fine-tuning과 대규모 docking은 수행하지 않습니다. 외부 API 장애 시에는 versioned snapshot으로 시연을 재현합니다.
8. 에이전트 도입에 따른 파급효과
□ 현장 가치와 측정 가능한 효과
누구나 공개 근거 기반의 첫 검토안을 쉽게 확보할 수 있다는 것이 큰 장점입니다. KOL 네트워크가 제한되거나 소규모 연구인력 중심의 중소 바이오텍과 학술연구자에게는 기꺼이 비용을 지불하더라도 사용할만한 기능이라고 생각합니다. 그동안 전문가는 검색과 서식 작업보다 환자 여정, 모집 가능성, 평가변수의 임상적 의미 및 benefit–risk 판단에 집중할 수 있습니다.
의사결정 자체도 개선됩니다. Getz 등은 15개 제약사·CRO의 protocol 836건을 분석하여 57%가 substantial amendment를 경험했고, 이 중 45%가 회피 가능하다고 평가되었다고 보고하였습니다. Amendment 직접비용 중앙값은 Phase II에서 14.1만 달러, Phase III에서 53.5만 달러였습니다[10]. 이 결과는 과거 산업표본이므로 국내 또는 Trial Board의 절감액으로 직접 환산할 수는 없지만, 실제 Trial Board를 통해 더 나은 의사결정을 하고, 의사결정 비용 자체를 줄일 수 있으리라 기대합니다.
□ 산업 경쟁력과 확장성
단기적으로는 항암 소분자 용량 최적화의 protocol synopsis와 evidence gap 분석에 적용합니다. 중기에는 약물상호작용, 특수집단, 외부대조군, endpoint selection, eligibility stress test 및 국가별 규제 차이 분석으로 확장할 수 있습니다. 장기적으로는 기관 내부의 비식별 설계 결정과 amendment 사유를 연결하여 조직의 임상설계 지식을 축적할 수 있습니다.
Trial Board의 최종 목표는 자동으로 protocol을 확정하는 것이 아닙니다. 반복적인 근거 조사를 줄이고, 설계의 반례와 불확실성을 더 일찍 확인하며, 규제 검토가 가능한 의사결정 이력을 만드는 것입니다.
