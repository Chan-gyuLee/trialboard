# 원문 구간 선택형 인용 · 2026-09-16

사용자 목표는 최소 입력 후 에이전트가 작업하고 필요한 판단만 요청하는 것이다.
이 변경은 자동 브리핑에서 모델의 인용문 재작성 때문에 중단되는 병목을 줄인다.
약물/적응증의 모호함, 근거 부족, 임상 판단까지 자동 승인하는 변경은 아니다.

## 계약

- 모델2회 한도를 유지한다. 첫 요청의 `source-bound/1` 조사 계획은 그대로다.
- 두 번째 요청은 `source-spans/1`. 모델은 인용문이나 출처 ID를 쓰지 않고, 제공된 원문 구간 ID와 해석을 반환한다.
- 기존 최대8개 출처/각 앞4,500자 범위를 유지한다. 원문을 최대600자 구간으로 나누되 문장/공백 경계를 우선하며 정규화·숫자 수정은 하지 않는다.
- 구간 ID는 출처 ID·출처 버전 지문·시작/끝·원문 내용에 묶인다. 응답 enum에는 이번 입력 구간 ID만 허용한다.
- 서버가 구간 ID를 다시 대조하고 정확한 원문 부분 문자열을 기존 `ResearchReview`의 `quote`로 넣는다.
- 원문 변경/없는 구간/틀린 출처/범위 오류는 계속 차단한다. 근접 문자열 검색이나 실패 인용 자동 보정은 없다.
- 기존 저장/웹/Markdown 계약을 유지하며, 모델 호출 기록에 별도 `citation_bindings`를 남긴다.
  위치 단위는 UTF-16 바이트가 아니라 Unicode code point다. 인용과 해석이 함께 있어도 임상적 타당성을 승인한 것은 아니다.
- 단계 이벤트 `CITATIONS_READY`로 자료 수와 구간 준비 상태를 전달한다. 내부 사고 전문을 표시하지 않는다.

OpenAI Docs의 [구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했다.
출력 후보를 제약하는 장치이며, 모델이 그 구간에 맞는 해석을 선택했는지는 별도 평가가 필요하다.
초록/서지 범위, 시험·환자군 혼동, 해석의 과장 가능성이 남는다. PDF 전문 자동 추출·설계안 자동 생성·시뮬레이션은 별도다.

## 검사

새 Python20개: 빈/긴/Unicode/줄바꿈 문서, 모든 비공백 문자 보존,600자 한도, source/version 변경,
없는 구간·추가 quote 삽입 거부, 원문/구간 지문/위치·DB복구·2요청 한도.
새 웹1개: 실제 Python API가 합성 모델로 보내는 전체 SSE를 프런트 reader로 읽고 저장 결과까지 검증한다.
단위 테스트만으로 서버의 새 단계와 화면 허용 목록의 불일치를 잡지 못했던 점을 보완했다.
기존 정확한 인용문 대조와 부분 실패 검사는 유지한다. 테스트 자료는 MOC이며 임상 평가가 아니다.

## 제품 방향

기본 동선은 약물명 입력/공개 전송 동의 → 범위가 모호한 경우에만 확인 → 자동 조사와 작업 상태 → 결과 검토다.
기존 전문가 도구는 선택적으로 펼치는 상세 기능으로 남긴다. 사용자에게 인용문을 수동으로 재입력하도록 요구하지 않는다.
조사 중에는 작업 상태를 펼치고, 완료되면 접어서 결과를 먼저 보여준다. 원하면 조사 기록을 다시 펼칠 수 있다.
아직 임상 설계까지 전자동 완성되는 제품은 아니다. 다음은 자료의 범위·관련성 개선과 자동 원문/설계 연결이다.

## 실제 브라우저 검증

2026-09-16 Chrome에서 새 입력부터 실행했다. sotorasib 입력·공개 전송 동의 → 적응증
Non-small Cell Lung Cancer 한 번 선택 → 계속. 이후 추가 입력 없이 약36초 동안 조사→브리핑을 완료했다.
시간은 범위 확인 후 UI 실행 구간이며, 최초 시험 검색 시간은 별도다.

- 최초 시도 `0c22372f-bad1-4aff-9d8c-1ba45e6bb24b`: 근거82개, 계획 통과 후 새 `CITATIONS_READY` 이벤트가

  계획 응답6,147토큰 보고. 취소된 검토 요청 사용량은 미확인으로, 0으로 간주하지 않는다.
- 수정 후 `07438cdb-8633-4d11-b857-39d4b466f8ce`: **COMPLETE**, 근거82개, 인용 연결 쟁점8개, KOL 질문6개.
  DACON terra 계획/검토2회 모두 검증 통과. 보고 토큰6,138+6,213=12,351.
  저장된8개 인용의 출처·버전·문자 위치·원문 문자열·구간 ID를 다시 대조했다.
- 이번 두 시도에서 최대4개 모델 요청이 시작됐고 응답3개 수신. 확인된 보고 합계18,498토큰에 취소 요청의 미확인 사용량이 더해질 수 있다.
  잔여량 헤더는 추정값으로 전체 누적 비용을 단정하지 않는다. 추가 유료 재시도 없음.
- Python584개/웹774개, Ruff/TypeScript/Vite 통과. 합성 테스트와 실제 대회 실행을 구분한다.
- 완료 후 결과 우선 배치 변경 뒤에는 저장 결과 복귀·인용 펼침·데스크톱 배치를 추가 모델 호출 없이 확인했다.
  변경 후 새 실행의 자동 접힘은 재유료 실행하지 않았고, 모바일/전체 키보드 QA는 남아 있다.

이는 한 약물의 조사·브리핑 성공이지 임상 정확도나 모든 약물의 자동화 성공률을 검증한 것이 아니다.

시험/코호트·용량 비교 목적에 맞는 관련성 강화가 다음 병목이다. PDF 전문/설계 생성/시뮬레이션은 이번 실행에 포함되지 않았다.
