# 제품 개발 전용 백그라운드 작업

2026-09-30 사용자 승인: 찬규의 기술명세/발표 주장 대조를 토대로 제품 개발은 대회 API에 위임하고 파트별 검토. 이 대화는 유지. **영상은 사용자와 별도 협의 전 어떤 수정·생성·렌더도 하지 않는다.**

## 역할과 경계

- 구현 모델: 기존 `scripts/dacon_worker.py`의 대회 Responses 공급자 `trialboard_dacon`, `gpt-5.6-sol`. 개인 공급자로 자동 전환하지 않는다.
- 감독은 작업 범위 설정·diff/테스트 검토·부족한 점의 수정 지시만 담당한다. 제품 구현은 대회 worker가 수행한다. 감독 대화/내장 감독 에이전트 자체의 과금까지 대회 API로 바뀌는 것은 아니다.
- 승인 비밀 파일을 명시 `--dacon-key-file /Users/ryul/.config/trialboard/dacon-api-key`로만 로드. 키의 값/인증파일/환경 덤프를 읽어 출력하거나 저장소에 복사하지 않는다. 권한 디렉터리700/파일600 확인.
- 제품 쓰기는 한 worker씩. `video/`, 영상 출력·공유자료·대본, 기존 비밀/실사용 DB, 배포 및 Git commit/push는 제외. 기존 변경 모두 보존.
- 로컬 공개/합성 fixture와 mock으로 검증. 실제 환자·비공개 자료 및 별도 외부 모델·TTS·이미지 API 호출 금지.
- 새 파트는 앞 파트의 diff/회귀검사 승인 뒤 진행. 실패한 것을 구현 완료로 표기하지 않는다. 감독과 실행 프로세스가 활성 상태일 때만 자동 진행하며 앱 종료/컴퓨터 잠자기 후 무인 재개는 보장하지 않는다.

## 구현 순서 및 수용 기준

### 0. 현재 코드 감사

찬규의 전체 지적을 구현됨/부분 구현/미구현/검증 필요로 분류하고 실제 코드·테스트 경로를 기록한다. 문서만을 근거로 기능을 새로 만들지 않는다. 현재 제품 baseline 및 기존 변경 목록을 기록한다. 원본 기술명세는 당시 기록으로 보존한다.

초기 확인: `SearchPlan.followup_terms`는 최대2개 문자열, `web/src/design-result.ts`의 KOL 질문은 이미 두 단계 priority가 있다. `research_links`는 관계와 target을 저장하지만 이것이 곧 모든 보고서의 의존성 그래프라는 뜻은 아니다. 찬규의 제안 파일명을 그대로 가정하지 않는다.

### A. 반대 근거를 찾는 후속 검색

현재 검색 예산·동의·관련성·ID 및 인용 검사를 유지하며 반대 결과/안전성/실패를 찾는 실제 질의 최소1개를 추적 가능하게 한다. 단순 프롬프트 문장 추가로 완료하지 않는다. polarity는 검색 의도이며 논문 결과의 확정 판정이 아니다. 실제 실행과 실패/건너뜀을 구분한다. 기존 저장기록/엄격한 서버·브라우저 reader 호환 경로를 마련한다.

검사: 반대 의도가 누락/잘못 태깅된 계획, 검색어 주입·빈값·예산, 동의 거부, 기존 계획·저장본, 질의 provenance, 실패가 성공으로 기록되지 않음. 근거 없는 negative 결과 생성 금지.

### B. KOL 질문의 결정론적 긴급도

현재 질문 생성·구조와 priority를 감사한 후 규칙 기반 점수/이유를 추가한다. 근거 차단/보류·조건 충돌·실제 사용 가능한 안전성 지표를 근거로 삼고 없는 값을 만들지 않는다. 예측 모델·임상적으로 검증된 순위라고 표기하지 않는다. tie-break 고정, 원래 질문 ID·근거·연결 맥락 유지. canonical 계약과 reader/export/UI를 함께 변경하고 기존 `kol-meeting-notes/1`을 조용히 깨뜨리지 않는다.

검사: 결정성, blocker 우선, 누락/동점, 원본보고서 결속·변조거부, 이전 계약·회의메모 가져오기, 사용자 화면과 export의 순서/이유 일치.

### C. 자료변경의 기록된 영향 범위 조회

실제 source ID+digest/프로젝트/실행 연결을 근거로 읽기 전용 영향 후보 조회와 제품 표시를 만든다. 원자료를 바꾸거나 자동 최신화/판단/연쇄 재계산하지 않는다. 저장되지 않은 의존성은 조회 불가로 명시. 같은 source ID의 다른 버전, 무관한 실행/프로젝트를 무조건 포함하지 않는다. 필요하면 추적 범위를 정직하게 좁힌다.

검사: fixture상 알려진 직접/간접 범위(지원할 경우), 버전구분, 중복·없는 ID/실행, 프로젝트 범위, SQL 인자화, 읽기 전용, 빈/실패 UI. 인증/테넌트격리 구현으로 오인시키지 않는다.

### D. 통합 검증과 주장 근거

Python 전체 테스트·ruff·웹 계약 테스트·TypeScript/Vite 빌드를 실행하고, 변경한 UI는 가능한 로컬 브라우저에서 확인한다. 자동검사와 실제 UI·임상 정확도 검증을 구분한다. 파트별 변경경로/명령/결과/제한/발표에서 가능한 정확한 주장만 보고서에 기록한다. 영상 문구 수정은 하지 않는다.

## 이번 구현에서 제외

계정·역할·테넌트격리·부서별 협업, 조건부 의미 캐시, 다문서 자동 병합, 주기 갱신/자동 재시도 큐, 학습된 tabular/우선순위 모델, 최적 용량 추천은 감사 후 미구현 경계를 기록할 뿐 이번 A/B/C에서 자동 착수하지 않는다. 신규 약물 기본정보 입력·그래프 완전성·합리적 불일치 자동판단은 현행 근거 확인 결과를 보고한다. 발표 워딩과 영상은 모두 별도 협의.

## 실행/상태

기존 실행기는 명시 provider/base URL/Responses/api-key 환경 헤더·개인 인증 비요구·자동 retry0으로 격리한다. [공식 설정 항목](https://learn.chatgpt.com/docs/config-file/config-reference)을 확인했으며 실제 대회 접속 가능 여부는 이번 worker 결과로 판정한다.

개발 감독은 이 문서와 별도 `docs/DEVELOPMENT_DACON_STATUS_2026-09-30.md`에 파트별 상태를 기록한다. 1차 사이클은 감사+A/B/C+검증으로 제한하며 worker 최대8회(수정 포함), 각 최대1200초. 인증/할당량/공급자 오류는 개인 계정으로 우회하지 말고 기록 후 중지한다. 429는 중간결과 보존 후 60초 이상 간격으로 해당단계 재개 최대1회(8회 한도 안). 무한 재시도 금지.

계획만 세운 현재 제품 전체 구현율은 약79%(±10%p), 테스트 개수·임상 성능과 무관한 주관적 계획 추정이다. 파트 검증 이후에만 재평가한다.
