# TEAM 모드 사용 범위

TEAM은 단일 컴퓨터의 루프백 개발 환경에서 팀별 저장 경계를 시험하기 위한 명시적 opt-in 모드다. 운영용 SSO, TLS 종단, 프록시 배포 또는 보안 인증을 뜻하지 않는다. 기본 `legacy_loopback` 동작과 기존 데이터는 변경하거나 자동 이전하지 않는다.

## 합성 환경 시작

실제 사용자 파일이 아닌 새 경로를 준비하고, 비밀번호를 화면에 표시하지 않는 별도 CLI로 최초 관리자 한 명을 만든다.

```bash
python -m trialboard.api.team_bootstrap \
  --identity-db /private/tmp/trialboard-team/identity.sqlite3 \
  --username admin --team-name "Review team"
mkdir -m 700 /private/tmp/trialboard-team/teams
python -m trialboard.api --access-mode team \
  --identity-db /private/tmp/trialboard-team/identity.sqlite3 \
  --team-storage-root /private/tmp/trialboard-team/teams
```

서버는 `127.0.0.1`에만 바인딩한다. identity DB는 새 파일만 원자적으로 생성하며 권한은 `0600`, 새 팀 디렉터리는 `0700`이다. TEAM 설정이 없거나 경로가 겹치거나 symlink/alias가 발견되면 시작 또는 접근을 거부하며 legacy로 대체하지 않는다. 계정 DB를 잃거나 잘못 지정해도 런타임이 새 DB를 자동 생성하지 않는다.

## 접근 표

| 경로 | 익명 | viewer | reviewer/admin |
| --- | --- | --- | --- |
| `GET /health`, `GET /api/access-mode` | 허용 | 허용 | 허용 |
| 로그인 challenge/login | 허용, Origin 필요 | 허용 | 허용 |
| session/CSRF/current team/logout | 거부 | 본인 세션 허용 | 본인 세션 허용 |
| 나머지 `GET /api/**` | 거부 | 현재 팀 DB 읽기 | 현재 팀 DB 읽기 |
| 나머지 POST/PUT/PATCH/DELETE | 거부 | 거부 | 현재 팀 DB, Origin+CSRF 필요 |
| 분류되지 않은 API·WebSocket | 거부 | 거부 | 거부 |
| `/brand/**`, `/data/**` | 공개 정적 데모 자료 | 공개 | 공개 |

팀·역할은 요청 헤더나 본문이 아니라 매 요청 identity DB의 활성 membership에서 읽는다. 역할 변경·탈퇴·계정 비활성화와 절대/유휴 만료는 기존 세션의 다음 요청부터 적용된다. 세션은 HttpOnly/SameSite=Strict 쿠키이고 서버에는 해시만 저장한다. 여러 탭이 받은 최근 CSRF 토큰은 제한된 개수만 병행 유효하며, 프런트는 한 시점에 하나만 발급 요청한다. 실패한 쓰기를 자동 재전송하지 않는다.

브라우저는 로그인 시 서버가 준 불투명한 세션 컨텍스트를 이후 API 요청에 예상값으로 보낸다. 서버는 이 값을 실제 쿠키 세션과 비교해 다른 탭에서 사용자나 팀이 바뀐 요청을 409로 차단한다. 이 값은 인증 수단이 아니며 팀 선택이나 역할 부여에 사용되지 않는다. 프런트는 세션 세대가 바뀐 뒤 도착한 이전 응답도 폐기한다. 같은 사용자·팀의 재로그인은 편집 화면을 유지하지만 진행 중이던 요청은 다시 실행하지 않는다.

정적 공개 미리보기는 빌드 시 `VITE_PUBLIC_PREVIEW=true`를 명시한 경우에만 켜진다. 이 모드는 공개 `/data`·정적 화면만 사용하고 `/api/**` 요청을 브라우저에서 차단한다. 기본 빌드는 서버의 TEAM/legacy 접근 모드를 확인하며, 서버 확인 실패를 정적 미리보기로 자동 대체하지 않는다.

## 현재 한계와 다음 연결점

- HTTP 루프백 전용이라 Secure cookie를 설정하지 않는다. 원격 프록시, forwarded header 신뢰, 외부 Origin, TLS 종료는 지원하지 않는다.
- coarse 역할과 팀별 SQLite 분리까지만 제공한다. 프로젝트별 ACL, 협업 승인, 충돌 정책, 실제 SSO, 장기 감사·보존·백업은 아직 없다.
- 관리자용 다중 계정 UI와 프로젝트별 권한 UI는 아직 없으며 협업 기능은 다음 단계다.
- 실행 시작 뒤 장시간 수행되는 모델/큐 작업의 membership 재확인은 후속 큐·이용조건 단계에서 실행 직전에 추가해야 한다.
- TEAM 모드는 현재 실행 소유권·프로세스 생존 여부·lease를 증명할 큐가 없다. 따라서 조회·준비·실행 요청은 기존 `RUNNING` 작업을 stale로 추정해 중단하지 않으며, 비정상 종료 복구는 소유권과 liveness를 확인하는 명시적 복구 기능이 추가될 때까지 자동 제공하지 않는다.
- 브라우저의 같은 사용자 세션 만료는 편집 상태를 잠금 뒤 보존한다. 다른 사용자/팀 로그인은 React 작업공간을 새로 마운트해 이전 PDF·프로젝트·결과 상태를 비운다.
- 서버 권한은 이미 사용자가 내려받은 파일을 회수하거나 삭제할 수 없다. 다운로드물의 보관·전달 정책은 별도 운영 통제가 필요하다.
- 역할에 따른 UI 표시는 편의 기능일 뿐이며 서버 권한 판정을 대신하지 않는다.

검증은 합성 임시 DB만 사용한다. 실제 계정 생성, 기존 DB 마이그레이션, 외부 네트워크 호출, 배포는 수행하지 않았다. 이 구현과 테스트는 인증·임상·보안 인증 또는 전문가 승인을 뜻하지 않는다.
