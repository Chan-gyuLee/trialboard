## 요약

TrialBoard는 표적항암제의 용량 최적화 시험을 준비하는 개발팀이 흩어진 근거를 확인하고, 복수 설계안의 장단점과 미해결 질문을 검토하도록 돕는 에이전트입니다. 사용자는 약물·시험·대상 환자군과 검토 질문을 입력하고, 원문을 추적할 수 있는 근거표, 설계 비교표, 가정별 시뮬레이션, 전문가 검토 질문을 받습니다. 최적 용량이나 임상 성공률을 자동으로 확정하는 제품은 아닙니다.

핵심은 시험등록정보, protocol, 통계분석계획서(SAP), 논문과 규제문서를 같은 시험의 버전·환자군·치료군·평가변수에 맞춰 연결하는 것입니다. 다섯 역할의 에이전트가 근거 탐색, 설계, 계산, 반론, 인용 검증을 수행하며, 근거가 부족한 판단만 보류하고 확인된 결과와 추가 데이터 요구사항은 함께 제공합니다. 최종 설계 승인은 사람이 담당합니다.

본선에서는 sotorasib 사례의 후향 근거감사와 별도의 합성 용량 시나리오를 사용할 계획입니다. 현재는 정상·분모 오류·자료 결측의 합성 검토 엔진, 로컬 계산 API, 고정된 FDA 원문 위치 확인, CSV 검토 웹을 구현했습니다. 자동 수집·LLM·시험 이력의 의미 검증·통합 설계 에이전트는 아직 없습니다. 인용 정확도, 임상 설계 품질과 사용자 시간 절감은 앞으로 검증할 항목이며, 본 문서의 성능 수치는 달성 결과가 아닌 목표입니다.

## 1 신약개발에서의 에이전트 활용의 필요성과 배경

### 전문가 회의 전에 반복되는 근거 검토

용량 최적화에는 효능뿐 아니라 안전성, 내약성, 약동학·약력학(PK/PD), 노출–반응, 모집 가능성을 함께 검토해야 합니다. ICH E8(R1)은 설계 단계의 질적 고려와 관련 전문가·이해관계자의 참여를 강조합니다[1]. FDA Project Optimus와 2024년 최종 가이드라인, 식품의약품안전처의 관련 안내서는 항암제 용량을 종합적인 근거로 검토하는 배경이 됩니다[3,4,11].

문제는 자료의 수보다 연결과 해석입니다. 같은 약물의 다른 적응증, 같은 시험의 다른 코호트, 변경 전후 SAP를 섞으면 그럴듯한 비교표도 잘못된 결론을 만들 수 있습니다. ClinicalTrials.gov의 구조화 정보와 공개 protocol·SAP를 활용하되, 공개되지 않은 자료는 결측으로 남겨야 합니다[2]. TrialBoard는 이 반복 검토를 지원하여 임상·임상약리·통계·규제 전문가가 결정해야 할 쟁점을 앞당겨 정리합니다.

### 본선에서 해결할 범위

대상은 단일 경구 표적항암 소분자의 단독요법이며, 용량 증량 이후 Phase Ib/II 용량 최적화 설계 검토로 제한합니다. First-in-human 시작용량, NOAEL/HED/MABEL 산정, 병용요법, biologic·ADC·세포유전자치료제, 환자별 처방은 제외합니다. 이 범위 밖 요청은 이유와 필요한 전문 검토를 안내합니다.

## 2 에이전트 설계 및 설계의 독창성과 창의성

### 역할과 검증 책임

다섯 에이전트는 공통 근거 저장소를 사용하되 산출물과 검증 책임을 분리합니다. Orchestrator는 여섯 번째 전문가가 아니라 실행 순서, 도구 권한, 재시도와 종료 조건을 관리하는 상태기계입니다.

| 역할 | 산출물 | 통과 조건 |
| --- | --- | --- |
| 근거탐색 | 출처 목록과 시험 이력 | 시험·적응증·문서 버전 및 원문 위치 확인 |
| 임상설계 | 최소 두 개의 설계 후보 | 설계 조항별 근거·가정·대안·결측 구분 |
| 통계설계 | 가정별 비교 계산 | 고정된 계산 코드·seed·입력 모수 보존 |
| 반론검토 | 취약점과 수정 요청 | 근거 충돌, 환자 부담, 실행 가능성 검토 |
| 인용검증 | 주장별 검증 기록 | 수치·단위·분모·시점·발화 주체 대조 |

### 자료의 연결과 주장의 채택을 분리

수집한 문서는 source ID, 원본 URL, 수집 시각, hash, 발행일과 버전으로 식별합니다. 근거에는 PDF 페이지·표·문장 또는 JSON 경로를 붙이고, 주장은 시험 ID, 적응증, 코호트, 치료군, 용량·투여 일정, 평가변수, 분석집단, 관찰 시점과 연결합니다. 날짜가 월까지만 알려지면 임의의 일자를 채우지 않습니다.

검증은 원문 위치 확인, 인용문 일치, 주장의 의미 지지 확인을 구분합니다. 문자열이 PDF에 있다는 이유만으로 전체 주장을 검증 완료로 표시하지 않습니다. 같은 문장이어도 분석집단이나 분모가 다르면 해당 비교에 채택하지 않습니다. 문서의 선후 관계와 실제 변경·보고 관계도 분리하며, 후속 문서라는 이유만으로 특정 규제 요구를 충족했다고 연결하지 않습니다.

### 수정과 판단 보류가 실제 동작하는 흐름

COLLECT → NORMALIZE → PROPOSE → SIMULATE → VERIFY → REVISE → ACCEPT 또는 ABSTAIN

ACCEPT는 자동 검증 조건을 통과한 전문가 검토용 초안입니다. 임상적 승인과 다릅니다. 근거가 부족하면 ABSTAIN으로 해당 판단을 보류하고, 부족한 필드·요청할 데이터·검토 담당 역할·판단 재개 조건을 제시합니다. API 실패나 파싱 실패는 과학적 근거 부족과 구분해 FAILED로 기록합니다. 재시도와 수정 횟수를 제한하고 오류가 해소되지 않으면 종료합니다.

### 검증 가능한 차별성

임상 연구의 에이전트 활용과 LLM 기반 protocol 검토는 이미 연구되고 있습니다[8,9]. 따라서 최초의 멀티에이전트라는 주장을 하지 않습니다. 차별화 가설은 시험 버전별 근거 연결과 주장 단위 검증이 단순 검색·RAG보다 잘못된 비교를 줄이고, 설계 수정과 보류를 더 정확하게 만든다는 것입니다. 이력 연결·인용 검증·반론 단계를 각각 제거한 비교 실험으로 기여를 확인합니다.

## 3 기술적 실현 가능성

### 확인된 구현과 남은 구현

2026년 9월 11일 재구성 후 합성 검토 CLI·스키마·출처/문맥/수치 대조·시뮬레이션, 제한된 로컬 FastAPI, 고정 FDA 원문의 정확한 문구/페이지 위치 확인, React/MUI 자료 검토 화면을 구현했습니다. Python 테스트 108개와 웹 함수/계약 테스트 61개, 정적 검사와 빌드를 통과했습니다. 이전 f19ea73의 수집·SQLite·이력 모듈은 사용자의 요청으로 제거했으며 Git 이력에 보존했습니다. 현재 일반 PDF 업로드, LLM, 영구 저장, 원격 시뮬레이션 실행은 없습니다. 자동 테스트는 실제 브라우저 사용성이나 임상적 정확도를 입증하지 않습니다.

임의 입력 문서의 주장-원문 참조 무결성, 문맥에 맞는 발화 주체 판정, 이력 연결의 의미 검증, 설계·계산·반론의 통합 실행, 평가 정답집과 사용자 화면의 실제 사용성은 추가 구현·검증 대상으로 관리합니다. 규제문서에 등장하는 승인 관련 단어만으로 승인 유형을 분류하지 않으며, 동일 약물의 다른 적응증·병용요법 문서가 본 시험에 섞이지 않도록 검증하는 것이 목표입니다.

### 결정적 계산과 불확실성의 표현

LLM은 검색 계획, 구조화 추출, 설계 초안과 반론에 사용합니다. 수치 계산은 버전이 고정된 R/Python 함수가 담당합니다. DROID와 MERIT는 적용 전제와 입력 자료를 확인한 뒤 비교할 방법론 후보이며, 본 팀이 새로 개발한 통계 방법으로 주장하지 않습니다[6,7]. 제한된 본선 구현에서는 검증 가능한 비교 규칙부터 연결합니다.

효능 포화, 완만한 증가, 비단조 효능, 고용량 독성 증가, 효능–독성 상충 시나리오에서 용량 선택 확률, 부적절한 선택 확률, 독성 한계 초과 확률, 기대 표본수와 중도중단 확률을 비교합니다. 각 지표의 사건 정의와 분모를 고정하고 Monte Carlo 오차를 보고합니다. 동일 입력·코드·seed로 결과가 재현되어야 합니다.

공개 집계 자료만으로 환자 수준 노출–반응이나 최적 용량을 확정하지 않습니다. PD 대리지표와 효능·독성 곡선을 가정한 경우 모든 표와 그래프에 합성 시나리오임을 표시합니다. 추정 곡선, 관측값, 문헌값을 시각적으로 구분하고, 임상적 허용 근거가 없는 추가 용량을 실제 투여 권고로 제시하지 않습니다.

### 오류를 막는 데이터 규칙

- 용량 값뿐 아니라 단위, 체중 보정 여부, 투여 빈도와 제형을 보존합니다. mg/kg·BID를 근거 없이 mg·QD로 바꾸지 않습니다.
- IC50과 Ki를 동일한 값으로 취급하지 않습니다. pIC50을 계산할 때는 IC50의 몰농도 변환과 로그 정의를 명시하며 pIC50에 nM 단위를 붙이지 않습니다.
- 효능 수치는 평가자, 분석집단, 분모, 추적기간을 함께 확인합니다. 상충하는 결과는 평균내지 않고 출처별로 남깁니다.
- source·span·claim 간 참조와 hash를 확인하고, 근거 없는 주장은 최종 설계의 채택 근거에서 제외합니다.

## 4 에이전트 평가 적절성

### 개발 자료와 평가 자료의 분리

평가 계획을 먼저 고정하고 개발용 사례와 독립 평가용 사례를 분리합니다. 동일 시험의 다른 문서를 서로 다른 집합에 넣어 누출을 만들지 않으며, 밀접한 protocol family도 함께 관리합니다. AI 추출 초안은 silver data로 표시하고, 전문가 합의 정답으로 취급하지 않습니다.

| 평가 집합 | 계획 규모 | 확인할 내용 |
| --- | --- | --- |
| 개발용 | 5개 사례·8개 문서·40개 주석 항목 | 추출 규칙과 오류 유형 정리 |
| 독립 추출 평가 | 10개 이상 사례·200개 이상 원자적 항목 | 수치·단위·버전·발화 주체 정확성 |
| 용량 시뮬레이션 | 5개 사전 정의 시나리오 | 선택 규칙의 특성과 계산 재현성 |
| 후향 감사와 오류 주입 | 실제 사례 및 인위적 오류 40–60개 | 충돌·결측·오류 검출과 수정 |
| 사용자 파일럿 | 참여자 확보 후 규모 확정 | 검토시간·누락·근거 확인 성공률 |

위 규모는 평가 계획이며 완료 수치가 아닙니다. 두 명의 관련 전문가가 모델 출력을 보지 않고 독립 주석한 뒤 불일치를 합의합니다. 답변 가능, 문서에 없음, 근거 충돌, 잘못된 문서 버전을 구분하고 주석 지침과 변경 이력을 남깁니다. 전문가 확보가 지연되면 정답집 미완성과 실제 검토 범위를 명시합니다.

첫 중간 점검은 독립 검토 50개 항목으로 진행할 수 있으나, 이를 200개 항목의 최종 목표 달성으로 보고하지 않습니다. 개발자가 직접 만든 정답만으로 외부 검증 또는 전문가 검증을 주장하지 않습니다.

### 공정한 기준선과 기능 제거 실험

단일 LLM, 동일 자료를 사용하는 LLM+RAG, 전체 TrialBoard를 비교합니다. 자료 접근 범위, 모델, 질문, 가능한 경우 총 호출·토큰 예산을 맞추고 차이가 있으면 공개합니다. 전체 시스템에서 이력 연결, 인용 검증, 반론·수정을 하나씩 제거하여 어떤 기능이 오류 감소에 기여했는지 확인합니다.

사용자 파일럿은 일반 검색, 단일 LLM+RAG, TrialBoard를 비교합니다. 동일 사례를 반복해서 보며 생기는 학습 효과를 줄이도록 동등한 난도의 사례와 과제 순서를 교차 배정합니다. 결과 작성시간뿐 아니라 사람이 원문을 재확인하고 수정하는 시간까지 측정합니다. 소규모 결과는 탐색적 제품 검증으로 해석하며 임상적 일반화를 주장하지 않습니다.

### 핵심 지표와 통과 목표

| 지표 | 측정 기준 | 보고 방식 |
| --- | --- | --- |
| 근거 포괄성 | 기준 근거집합 대비 검색·수집 누락 | source coverage, Recall@5, nDCG@10 |
| 인용 정확도 | 채택 주장 중 원문이 지지한 비율 | precision 목표 0.95 이상 |
| 추출 정확도 | 사전 정의 필드별 정답 일치 | macro-F1 목표 0.90 이상 |
| 이력 완전성 | 필수 노드와 관계의 정답 일치 | node·edge recall 및 F1 분리 |
| 충돌·결측 탐지 | 정답 충돌·결측의 검출 | 유형별 precision·recall |
| 적절한 보류 | 답변 불가 항목의 보류와 과잉 보류 | precision·recall 및 답변 coverage |
| 치명적 수치 오류 | 용량·치료군·단위의 잘못된 채택 | 평가 집합 내 관측 0건 목표 |

모든 수치는 미검증 목표입니다. 지표별 평가 단위, 분모, 제외 기준과 판정 규칙을 사전 고정합니다. 작은 표본의 점추정치만 보고하지 않고 사례 수·항목 수·오류 수와 신뢰구간을 함께 제시합니다. 동일 시험 내 항목은 독립으로 간주하지 않고 시험 단위 집계 또는 군집 재표집을 사용합니다. 오류 0건이 실제 오류 확률 0을 뜻하지 않음을 명시합니다.

검증하지 않은 주장과 보류한 주장은 인용 precision의 분모에서 사라지기만 해서는 안 됩니다. 전체 요청 항목 수, 답변 비율, 답변한 항목의 정확도와 보류 사유를 함께 보고하여 아무 답도 하지 않는 시스템이 높은 성능으로 보이지 않게 합니다.

### 실패 사례도 통과 조건에 포함

오류 주입은 단위 1,000배 오류, 잘못된 시험 식별자, 코호트 분모 변경, 오래된 SAP, 신청자와 심사자 발화 혼동, 근거 없는 문장, API·파싱 실패를 포함합니다. 원본과 변조 fixture는 별도 보관하고 주입 위치와 기대 동작을 기록합니다. 오류를 탐지했는지뿐 아니라 잘못된 최종 주장을 차단했는지, 안전한 부분 결과를 남겼는지 확인합니다.

시뮬레이션은 알려진 생성 모수, 경계 입력, 극단적 효능·독성, seed 재현성과 독립적으로 계산 가능한 기준값으로 검증합니다. 적용하지 않는 지표는 제외 이유를 적습니다. 불확실성 구간을 출력하는 계산은 해당 구간의 coverage도 점검합니다.

### 본선 심사 항목과 입증 자료

본선 평가의 과학적 혁신 30점은 이력·문맥 오류 감소 실험으로, 자율성 10점은 오류 후 도구 재호출·수정·종료 로그로, 도구 활용 15점은 출처와 계산의 실제 연결로 입증합니다. 자원 활용 15점은 호출·토큰·시간 실측으로, 시연 완성도 30점은 세 실행 예제와 재현 가능한 결과로 대응합니다. 점수 확보를 보장하는 문구가 아니라 준비할 증거의 목록입니다[16].

## 5 AI 활용 투명성 및 연구 윤리

### 실행 이력과 책임

본 제안서의 개정과 개발에는 생성형 AI를 문헌 확인 보조, 주장 비판, 구조화, 코드 작성·검토와 문서 편집에 사용했습니다. 제출자는 출처, 실제 구현 범위와 최종 표현을 검토하고 책임집니다. AI 초안과 전문가 승인 결과를 구분하며, 아직 수행하지 않은 평가나 전문가 참여를 완료한 것으로 표시하지 않습니다.

본선 구현에서는 실행별로 모델·제공자·버전, prompt hash, 코드 commit, 검색 query, 도구 호출, source URL·수집 시각·hash, 중간 결과, 계산 모수·seed, 수정·보류 사유를 manifest에 기록합니다. 비밀키와 민감한 입력은 로그에 남기지 않습니다. 모델 설명을 검증의 증거로 삼지 않고 원문과 계산 결과를 증거로 제시합니다.

### 규제문서의 권위와 적용 범위

FDA 웹사이트에 게시되었다는 사실과 FDA가 작성하거나 동의한 주장이라는 사실은 다릅니다. 예를 들어 2023년 ODAC sotorasib 자료 중 FDA media/172698은 Amgen 제출자료입니다[14]. 2021년 FDA 종합심사문서도 신청자 자료·입장과 FDA 판단을 구분합니다[15]. 따라서 문서 단위 작성자와 별개로 주장·표·절 단위의 발화 주체를 확인합니다.

가이드라인은 관할, 발행일, 개정 상태와 적용 범위를 표시하고, 권고를 법적 의무나 승인 보장으로 바꾸지 않습니다. ICH E4, E6(R3), E9(R1)은 해당 설계 질문에 필요한 항목에 연결합니다[12]. SPIRIT 2025의 34개 항목은 보고 완전성 점검에 사용하며, 과학적 타당성 점수나 자동 규제 적합 판정으로 해석하지 않습니다[5].

### 데이터 사용과 사람의 승인

본선에는 공개자료 또는 명확히 표시한 합성 데이터를 사용합니다. 개인정보, 환자 원자료와 기업 비밀자료를 외부 API로 전송하지 않습니다. 향후 기업 파일럿은 별도의 데이터 사용 합의, 접근 통제, 저장·삭제 정책과 외부 모델 전송 범위를 먼저 정합니다. 현재 공개자료 시연이 기업 보안 요구 충족을 증명하는 것은 아닙니다.

공개 원문도 재배포 권한을 자동으로 갖는 것은 아닙니다. protocol·SAP 등은 허용 범위의 분석용 cache로 관리하고, 공개 저장소에는 권리 확인 없이 원문을 배포하지 않습니다. URL, hash, 권리 메타데이터와 필요한 최소 파생사실을 남깁니다. 외부 문서는 명령이 아닌 데이터로 취급하며 문서 안의 지시가 도구 권한이나 실행 규칙을 바꾸지 못하게 합니다.

최종 protocol synopsis는 전문가 승인 전까지 연구용 초안입니다. 환자별 진단·치료·투약, 자동 승인신청이나 임상적 실행을 제공하지 않습니다. 임상·임상약리·통계·규제 담당자가 쟁점을 검토한 기록과 승인 범위를 남기며, 미해결 사항을 숨기지 않습니다.

## 6 본선 시연 시나리오

### 하나의 문제를 세 조건에서 실행

주 시연 질문은 “sotorasib 관련 공개자료로 용량 비교 설계를 준비할 때, 확인된 근거와 아직 결정할 수 없는 것은 무엇인가”입니다. NCT03600883과 관련 자료를 사용하되, 실제 자료의 후향 근거감사와 합성 자료의 설계 특성 계산을 명확히 분리합니다[13–15]. 이후 결과를 알고 과거 위험을 예측한 것처럼 설명하지 않습니다.

240 mg와 960 mg 비교를 검토할 때 평가변수, 분석집단, 분모, 시점과 원문의 조건을 함께 제시합니다. 집계 자료만으로 두 용량의 동등성·비열등성, 최적 용량 또는 확정 표본수를 선언하지 않습니다. 다른 적응증·병용요법의 허가 변경도 본 사례의 승인 전환으로 연결하지 않습니다.

| 실행 예제 | 입력 조건 | 심사자가 확인할 결과 |
| --- | --- | --- |
| 정상 근거 검토 | 버전이 고정된 공개자료 | 주장 클릭 → 원문 위치 → 근거 채택 조건 |
| 오류 검출과 수정 | 명시적으로 변조한 단위·분모 fixture | 오류 탐지 → 재검증 → 수정 또는 차단 |
| 결측과 판단 보류 | 특정 자료를 제외한 별도 fixture | 해당 판단 보류 → 데이터 요청 → 확인된 부분 결과 |

세 예제는 평가 가능한 실행 버튼과 입력 manifest를 각각 제공합니다. 녹화 화면만 제공하지 않고, 저장 결과 재생인지 스냅샷 기반 재실행인지 실시간 수집인지 표시합니다. 같은 스냅샷과 계산 seed의 재현성을 보이며, 외부 API 장애 때는 장애 사실을 밝힌 뒤 스냅샷 실행으로 전환합니다.

### 약 10분 영상 구성과 4분 핵심 시연

0:00–1:00에 사용자의 결정 과제와 범위를 소개합니다. 1:00–5:00은 정상 사례의 근거 확인, 경쟁 설계 비교, 합성 시뮬레이션과 전문가 질문까지 이어지는 핵심 시연입니다. 5:00–7:00에는 오류 주입 후 재검증을, 7:00–8:30에는 결측과 부분 보류를 보여줍니다. 8:30–10:00에는 실제 평가 결과, 한계, 자원 사용과 사용자 검증 계획을 제시합니다.

화면에는 확인한 사실, 계산에 사용한 가정, 아직 확인하지 못한 사항을 따로 표시합니다. 규제 요구사항과 설계 조항의 연결, Protocol Diff, KOL Question List를 하나의 검토 흐름으로 묶습니다. 질문에는 “무엇을 판단해야 하는가”, “왜 막혔는가”, “누가 어떤 자료를 확인하면 되는가”를 포함합니다.

본선 제출물은 실행 예제 3개 이상을 갖춘 demo URL, 약 10분의 YouTube 일부 공개 영상, 5–10분 발표 분량 PDF를 기준으로 준비합니다. 선택 기술문서와 GitHub에는 평가 방법·재현 절차·제한을 남깁니다. 마감은 2026년 10월 2일 16:00 한국시간이며, 실제 제출 직전 공지와 접근 권한을 다시 확인합니다[16].

## 7 API 및 GPU 관련 예상 소요 규모

### 측정할 자원과 실행 한도

일반 실행 1건의 초기 예산은 LLM 호출 8–15회, 외부 API 호출 20–40회, 입력 50k–120k tokens, 전체 실행시간 2–5분입니다. 이는 실측치가 아닌 조정 가능한 설계 목표입니다. cache 적중 여부와 최초 수집·재실행을 구분하여 입력·출력 토큰, 도구별 시간, 재시도 수와 실패율을 보고합니다. 공급자 단가가 확정된 시점에만 실행당 비용을 계산합니다.

구조 처리와 Monte Carlo 계산은 CPU 우선으로 구성하며, CPU 8–16 core·RAM 16–32 GB를 초기 운영 예산으로 잡고 실제 부하로 조정합니다. 대형 모델 학습, 대규모 docking과 필수 GPU 의존은 범위에서 제외합니다. 호출 예산과 시간 한도를 넘으면 부분 결과와 종료 원인을 반환하고 무한 재탐색을 막습니다.

## 8 에이전트 도입에 따른 파급효과

첫 고객 가설은 용량 최적화 또는 규제기관 미팅을 준비하는 소규모 바이오텍의 임상개발 책임자입니다. 초기 판매 단위는 범용 플랫폼이 아니라 특정 약물·설계 질문에 대한 근거 검토 패키지입니다. 출처 연결 근거표, 후보 설계 비교, 가정별 계산, 미해결 쟁점과 회의 질문을 납품하고, 활용성과 반복 수요를 확인한 뒤 지속형 도구 또는 기업 내부 AI팀 협업으로 확장합니다.

유료 파일럿에서는 자료 범위, 산출물, 검수 기준, 데이터 처리와 책임 범위를 사전에 합의합니다. 효과는 전문가의 총 준비·재확인 시간, 중요 쟁점 누락, 근거 확인 성공률, 반복 사용과 유료 전환 의향으로 측정합니다. 문헌의 protocol 변경 비용은 문제의 배경일 뿐[10], TrialBoard의 절감액이나 매출로 환산하지 않습니다. 고객의 지불 의사와 계약 가능성은 아직 검증할 사업 가설입니다.

## 부록 본선 화면과 산출물 명세

예선의 개념 화면을 아래의 구현·검수 명세로 대체합니다. 이 표는 완성 화면이나 실측 성능이 아닙니다. 실제 구현 화면은 근거 링크와 실행 결과가 연결된 뒤 촬영합니다.

| 화면 또는 산출물 | 반드시 보일 정보 | 검수 기준 |
| --- | --- | --- |
| 실행 개요 | 질문·범위·자료 기준일·실행 모드 | 실시간·스냅샷·저장 결과 구분 |
| Evidence Card | 주장·단위·분모·버전·발화 주체 | 원문 위치로 이동하고 맥락 확인 |
| Trial Lineage | 시험·문서·변경·결과 관계 | 시간 순서와 입증된 관계 구분 |
| Design Matrix | 후보별 근거·가정·장단점 | 최소 두 안 또는 생성 불가 사유 |
| DoseMap | 관측값·문헌값·가정값·결측 | 합성 곡선을 임상 근거처럼 표시하지 않음 |
| Simulation Report | 모수·규칙·seed·결과·오차 | 고정 계산 재실행 결과 일치 |
| Conflict Ledger | 충돌 근거·영향·해결 상태 | 충돌을 숨기거나 평균내지 않음 |
| Regulatory Traceability | 관련 권고·범위·설계 조항 | 권고와 법적 의무를 구분 |
| Protocol Diff | 수정 전후·수정 이유·근거 | 수정이 검증 요청과 연결됨 |
| KOL Question List | 판단 과제·부족 자료·담당 역할 | 질문별 판단 재개 조건 확인 |

### 최종 검토 패키지의 사용 순서

검토자는 먼저 질문과 적용 범위를 확인합니다. 이어 근거표에서 핵심 수치의 원문을 열고, 설계 비교표에서 관측 근거와 가정에 의존하는 조항을 구분합니다. 시뮬레이션은 어떤 가정에서 결론이 달라지는지 확인하는 데 사용합니다. 마지막으로 보류된 판단과 추가 데이터 요구사항을 담당 전문가에게 배정합니다.

전체 결과가 보류되더라도 확인된 사실과 검토 목록은 제공할 수 있습니다. 반대로 근거표가 완성되어도 용량 선택이나 표본수 결정이 자동으로 승인되는 것은 아닙니다. 화면과 내보내기 문서에서 이 차이를 유지합니다.

### 출시 전 확인할 기준

세 예제가 새 환경에서 실행되고, 주요 주장에 원문 위치가 연결되어야 합니다. 오류 주입 예제는 의도한 잘못된 채택을 차단해야 하고, 결측 예제는 없는 자료를 생성하지 않아야 합니다. 결과의 재현 조건, 실제 평가 규모, 알려진 오류와 사용 제한을 공개해야 합니다. 이 기준을 충족하기 전에는 검증 완료 제품이나 임상 의사결정 자동화 도구로 소개하지 않습니다.
