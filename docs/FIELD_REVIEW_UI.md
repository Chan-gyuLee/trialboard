# PDF 원문–필드 검토 (2026-09-13)

## 구현 범위

기존 MUI 화면에 원문과 구조화 필드를 대조하는 작업면을 추가했다.
공개·사용 허가된 텍스트 PDF 한 개와 검토 데이터는 브라우저 메모리에서만 처리한다.
자동 저장·서버 전송·웹 AI 호출은 없다. Codex 인증을 웹에 공유하지 않고 대회 토큰도 사용하지 않는다.
이번 변경은 로컬 소스에 구현했으며 기존 호스팅 링크는 갱신하지 않았다.

후속 단계: [사용자 수정 후 로컬 재검증](FIELD_REVALIDATION.md)이 추가됐다.
원문 export·필드 검토 이력·원본 PDF를 함께 읽고 Python 규칙을 다시 실행한다.
화면에서 자동 재검증/AI 실행은 하지 않는다. 후속 [재검증 결과 가져오기](REVALIDATION_RESULT_UI.md)로 로컬 결과를 다시 확인할 수 있다.

## 사용 순서

1. 자료 검토 → **PDF 원문 확인**에서 PDF를 선택한다.
2. **필드 검토 → 관측값 추가**로 한 용량·집단·지표의 관측값을 만든다. 사건 수/분모와 보고 비율 유형을 구분한다.
3. 용량·사건 수·분모·집단·시점 등 12개 필드 중 하나를 선택한다.
4. **원문 문구 찾기**에서 페이지와 문구를 고르고, 필드 검토로 돌아와 **선택 문구를 근거로 연결**한다.
5. 문구 안의 실제 값을 입력하고 원문 위치를 연다. 직접 대조한 체크와 사유를 남겨 확인/수정을 기록하거나 보류한다.
6. 검토 메모(Markdown)와 이력 JSON을 내려받는다. 기록 전 편집값은 내보내기에 포함되지 않는다.

로컬 에이전트 결과가 있다면 **추출 결과 불러오기**로 시작할 수도 있다.
먼저 이 PDF의 원문 확인 메모 JSON을 내려받고 [CLI 안내](AGENT_WORKFLOW.md)의 PDF 입력 경로를 사용한다.
그 실행이 만든 결과 JSON만 불러온다. 필드 검토 이력 JSON과 원문 메모 JSON은 서로 다른 계약이다.
현재 필드 검토 JSON 자체의 재불러오기는 지원하지 않으므로 원본 PDF·모델 결과·검토 기록을 따로 보관한다.

## 출처·판단 계약

- `pdf-field-review/1`: 원본 PDF SHA-256, 수동/가져온 결과 구분, 모델 실행 ID/모드/결과 파일 hash, 관측값별 필드와 변경 이력.
- 각 필드: `original`, `current`, `decision`, `history`. 인용은 페이지·문구 ID·정확한 인용 문자열을 가진다.
- `unreviewed / confirmed / corrected / held`는 사용자 검토 상태다. 전문가 자격이나 임상 승인을 인증하지 않는다.
- 원본 값은 변경하지 않는다. 각 확인/수정/보류에 이전 값·이후 값·사유·브라우저 시각을 남긴다. 서명된 불변 감사 로그는 아니다.
- 보류는 미기록 편집값을 채택하지 않고 직전 기록값과 보류 사유를 보존한다.
- 최대 12개 관측값, 필드당 이력 40개, 결과 JSON 2 MB. 중복 키·원형 오염 키·지나치게 깊은 JSON을 거부한다.
- 입력 보고서는 `bounded-evidence-agent/3.2`, PDF export provenance, 초안/부분 보류 상태만 지원한다.
- Python 입력 hash를 재계산하고 모든 입력 문구가 현재 PDF의 hash·페이지·ID·텍스트와 일치하는지 확인한다.
- 공개 웹 발췌/다른 PDF/이전 엔진/실패 실행은 거부한다. 파일 일치는 모델 실행 진위나 임상적 의미를 인증하지 않는다.
- 모델 채택 여부와 무관하게 모든 필드를 미확인으로 시작한다. 찾을 수 없는 인용은 연결 근거 없음으로 남긴다.
- 확인/수정은 값이 인용 안에 있고, 좌표가 지원되며 해당 페이지를 표시한 뒤 직접 대조한 경우에만 가능하다.
- 비율 자료에서 사건 수를 역산할 수 없다. 분모 0, 비율/소수/다른 숫자의 일부를 정수로 확정하는 입력을 거부한다.
- 내보내기는 항상 `clinicalApproval: false`, `reviewerIdentity: UNAUTHENTICATED_USER`, `downstreamStatus: REQUIRES_REVALIDATION`이다.

## 검증과 한계

Node 24에서 웹 테스트 **149개** 통과. 이번 필드 계약 테스트는 **59개**다.
다른 PDF·페이지·동일 문구의 다른 위치, 입력 hash 변조, JSON 제한, 확인 전제, 변경 이력,
비율/사건 수 분리, 내보내기 escaping 등을 검사했다.
Python 테스트 **232개**, TypeScript 검사와 production build도 통과했다.
기존 MUI `use client` 및 500 kB 초과 메인 청크 경고는 남아 있다.

```bash
# web/에서 Node 24와 상위 Python uv 환경 사용
node scripts/check-field-review-bridge.mjs
```

위 검사는 합성 PDF export 형태 → Python 입력 변환/스크립트 에이전트 → 웹 가져오기 → 사용자 확인/내보내기를 확인한다.
실제 PDF 렌더링·AI 호출·임상 정확도 테스트가 아니다. 합성 자료를 공개 PDF나 실제 모델 실행으로 표시하지 않는다.
개발 서버의 HTTP 응답을 확인했지만 실제 브라우저 업로드·클릭·키보드·모바일/시각 QA는 수행하지 않았다.

남은 중요한 작업:

1. Python 규칙 재검증 CLI와 결과의 화면 복귀는 후속 구현 완료. AI 반론 재실행은 남아 있다. 이전 모델 쟁점은 수정 전 실행 기록으로 별도 표시한다.
2. 표 머리글·각주·문단 여러 개를 묶는 근거 계약과 UI. 단일 문구 연결은 임상 문맥 전체를 증명하지 않는다.
3. 누락/보류를 확정 비교·계산에서 제외하는 공통 계약, 전문가 주석과 독립 평가.
4. [이력 JSON 재불러오기](FIELD_REVIEW_RECOVERY.md)는 후속 구현 완료. 인증된 검토자·영구 저장·접근 권한은 남아 있다.
5. 실제 브라우저 사용성 검증. 소스 수정이나 함수 테스트를 사용자 흐름 검증으로 대체하지 않는다.
