# 자동 조사 뒤 공개 원문 준비

후속 구현: [긴 PDF 준비](LONG_PDF_PREPARATION.md)에서 자동 경로를200페이지 탐색/최대40페이지 보관으로 분리했다.
아래는 최초40페이지 제한 단계의 기록이다. 실제43/123페이지 문서는 후속 검증에서 준비에 성공했다.

2026-09-16. 사용자 입력을 늘리지 않고 조사 → 원문 확보 → 텍스트·추출 입력 준비를 연결했다.
**임상 필드의 AI 추출, 설계 생성, 시뮬레이션까지 자동 실행한 것은 아니다.**

## 구현 범위

- 첫 동의에 공개 PDF 최대 2개 다운로드·텍스트 처리 범위를 명시한다.
- 새 조사 완료 뒤 선택한 NCT의 ClinicalTrials.gov 등록 프로토콜/SAP만 후보로 삼는다.
  등록 문서 연결, NCT, 공식 CDN 경로, PDF URL 일치를 검사한다. SAP 우선, 최대 2개 순차 시도다.
  다른 시험·FDA·관련 논문 PDF로 범위를 자동 확장하지 않는다.
- 기존 문서 API로 다운로드하고 PDF 형식·5MB 제한·응답 SHA-256을 확인한다.
- 기존 PDF 파서의 40페이지/20,000 텍스트 항목/250,000자 제한을 유지한다.
  문서당 55초, 전체 화면 작업 370초 제한과 취소를 적용한다.
- 실제 읽은 페이지의 문구 기반 후보 중 최대 3개를 선택하고 주변 2개 문맥을 포함한 기존 추출 입력을 준비한다.
  사람이 확인했다는 표시나 임상 사실을 자동 생성하지 않는다.
- 화면에 ‘원문 준비’ 단계, 실제 처리 페이지, 후보 문구, 실패 원인을 표시한다.
  페이지 한도 초과는 일반 읽기 실패와 구분한다. 준비 입력 JSON을 저장할 수 있다.

새 모델 호출은 0회다. 기존 AI 브리핑 **이후** 원문을 준비하므로, 앞선 브리핑이 이 PDF를 읽었다고 표시하지 않는다.
MUI 기반 기존 화면 구조와 PDF 처리 제한을 재사용했다.

## 저장·복구 경계

다운로드가 성공한 원본 PDF는 기존 로컬 DB에 보존된다. 텍스트·후보·준비 입력은 현재 탭 상태이며,
JSON 내보내기만 지원한다. 아직 프로젝트 자동 저장이나 PDF AI 실행 화면으로의 자동 인계는 없다.
저장 조사 기록을 다시 열면 새 다운로드/추출/모델 요청을 실행하지 않고, 이번 원문 준비가 없음을 표시한다.
원문 실패가 기존 조사·브리핑 결과를 지우거나 조사 성공을 원문 처리 성공으로 바꾸지 않는다.

## 검증과 실제 제한

- 웹 전체 806개 테스트 통과, TypeScript/Vite 빌드·Ruff·diff 검사 통과.
- Python 코드는 이번에 변경하지 않았다. 직전 전체 606개 통과 기록을 유지한다.
- 신규 검사: 출처 경계, 동의/취소, 다운로드/지문/크기, 최대 2개, 파서 정리,
  빈 후보/페이지 제한, 실제 PDF 파서→추출 입력, 조사 뒤 문서 실패 결과 보존.
- 고정 FDA PDF를 사용한 실제 파서 검사는 **MOC 문서 연결**이다. 해당 FDA 파일을 선택 시험의 프로토콜로 검증한 것이 아니다.
- 실제 조사 `07438cdb-8633-4d11-b857-39d4b466f8ce`의
  `doc_NCT04933695_SAP_005`와 `doc_NCT04933695_Prot_004`를 다운로드했다.
  원본 보존은 성공했지만 SAP **43페이지**, 프로토콜 **123페이지**로 40페이지 한도를 초과했다.
  따라서 이 두 문서의 자동 텍스트·추출 입력 준비는 **미완료**다. 재확인 요청은 캐시 HIT였고 모델은 호출하지 않았다.
- Chrome 로컬 화면에서 동의 범위와 저장 브리핑 재열기/원문 미실행 표시를 확인했다.
  새로운 성공 원문 준비 화면 및 모바일 전체 흐름의 직접 조작 검증은 아직이다.

## 다음 작업

1. 긴 문서의 페이지 선택·범위 기록 계약: 전체 페이지 수, 실제 읽은 페이지, 미검토 페이지를 보존한다.
   앞 40페이지를 잘라 전체 검토로 표시하거나 자원 한도만 무조건 높이지 않는다.
2. 준비 입력·선정 정책을 조사 ID/문서 지문과 함께 저장·복구하고 기존 추출 실행으로 인계한다.
3. 제한된 실제 AI 추출 → 같은 시험/코호트·단위/각주 검증 → 필요한 쟁점만 사용자 확인 → 설계 연결.
4. 긴 문서 성공/실패/취소와 모바일 화면 QA, 실제 전체 흐름 검증.

전체 약 77%/기업 도입 약 25% 추정은 유지한다. 테스트 수나 원본 다운로드만으로 임상 검증 진척을 올리지 않는다.
