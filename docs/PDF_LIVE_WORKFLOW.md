# PDF에서 실제 에이전트·설계 검토까지

2026-09-15 구현. 합성 fixture 재생과 실제 모델 실행을 구분한다.

## 사용 흐름

1. 자료 검토 → PDF 원문 확인. 공개·사용 허가된 비민감 PDF만 연다.
2. 원문 문구를 선택해 PDF 강조 위치를 대조하고 확인 메모를 남긴다.
3. ‘02 에이전트 검토’에서 약물·적응증·시험·질문을 입력한다. 실제 전송 범위를 펼쳐 확인한다.
4. 모델 전송에 동의하고 실행한다. 확인 문구와 앞뒤 2문구만 전송하며 PDF 파일 전체나 사용자 메모는 보내지 않는다.
5. 서버 이벤트에 따라 현재 작업·목적·경과시간·추출 초안·규칙 쟁점·반론·확인 질문·다음 단계를 보여 준다. 모델 내부 사고 전문이나 가짜 진행률이 아니다.
6. 원본 실행 JSON을 저장하고 필드 검토로 인계한다. 값은 모두 미확인으로 시작한다.
7. 한 관측값의 값·인용 대조표를 열어 원문과 확인한다. 같은 표시 페이지의 유효한 보고 필드만 사유·명시적 확인 후 함께 기록할 수 있다. 오류는 개별 수정/보류한다. 미보고 필드는 채우지 않는다.
8. 설계 비교에서 현재 질문·용량군을 연결한다. 일반 자료의 표본수·확률은 빈칸이다. 등록된 합성 PDF에서만 별도 MOC 가정을 선택할 수 있다.
9. 시나리오의 근거 연결에서 관측값·문맥을 보고 새 가정과 사유를 직접 입력한다. 관측 비율을 자동 확률로 변환하지 않는다. PDF/review hash, 인용, 변경 전후와 사유를 시나리오 rationale에 남긴다.
10. 별도 동의 후 로컬 계산. 최초 실행 기록은 현재 세션에서 자동 연결한다. 미확인·보류·문맥 문제와 최초 모델의 미해결 비교 한계는 계산을 차단하고 KOL 의제로 넘긴다.
11. 회의 메모·담당자·다음 행동과 이력을 기록하고 회의 JSON/Markdown을 저장한다. 파일 복구 때 같은 PDF와 최초 실행 JSON도 보관한다.

## 로컬 시작

```sh
uv run python -m trialboard.api --enable-designs --enable-agent-demo --enable-pdf-agent
```

- `--enable-pdf-agent`는 별도 opt-in. 고정 예제 실행 플래그와 독립적이다.
- `POST /api/pdf-agent/run`: `{input: AgentInput, consent: true}`. PDF provenance, 같은 source hash, 페이지, 제한된 본문을 검사한다.
- 최대 4회 모델 요청·수정 1회, 서버 120초·화면 135초. 실제 비교 적용 한계만 남으면 같은 자료 재추출을 생략하고 사람에게 인계한다. 남은 반론을 삭제하지 않는다.
- localhost 개발 화면 전용. 고정 실행과 PDF 실행은 한 개의 동시 실행 슬롯을 공유한다. 취소 시 기존 adapter의 프로세스 정리를 사용한다.
- 로그인 계정의 공식 Codex CLI adapter. 대회 API 키 사용·새 공급자 전환 없음. 서버 영구 저장 없음. 소비한 사용량은 중단해도 반환되지 않는다.

## 검증의 의미와 남은 한계

인용/수치/버전 연결을 자동 검사한 것이며, 원문 진위·임상 타당성·사람의 실제 검토를 인증하지 않는다.
MOC의 확인 이력은 자동 점검 기록이고 전문가 승인이 아니다. 실제 모델은 합성 자료에도 한계를 제기할 수 있다.
그 경우 억지로 계산으로 넘어가는 대신 차단→질문→다음 근거 요청을 시연한다.
성공 계산 예제는 별도 합성 fixture/가정임을 계속 표시한다.

자동 저장·다중 사용자 협업·서버 프로젝트 버전·임상 평가·운영 배포는 미완료다.
개발 중 HMR로 미저장 화면 상태가 사라질 수 있으므로 실행 중 앱 소스를 수정하지 말고 먼저 JSON을 저장한다.
