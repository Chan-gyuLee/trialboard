# 대회 API 개발 지속·자동 재개 승인

> **2026-10-01 철회됨.** 아래는 과거 기록이며 실행 승인이 아니다. 최신 사용자는 대회 API를 제품 런타임에만 사용하고 개발은 개인 계정으로 하도록 지시했다. 잔량 복구 후에도 Dacon 개발/자동재개 금지. [최신 정책](API_USAGE_POLICY_2026-10-01.md).

최신 사용자 지시: “계속 개발시켜 Api로. 자꾸 중단되면 너가 재개해 끝까지 개발하게”.

이 지시는 이전 단계별1회재시도 후 승인대기 규칙을 대체한다. 기존 남은 제품개발 범위는 유지하며, 일시 오류마다 사용자에게 재개를 반복 요청하지 않는다. 완료는 코드·테스트·연결 UI와 독립 QA로 판정하며, 외부 자료/전문가/운영 인프라가 필요한 부분은 별도로 명시한다.

## 실행

- 감독은 기존 `/root/dacon_product_supervisor`, 구현은 `scripts/dacon_worker.py`의 Dacon `gpt-5.6-sol` 단일 writer. 개인계정 공급자로 자동 전환하지 않는다.
- 첫 재개는 마지막 쓰기 가능한 프로젝트 소유자 보호 + Ruff2건을 좁은 작업으로 완료. 이후 권한UI검증·문서버전·이용조건·큐·캐시·다문서·입력/사전/인용·표/OCR·운영도구·통합검증으로 이어간다.
- 영상·녹음 키트·TTS·원본자료·실사용DB·실계정·서버설정·DNS·배포·Git commit/push 변경 금지 유지. 도메인/유료호스팅은 별도 승인 범위다.
- 작업은 작은 검증 가능한 단위로 나눈다. 완료한 코드를 매번 다시 만들지 않고 변경·검증 결과를 인수인계한다. 전체 로그/소스의 불필요한 모델 전송을 줄인다.

## 일시 오류 재개

1. 429/전송단절/timeout/5xx 발생 시 이전 프로세스 종료와 부분 변경부터 확인한다. 진행된 작업을 되돌리지 않는다.
2. Retry-After가 있으면 준수. 없으면 연속 오류에120→240→480→900초 대기(+소량 지터). 이미 충분히 경과했다면 첫 재개 가능. 더 긴 서버 대기 지시는 우선한다.
3. 완료된 변경을 제외한 좁은 후속 지시로 재개. 성공적으로 진행하면 오류 연속 횟수를 초기화한다.
4. 일시 오류가5회 연속이면15분 회로차단 대기 중 로컬 안전 검사를 수행하고 원인을 검토한 뒤 작은 작업으로 재개한다. 승인대기를 이유로 자동 종료하지 않는다.
5. 60초를 넘는 단일 blocking sleep/wait 대신 짧은 대기와 상태 기록을 사용한다. 실패를 숨기거나 무한 빠른 재시도를 하지 않는다.

401/실제 총quota소진403/명시 모델미지원 등은 단순 대기로 해결되는 오류와 구분해 보고한다. 안전한 대안 확인 없이 맹목 재시도하지 않고, 공급자·비밀·계정 경계를 바꾸지 않는다.429만으로 전체토큰소진이라고 추정하지 않는다. 실제필수권한·자료·서비스변경이 필요하면 해당 항목은 사용자 방향이 필요하다.

## 점검과 보고

이전 최대24회는 비용·오류폭주를 막기 위한 자가설정 배치였다. 최신 지속승인 아래24회는 자동종료점이 아니라 누적호출·진전·사용량 재점검 지점이다. 기존 범위에서 실질적 진전이 있으면 다음 작은 배치로 이어간다. 과거 CLI 캐시포함 토큰 집계를 실제 대회 차감량과 혼동하지 않는다.

주요 단계 통과·중요 결함·반복 오류는 부모에게 보고하고 `DEVELOPMENT_REMAINING_STATUS_2026-09-30.md`와 REPORT에 기록한다. 현재79±10%p는 기존 전체 계획 추정이며 재시작만으로 높이지 않는다. 앱종료·컴퓨터잠자기 뒤 무인 실행을 보장하지 않는다.
