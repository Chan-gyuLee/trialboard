# 사용자 수정 후 로컬 재검증

2026-09-13. `field-revalidation/1`은 브라우저의 필드 검토 JSON을 기존 Python 규칙 엔진에 다시 넣는 오프라인 경로다.
모델 호출·원문 외부 전송·개인/대회 API 사용은 없다. 웹 자동 실행은 아직 없으며,
후속 단계에서 [재검증 결과 가져오기 화면](REVALIDATION_RESULT_UI.md)을 연결했다.

## 사용 방법

준비할 파일:

1. 검토에 사용한 **동일한 원본 PDF**.
2. PDF 원문 확인 화면 하단의 **추출 원문 포함 JSON**. 원문 확인 메모를 한 개 이상 기록해야 내려받기 버튼이 활성화된다.
3. 필드 검토 화면의 **이력 JSON**. 기록하지 않은 편집값은 포함되지 않는다.
4. 에이전트 결과를 가져와 검토했다면 **그때 불러온 결과 JSON 그대로**. 내용이 같아도 재저장해 바이트가 바뀌면 파일 hash가 달라 거부한다.

에이전트 결과를 가져온 검토:

```bash
uv run python -m trialboard.agent.revalidate \
  --review /path/to/trialboard-field-review.json \
  --source-export /path/to/trialboard-pdf-evidence.json \
  --pdf /path/to/original.pdf \
  --agent-report /path/to/original-agent-result.json
```

수동으로 만든 관측값만 있는 검토에는 원래 에이전트 결과 대신 문맥을 명시한다:

```bash
uv run python -m trialboard.agent.revalidate \
  --review /path/to/trialboard-field-review.json \
  --source-export /path/to/trialboard-pdf-evidence.json \
  --pdf /path/to/original.pdf \
  --asset '원문 약물명' --indication '원문 적응증' \
  --study '원문 시험명' --question '검토할 질문'
```

가져온 에이전트 결과의 문맥을 명령줄로 덮어쓸 수 없다. 보고서에는 수동으로 추가한 행을 함께 포함할 수 있다.
결과는 `output/revalidation/<새 실행 ID>/report.json`과 `report.md`에 저장한다.
실행마다 새 디렉터리(권한 0700)와 파일(0600)을 만들며 기존 입력·결과를 덮어쓰지 않는다.
이 폴더는 Git 제외 대상이다. 출처·검토 이력이 포함되므로 결과 공유 범위에도 주의해야 한다.
입력/출력 오류는 exit 2, 규칙 검사가 끝나면 exit 0이다. exit 0은 임상적 타당성이나 관측값 채택을 뜻하지 않는다.

## 무엇을 다시 검사하는가

- 원본 PDF 바이트의 SHA-256·크기를 직접 계산해 두 export의 문서 식별자와 대조한다.
- 페이지·문구 ID·인용·지원 좌표와 검토 이력의 연결을 검사한다. 필드 이름, 중복 행, 상태·이력 불일치, 근거 없는 확인, 변형된 원래 값을 거부한다.
- 가져온 보고서는 파일 hash, 실행 ID/모드, 입력 hash, 원문 조각, 관측값 ID/유형, 원래 필드를 대조한다. 임의 삭제된 원래 행도 거부한다.
- `confirmed`/`corrected` 값만 검증 입력에 남긴다. 미확인 값을 결측으로 바꾸더라도 원본 검토 기록에서는 지우지 않는다.
- `held`가 한 필드라도 있는 관측값은 전체를 검증 대상에서 제외하고 ID/필드/사유를 보존한다. 선택 필드나 원래 미보고 필드를 보류한 경우도 같다.
- 기존 `verify()`로 인용·수치 역할·분모·시험 문맥·지표·중복·집단/시점 차이 등 제한된 규칙을 다시 검사한다.
- 수정 전 원래 값에도 동일한 현재 규칙을 적용해 `added`, `no_longer_emitted`, `unchanged` 쟁점을 비교한다. 직전 사람 검토 파일과의 비교나 이전 AI 승인 비교가 아니다.
- 원래 값, 현재 값, 변경 사유/이력, 실제 검증 입력, 원문/입력 파일 hash, 검사 코드 hash를 기록한다.

원문 숫자를 정수로 읽는 기존 공통 규칙도 보완했다. 쉼표가 포함된 큰 숫자의 일부, 유니코드 음수 기호,
전각 퍼센트 기호를 사건 수로 읽지 않으며 정수 뒤 문장 마침표·쉼표는 허용한다.

## 해석 시 주의

`accepted`는 **사용자 검토를 거쳐 현재 규칙 검사를 통과한 관측값 초안**이지, 실제 임상 근거나 설계 권고의 승인 목록이 아니다.
관측값이 남아 있어도 비교 제한은 존재할 수 있다. 모든 결과에 `clinical_approval: false`,
`comparison_status: NOT_APPROVED`, `critique_status: NOT_RERUN`, `model_calls: 0`을 남긴다.

이전 AI의 추출/쟁점/반론은 `previous_model_review`에 별도 보존하며 현재 판단으로 재사용하지 않는다.
`no_longer_emitted`는 해결 인증이 아니다. 보류로 자료가 제외되어 검사가 줄어든 경우도 해당한다.

PDF **바이트 동일성만** 독립 확인한다. PDF 텍스트와 좌표를 다시 추출·렌더링하지 않으므로,
export에 담긴 텍스트/좌표가 실제 PDF와 일치한다는 보증은 아니다. 서명 없는 사용자 검토 이력의 내부 일관성만 확인하며 검토자 신원·실제 육안 대조를 인증하지 않는다.
JSON은 파일당 8 MiB, PDF는 5 MiB, 최대 40페이지다. 실제 규칙 입력은 기존 제한인 40개 문구/24 KB 텍스트 안에 들어야 한다.
범용 PDF 표·여러 문구의 의미·표 머리글/각주·임상 비교 가능성은 아직 검증 범위 밖이다.

## 검증

- Python 전체 **294개** 테스트. 신규 재검증 테스트 57개, 기존 숫자 역할 회귀 사례 5개 추가.
- 웹 기존 **149개** 테스트. 화면 코드는 이번 단계에서 변경하지 않았다.
- `web/`에서 Node 24로 `node scripts/check-field-review-bridge.mjs` 실행.
  실제 웹 가져오기/확인/수정/보류/내보내기 함수와 Python을 왕복한다.
  합성 사례의 미확인 0개 → 분모 교정/확인 4개 → 한 관측값 보류 후 3개를 검증한다.
- 위 사례는 스크립트 응답과 PDF 형태의 시험용 바이트를 사용한다. 실제 PDF 렌더링·LLM 호출·임상 정확도·브라우저 클릭 테스트가 아니다.
- Ruff/format과 diff 공백 검사를 수행했다. 기존 FastAPI/Starlette 경고 2개는 남아 있다.
