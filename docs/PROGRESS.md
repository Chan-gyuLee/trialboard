# TrialBoard 단계별 구현 기록

## 2026-09-11 인수인계 기준

친구용 요약은 [오늘 작업 공유](TEAM_UPDATE_2026-09-11.md), 이후 작업의 우선순위와 통과 조건은 [다음 작업 목록](NEXT_TASKS.md)을 따른다.
최종 로컬 검증은 Python 108개·웹 61개 테스트, Ruff, lockfile, TypeScript, production build 통과다.
일반 PDF 입력·LLM·원격 계산·영구 저장·임상 전문가 검증·실제 브라우저 QA는 아직 없다.
두 로고 시안은 미승인이며 두 번째는 심볼 없는 워드마크다.

아래는 **각 단계가 끝난 당시의 기록**이다. 과거 단계의 테스트 수와 “원래 GitHub에 push하지 않았다”는 문구는 그 시점의 상태다.
이번 인수인계에서는 사용자가 원래 GitHub에 업로드를 요청하여 백엔드·공개 원문·웹·디자인·문서를 별도 커밋으로 정리한다.
실제 반영 상태는 Git 이력과 원격 브랜치를 기준으로 확인한다. Sites 배포와 원래 GitHub 업로드는 서로 다른 작업이다.

## 1단계 합성 검토 핵심

`trialboard/review/`에 정상·분모 오류·자료 결측 경로를 구현했다. 참조·hash·버전·문맥·수치 대조,
부분 보류, 두 고정 표본수 설계의 합성 시나리오 계산과 보고서를 연결했다.
LLM·실제 임상자료·임상적 성능 검증은 포함하지 않는다.

## 2단계 실제 원문과 검토 화면

비공개 미리보기: https://trialboard-evidence-review.fuzzyline-9367.chatgpt.site

2026년 9월 11일 owner-only 배포 성공을 확인했다. 원래 GitHub 저장소에는 push하지 않았으며,
검증한 `web/`만 별도의 임시 source checkout에서 Sites의 비공개 저장소로 전송했다.
앱 내 브라우저 열기는 지원되지 않아 링크로 전달한다.

`trialboard/evidence/`는 고정된 FDA 원본의 SHA-256을 재검증한 뒤, 개발자가 지정한 문구를
정확히 찾아 페이지 좌표를 출력한다. 검색 결과가 없거나 여러 개면 실패한다. 문자열 일부나
유사도만으로 의미 검증 완료를 표시하지 않는다.

현재 문서는 2021년 sotorasib 최초 승인서한과 2024년 항암제 용량 최적화 최종 가이드라인이다.
근거 5개, 원문 페이지 4개를 확인했다. PDF 페이지 번호는 1부터 세며 인쇄된 본문 쪽수와 다를 수 있다.
날짜를 월까지만 아는 가이드라인에는 임의의 일자를 채우지 않는다.

`web/`는 React·TypeScript·Vite 검토 화면이다. 원문 근거·합성 설계 비교·합성 보고서 탭이 있으며,
실제 자료와 합성 자료를 섞지 않는다. 이 단계의 화면은 고정된 근거와 미리 계산된 결과를 탐색한다.
시나리오를 바꾸는 동작은 저장 결과 선택이지 서버 계산이나 LLM 실행이 아니다.
PDF.js 전체 뷰어 대신 해당 원문 페이지 이미지와 정확한 강조 좌표, 공식 PDF 링크를 먼저 연결했다.

### 재생성

```bash
uv sync
uv run python -m trialboard.evidence.build
uv run pytest
cd web
npm ci
npm run build
npm run dev
```

Node는 24 계열을 권장한다. Vite 7은 Node 20.19+ 또는 22.12+가 필요하다.
원문 PDF 스냅샷은 Git에 포함하지 않는다. 새 환경에서는 `build.py`의 두 공식 URL에서 원문을
받고, 지정된 SHA-256과 일치하는 파일을 `data/snapshots/<sha256>.pdf`에 두어야 재생성된다.
원문이 달라졌다면 기존 hash를 무조건 바꾸지 말고 문서와 앵커를 다시 검토한다.
웹에는 선택된 공개 FDA 페이지 이미지와 합성 결과만 포함한다. 원본 HWPX·사내자료·비밀키는 포함하지 않는다.

### 검증 범위

- Python 테스트: 기초 테스트와 검토·계산·원문 위치 검증. 실제 원문이 없는 환경에서는 원문 5개 테스트만 skip된다.
- 원문 4페이지의 렌더링을 직접 확인했다. 원문 내용과 페이지가 맞으며 글자가 읽힌다.
- TypeScript 검사와 웹 production build를 수행한다.
- WebMCP 읽기·근거 열기 도구의 입력 검사와 mock registry 계약을 단위 테스트했다.
- 앱 내 브라우저가 제공되지 않아 실제 브라우저 상호작용과 실제 WebMCP 등록은 검증하지 못했다.
  mock 계약 테스트를 실제 브라우저 검증으로 보고하지 않는다.

### 기존 코드 처리

사용자의 명시적인 삭제 요청에 따라 이전 `agents/`, `core/`, `corpus/`, `graph/`, `lineage/`,
기존 CLI와 테스트 두 파일, 이전 PLAN·수집 manifest·실험 이미지를 작업 트리에서 제거했다.
현재 구현은 `review/`, `evidence/`, `serialization.py`, `web/`로 구성한다.
공용 해시 기능은 새 직렬화 모듈로 독립시켰고 비정상 NaN·무한대 값을 거부한다.

Python 의존성은 현재 사용하는 Pydantic·NumPy·pdfplumber와 개발용 pytest·Ruff로 줄였다.
이전 PyMuPDF·RDKit·SQLAlchemy·수집/LLM/API 관련 미사용 패키지는 제거했다.
향후 실제 API·LLM 기능을 구현할 때 필요한 의존성만 다시 도입한다.
`trialboard` 실행 명령은 새 합성 검토 CLI를 가리킨다.

복구 기준 commit: `f19ea73ff5eecb20b089ea4626514865015a5768`.
Git 이력은 변경하지 않았다. 삭제한 추적 파일은 이 commit에서 복구할 수 있다.
이전 실행 캐시와 실험 이미지는 `/private/tmp/trialboard-legacy.FF5X9t`로 분리했다.
임시 폴더의 장기 보존을 보장하지 않으므로 추적 파일의 복구 기준은 Git commit이다.
원본 HWPX, 제안서 추출 본문, 실제 공개 원문 스냅샷과 이전 로컬 DB는 보존했다.
이전 DB는 새 실행에서 사용하지 않는다.

정리 후 Python 테스트 51개를 통과했고, 새 경로로 공개 근거와 합성 보고서 전체를 다시 생성하여
현재 웹에 포함된 데이터와 파일별 동일성을 확인했다. 테스트 수는 이전 테스트 제거와
새 직렬화 테스트 추가를 반영하며, 임상적 성능을 나타내지 않는다.

## 다음 단계

1. 로컬 화면·API 연결은 4단계에서 구현했다. 다음은 실제 브라우저 사용성 검증과 원격 Python API의 호스팅·인증 설계다. 배포된 링크에서 재계산이 된다고 표시하지 않는다.
2. 근거와 설계 조항·검토 질문 사이의 구조화 연결을 확장한다. 고객 후보물질 데이터 계약과 공개 참고 근거를 분리한다.
3. 제한된 도구 사용·추출·반론·수정의 LLM 실행을 붙이고 독립 평가를 시작한다.
4. 실제 브라우저에서 원문 이동, 조건 변경, 오류·결측, 내보내기, 좁은 화면과 키보드 탐색을 검증한다.

## 3단계 로컬 검토 실행 API

`trialboard/api/`에 FastAPI 실행 서버를 구현했다. 사용 중인 엔진을 재사용하며 저장된 웹 결과를
돌려주지 않는다. 합성 확률·가중치·한계값, 두 표본수, seed·반복과 오류 모드를 수정할 수 있다.
구조화 근거는 여전히 합성 fixture만 지원한다. 실제 자료 업로드나 LLM 호출은 없다.

정상·분모 오류·결측 검증과 새 계산, 정규 입력·근거 입력·구조화 보고서·Markdown 반환을
하나의 요청으로 연결했다. 오류·결측이 있으면 계산과 별개로 부분 보류를 유지한다.
실행 ID는 요청마다 새로 만들고, 입력 hash와 실행 환경으로 재현을 지원한다.
서버 저장·재조회·불변 감사로그는 구현하지 않았으며 `persisted: false`로 표시한다.

본문 크기·필드 타입·확률·표본수·전체 계산량·동시 실행을 제한한다. 외부 브라우저 Origin과
비로컬 Host도 거부한다. 이는 로컬 개발용 방어이며 인증·운영 보안을 대체하지 않는다.
실제 구현에 필요한 FastAPI·Uvicorn과 개발용 HTTPX만 의존성에 추가했다.
기존 비공개 웹 미리보기의 코드·배포는 변경하지 않았다.

실행과 API 계약은 [API 문서](API.md)를 참고한다.

### 이번 단계 검증

Python 테스트 108개와 Ruff 검사를 통과했다. API 신규 테스트는 57개이며 기존 51개도 유지했다.
테스트 의존성에서 HTTPX TestClient 및 AnyIO 별칭 관련 deprecation 경고 2개가 발생한다.
이를 숨기지 않았으며 테스트 실패는 없다. 임상적 타당성 평가와는 별개다.

실제 Uvicorn 서버를 loopback에서 실행하여 HTTP 요청으로도 정상·분모 오류·결측을 확인했다.
각 군 24명·72명 입력에 총 표본수 48명·144명이 반영됐고, 오류·결측 모드는 부분 보류를
유지했다. 과대 본문은 413, 외부 Origin은 403으로 거부했다. 점검용 서버는 종료했다.

## 4단계 Material UI 작업 화면과 로컬 재실행

사용자가 요청한 일반적인 전문 제품 UI 방향에 따라 Material UI·Emotion을 추가했다.
흰 작업면·회청색 탐색 영역·파란 핵심 버튼으로 바꾸고, 첫 화면을 좌측 조건 편집과 우측
두 설계 비교로 구성했다. 공개 근거 검색·원문 페이지 강조·인용문·보고서·WebMCP 기능은 유지했다.

편집값과 마지막 결과의 입력을 분리한다. 미실행 편집에는 명확한 안내를 표시하고,
실행 성공 시 이전 막대 위치·선택 빈도 차이(%p)를 보여준다. 차이를 통계적 유의성으로 해석하지 않는다.
새 실행에 실패하면 마지막 결과를 보존한다. 사례·가정을 전환하면 초기화됨을 미리 표시한다.
보고서 내려받기는 마지막 결과를 사용하고, 직접 실행한 경우 입력·결과 전체 JSON도 제공한다.

로컬 Vite 서버가 Python API를 중계한다. production 빌드는 정적 미리보기이며 실행 버튼을
비활성화하고 재계산 제한을 설명한다. 방문자의 localhost에 접근하거나 임의의 계산 결과를 만들지 않는다.
원격 API·인증·서버 저장은 이번 범위에 포함하지 않는다.

웹 계약 테스트 28개를 통과했다. 프론트엔드 입력 생성 함수와 API 호출 함수를 이용해
실제 Vite → Python 경로로 정상·분모 오류·결측 요청을 보내고 표본수 24/72와 확률 수정 반영을 확인했다.
가정을 바꾸지 않은 재실행은 기존 저장 시뮬레이션과 정확히 일치했다. Python 테스트 108개도 통과했다.
TypeScript 검사와 production build를 완료했다. MUI의 use-client 지시문 및 500 kB 청크 관련
번들 경고가 남아 있다. 실제 브라우저 스크린샷·클릭·반응형 시각 QA는 수행하지 않았다.

비공개 owner-only 미리보기 갱신 성공을 확인했다. 현재 주소는 동일하며 Sites 버전 2다.
검증한 웹 소스는 별도 배포 checkout에서 commit `351e6dff4941de7111c47d7b249a21f5168e291c`로
저장했다. 원래 GitHub 저장소에는 commit·push하지 않았다. 원본 제안서와 Python 구현은
배포에 포함하지 않았다. 미리보기 자동 열기 도구가 제공되지 않아 링크로 전달한다.

## 5단계 자료 → 질문 → 검토 기록

사용자가 첫 화면의 목적을 이해하기 어렵다고 지적하여, 시뮬레이터 중심의 시작 화면을 교체했다.
MUI는 Google이 직접 배포하는 제품이 아닌 Material Design 기반 React 라이브러리임을 명확히 설명했다.
Sites 스킬의 기존 사이트 작업 흐름을 사용했으며 MUI는 유지하되 상단 탐색·단일 문서 작업면으로 재구성했다.

`web/src/intake.ts`의 독립 규칙 엔진과 `IntakeWorkspace.tsx`에서 집계표 선택, 실제 읽기,
원문 확인, 질문별 검토, 원본 행 이동, Markdown·원문 포함 JSON 내보내기를 구현했다.
UTF-8 CSV 한 개를 256 KB·500행·셀 2,000자로 제한한다. 파일은 브라우저 메모리에서만 처리하고
탭 내 탐색 동안 유지하지만 새로고침하면 사라진다. 환자별 정보·식별정보는 넣지 않도록 안내한다.
장기 보관·서버 업로드·원격 LLM 호출은 구현하지 않았다.

검토는 필수 정보·정수 사건 수/분모·알 수 없는 평가항목·용량/항목 중복·시험 문맥 혼합과
평가집단/관찰기간/정의 문자열 차이, 질문에 해당하는 요약 부재를 실제 계산한다.
시험이 섞이면 교차 비교하지 않으며 중복 행은 합산하지 않는다. 누락은 0으로 취급하지 않는다.
문구 비교는 의미 판정이 아니고, 표 점검 통과도 임상적 타당성이나 입력 진위를 뜻하지 않는다.
PK/PD·장기 내약성·편향·권장 용량/표본수 등 미평가 항목을 별도로 표시한다.

초기 화면에는 가짜 분석 결과가 없다. 합성 예제 버튼을 누르면 12주/8주가 다른 행을 직접
읽고 검토한다. CSV에서 이를 수정하면 해당 쟁점이 사라지는 것을 테스트했다.
공개 FDA 근거는 별도 참고 라이브러리이고, 입력 CSV의 원본을 검증한 근거로 표시하지 않는다.
