# 용량 비교 목적의 자동 시험 선정 · 2026-09-16

사용자 목표: 입력은 최소화하고 에이전트의 실제 작업과 결과를 보여준다.
이번에는 약물명→적응증 확인 후 시작할 시험을 고르는 `dose-start/1`을 추가했다.
기존 MUI/로컬 구조를 유지하며 새 입력란·실행 단계·모델 호출은 추가하지 않았다.

## 선정 규칙

`web/src/trial-priority.ts`가 수집된 등록정보에서 문구 신호만 계산한다.

1. 서로 다른 시험군에서, 입력 약물명 바로 뒤에 서로 다른 양수 mg 용량이 명시된 경우.
2. 단일 등록 약물과 입력명이 일치하고, 제목에 약물명과 용량 비교/탐색 표현이 있는 경우.
3. 위 신호가 없으면 기존 결과 공개 여부/첨부 문서 수를 사용하고 용량 비교 문구 미확인을 명시한다.

같은 신호 수준에서는 자료 접근성, 마지막은 NCT 순서로 정한다. 점수는 내부 정렬값이지 임상적 확신/성공 확률이 아니다.
한 시험군 내 서로 다른 용량·라벨/설명의 상충, 다른 약물의 용량, mg/kg, 정제 수, 별칭은 두 용량군 신호로 쓰지 않는다.
문구 원형을 보존한다. 관찰된 계획을 무작위 비교 결과나 동일 환자군·동일 일정으로 승인하지 않는다.
단순 문구 규칙이라 비교시험·병용요법·코호트의 복잡한 의미를 해석하지 못하며 mg 외 단위와 별칭은 미지원이다.

기존 `researchCandidates`/`chooseCandidate`/실제 `runAutoReview`에 연결했다.
약물/적응증 범위 확인은 그대로이며, 다른 암종을 높은 점수로 덮어쓰지 않는다.
명시적으로 입력한 NCT도 바꾸지 않는다. 확보한 최대20개 검색 결과 안에서만 선택하며 전체 등록부 최적 선정이 아니다.

## 화면

- 범위를 고르면 조사 시작 시험·선정 이유·최대2개 용량 문구를 자동 표시한다.
- 작업 중에는 상태를 펼치고, 범위 확인/완료 시에는 기록을 접어 질문·결과가 먼저 보이게 한다.
- 새 실행의 결과에서 선정 문구를 다시 볼 수 있다.
- 저장 기록 재열기는 과거 시험 범위를 그대로 열며 현재 규칙으로 다시 선택하지 않는다.
  **선정 정책/문구의 별도 영구 저장은 아직 없다.** 과거 기록의 선정 이유를 새 규칙의 이유로 소급 표시하지 않는다.
- 입력 데이터 검증에 arm.description의 문자열/null 검사를 추가했다. 과거 null 기록 호환 유지.

## 검증

- 새 합성 검사16개(선정15/자동 흐름1): 상대 약물/별칭/부분 일치/동일 용량/단위/정제/0/감량/상충/
  Unicode/다중 적응증/명시 NCT/불변성/실제 조사 요청으로 인계.
- 웹 전체790개 통과, TypeScript/Vite 빌드 및 Ruff/diff 통과. Python 코드 변경 없음(직전606개 통과 유지).
- 기존 실제 검색 기록 `07f0311a-9ee2-45e5-a40c-3a0557ab4a45`를 GET으로 읽어 대조했다.
  Non-small Cell Lung Cancer 범위에서는 기존과 동일한 NCT04933695를 선정하며,
  등록 시험군 문구 `Sotorasib: 960 mg` / `Sotorasib: 240 mg`를 근거로 표시한다.
  따라서 이 사례는 선택 시험이 바뀐 성공 사례가 아니라 선정 기준/설명의 개선 확인이다.
- Chrome 실제 약물 입력→공개 검색72건 중20건 확보→범위 선택→시험/문구 표시 확인.
  모델 실행 전 범위 확인에서 멈췄다. UI 배치 수정 전후 공개 검색 각1회, 새 모델 호출0회.
- 모바일/전체 키보드/새 정책 실모델 전체 완주는 아직 미검증이다. 기존 COMPLETE 브리핑과 합쳐 보고하지 않는다.
