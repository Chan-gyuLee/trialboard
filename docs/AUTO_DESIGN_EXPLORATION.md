# 자동 조사 뒤 가상 설계 탐색

2026-09-16. 로컬 구현. 실제 근거 기반 임상 설계나 AI 설계 생성 완료가 아니다.

## 사용자 흐름

약물 입력·한 번의 동의 → 범위 확인 → 조사·원문 검토 → 비교 준비 점검 →
**별도 MOC 가상 설계 탐색 자동 계산·저장** → 보고서.
초기 동의 문구에 로컬 MOC 계산 범위를 포함했고 중간 실행 버튼은 추가하지 않았다.
가상 가정을 바꾸는 탭은 저장된 9개 조합 중 표시만 바꾼다. 모델/계산 재호출이 아니다.

신규 `illustrative-designs/1` 규칙 라이브러리:

- 군당20/40/60명, 고정 균등배정 두 가상군 A/B. 권장 표본수나 실제 용량군이 아니다.
- 가정3종: 차이 없음 / 효능·이상반응 상충 / 모두 한계 초과.
- 기존 `review.engine.simulate` 사용, seed42·각2,000회·총9조합. PCG64 환경/엔진 지문 기록.
- 실제 등록 수치는 참확률로 추정·변환하지 않는다. A/B에 실제 용량을 매핑하지 않는다.
- `provenance=RULE_LIBRARY_HYPOTHETICAL`, clinicalApproved=false, userApproved=false,
  recommendedPlanId=null, evidenceUsedAsParameters=false, modelCalls=0.
- `research-exploration/1`은 기존 `design-brief/1`의 사용자 가정·근거 검증을 우회하지 않는 별도 산출물이다.
  **AI_PROPOSED 계약 및 모델 기반 설계 제안은 아직 미구현**이며 현재 규칙 라이브러리를 AI 생성으로 소개하지 않는다.

선택 빈도/보류 빈도/가정한 한계 초과 군 선택/Monte Carlo 표준오차를 표시한다.
‘차이 없음’에서는 두 군의 참효용이 같아 어느 쪽을 선택해도 올바른 선택으로 집계한다는 안내를 추가했다.
어떤 수치도 검정력·임상 성공·허가 확률이 아니다. 반응/이상반응 독립성, 결측/탈락/중간중단 미구현 한계 유지.

## 연결·저장·실패 처리

- `/api/research/runs/{id}/exploration` GET/POST. POST는 정확한 로컬 Origin 및 consent:true 필요.
  클라이언트가 확률·수치·승인값을 주입할 수 없다. 설계+근거 조사 기능 플래그 모두 필요.
- 서버의 완료/부분 완료된 저장 조사만 사용. 모델 브리핑이 없는 실패를 가상 설계로 대체하지 않도록
  기본 자동 흐름은 review가 있을 때만 계산한다. capability 없는 구 서버에서는 실행하지 않는다.
- SQLite `research_exploration`에 run당1기록, digest와 JSON 저장. 중복 요청은 같은 결과를 반환하고
  읽기는 재계산하지 않는다. 손상 기록은 보류하며 덮어쓰지 않는다. 기존 조사/추출 이력은 불변.
- 기존 로컬 계산 동시 실행 제한 재사용. 실패/취소 시 자동 재시도 없음, 실제 조사 결과 유지.
- 실행 단계에 ‘가상 설계 탐색’ 추가. 요청 직전과 결과 검증·저장 후 상태만 표시. 가짜 사고 과정 없음.
- 결과 화면에 MUI 탭·3열 카드·모바일 단일열 스타일. 섹션 상단/하단 MOC 표시.
  통합 Markdown에 모든 가정/9조합/엔진 지문/한계·질문 포함.
- Sites 지침에 따라 기존 MUI/React·Python/SQLite 구조를 유지했다. 외부 DB·배포·의존성 변경 없음.
