# 용량 검토용 입력 선정 · 2026-09-16

## 이번 변경

추가 입력·클릭 없이, 수집한 자료 중 AI가 실제 읽는 제한된 문맥을 개선한다.
검색 결과 전체를 읽거나 임상적 관련성을 확정하는 기능은 아니다.
`trialboard/research/relevance.py`의 정책 버전은 `dose-context/1`이다.

- 계획 입력 최대24개: 선택 시험 등록정보 → 검토 범위 문구에 선택 NCT가 있는 자료 → 등록부 결과 인용 →
  약물명과 용량 비교 표현이 함께 있는 자료 → 그 외 읽을 수 있는 자료 → 메타데이터 순서.
- 배경 인용·제목의 리뷰/증례 표현은 같은 순위 안에서 뒤로 보낸다. 모델 우선순위는 같은 신호 수준에서 반영한다.
- 검토 입력 최대8개: 선택 시험 등록정보와 연결 신호가 있는 논문1개를 먼저 확보하고, 새 후속 논문 최대2개를 보존한 뒤 채운다.
- PDF_AVAILABLE/서지 메타데이터는 수집 기록과 계획에 남되 인용 브리핑의 본문 자리로 채우지 않는다.
  PDF를 읽었다고 표시하지 않으며 원문 확보는 다음 작업이다.
- 신호는 실제 검토가 읽는 앞4,500자 기준이다. 계획 발췌는 기존650자이므로 신호만 보고 결과를 추정하지 않도록 지시했다.
- NCT 검색 경로 태그만으로 본문에 해당 NCT가 있다고 판단하지 않는다. 완전한 토큰을 대조한다.
- 용량 비교 표현은 영어 문구 규칙이며 부정·계획·배경도 잡힐 수 있다. 수치 추출/결과 인정/동일 코호트 승인에 사용하지 않는다.
- 각 모델 요청 전에 입력 출처 ID·버전 지문·신호를 `calls[].context_selection`에 보존한다.
  출력 거부/실패 기록에도 남는다. 기존 저장 스키마/인용 계약/동의/대회 모델/2요청 한도를 유지했다.
- 기존 `CITATIONS_READY` 이벤트로 등록정보 수·시험번호 문구가 있는 논문 수·구간 수를 표시한다.
  새로운 단계나 버튼은 추가하지 않았다. 내부 사고 전문이나 임상 확신 점수가 아니다.

[OpenAI의 문맥 구성 안내](https://developers.openai.com/api/docs/guides/prompt-engineering)를 참고해
자료와 지시를 분리하고, 신호의 의미/범위를 명시했다. 모델 변경이나 SDK 변경은 없다.

## 다음

지금 정책은 **이미 선택된 한 시험 안에서 읽을 자료를 고르는 것**이다. 최초 시험 선택은 아직 기존 로직이다.
약물명에서 시작할 때, 용량 비교 목적에 맞는 최초 시험 후보를 고르는 기준과 선정 근거를 강화해야 한다.
다른 시험/코호트는 자동 합치지 않는다. 이후 원문 확보→근거 충분성 확인→설계 초안/계산 연결,
복수 약물 평가와 임상 전문가 검토가 남는다. 전체 추정77%/기업25% 유지.
