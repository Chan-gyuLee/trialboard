다음 세부 순서:

3. 실제 Codex 모델의 수정 루프·프롬프트 주입·잘못된 보류를 평가한다. 지금 수정 경로의 성공은 여전히 scripted test이며 실제 자율 수정 성능을 검증한 것이 아니다.
4. 통과한 뒤 PDF 필드 확인 UI에 초안·원문·보류 이유를 연결한다. 개인 Codex 로그인을 웹에 공유하지 않으며, 서버 API 실행은 대회 전환/권한 정책을 정한 뒤 추가한다.

## 목표와 실행 순서

개발팀이 실제 자료를 넣고 “무엇을 비교할 수 있고, 무엇을 더 확인해야 하는가”를 원문과 함께 검토하여 회의용 브리프를 가져가는 흐름을 완성한다.

`자료 계약 → PDF 원문·추출 확인 → 질문·쟁점·브리프 연결 → 제한된 AI 실행 → 독립 평가 → 본선 패키지·파일럿`

사용성 점검과 전문가 정답집 준비는 앞 단계부터 함께 시작한다. 이름·장식·범용 에이전트 구조를 핵심 흐름의 선행 조건으로 두지 않는다.

- [ ] **P0-03 텍스트 PDF 입력.** 먼저 사용 권한이 확인된 공개 문서로 단일 문서 흐름을 만든다. 파일/페이지/시간 제한을 정하고 텍스트·표·페이지 위치를 추출한다. 스캔·깨진 인코딩·복잡한 표는 지원 밖 또는 수동 확인으로 표시한다. 범용 OCR은 뒤로 미룬다. **완료 조건:** 정상·추출 실패·표 해석 불가의 세 경로가 원문을 보존하고 명확히 종료한다. 실제 기업 파일의 서버 전송은 저장 위치·권한·보존 정책을 결정하기 전 열지 않는다.
- [ ] **P0-04 원문으로 돌아가기.** 추출 필드/검토 쟁점 클릭 시 올바른 문서 버전·페이지·표/문장 위치를 연다. 좌표의 원점·회전·페이지 크기를 보존한다. **완료 조건:** 다른 페이지, 같은 문구의 중복 위치, 변경된 문서 hash를 포함한 실패 테스트와 사람이 확인한 사례. 문자열 일치만으로 임상 검증 완료 표시 금지.
- [ ] **P0-05 추출 확인 단계.** 자동 추출은 초안으로 제시하고 사용자가 수치·단위·분모·집단·시점을 확인/수정/보류한다. 원문값과 수정값·사유를 구분한다. **완료 조건:** 미확인/충돌 필드는 확정 근거에서 제외되고, 수정하면 관련 쟁점이 다시 계산된다.

공개 PDF 입력·문구 확인의 첫 흐름은 구현했다. 다음은 P0-02의 공통 계약과 P0-05의 임상 필드 확인을 연결하고, P0-01의 실제 사용성을 점검한 뒤 지원 문서를 늘린다.

## P1 — 실제로 가져갈 수 있는 검토 결과

- [ ] **P1-01 핵심 질문 검증.** 임상개발·임상약리·통계·규제 담당자가 실제 회의에서 확인하는 질문인지 인터뷰한다. 현재 세 질문은 제품 가설이다. 우선 용량 간 비교 가능성, 내약성 정보 부족, 다음 회의의 추가 자료 요구를 검증한다. PK/PD·노출–반응 등 필요한 범위는 전문가 피드백에 따라 추가한다. 인터뷰 없이 현업 적합성 검증 완료라고 하지 않는다.
- [ ] **P1-02 근거-질문-조항 연결.** 각 질문에 필요한 근거를 정의하고 주장별 채택/보류 이유와 영향을 받는 설계 조항을 연결한다. 같은 약물의 다른 적응증·코호트를 섞지 않는다. **완료 조건:** 한 근거를 제거/변경하면 관련 판단만 갱신되고, 관련 없는 문서로 빈칸을 채우지 않는다. 의존: P0-02/05.
- [ ] **P1-03 회의용 브리프.** 확인된 사실, 비교 제한, 후보 설계의 근거와 가정, 미해결 질문, 요청할 자료, 담당 역할, 판단 재개 조건을 한 결과로 내보낸다. 현재 Markdown/JSON에서 시작한다. **완료 조건:** 모든 사실 주장은 원문 또는 명시된 사용자 입력으로 추적되며, 합성 예제가 실제 약물 결과로 보이지 않는다.
- [ ] **P1-04 제한된 LLM 연결.** 대회 제공 모델/API의 실제 계약을 확인한 뒤 서버 adapter를 연결한다. 자료 읽기·구조화 초안·반론·추가 자료 요청에 한정하고 계산은 검증된 코드가 담당한다. 허용 도구, 호출/시간/비용 상한, 수정 최대 2회, 실패/취소/부분 보류를 구현한다. 문서 속 지시는 비신뢰 데이터로 취급한다. 비밀키는 서버 설정에만 저장하고 저장소/클라이언트/일반 로그에 넣지 않는다. **완료 조건:** 잘못된 구조화 응답, API 중단, 예산 초과, 프롬프트 주입을 포함한 테스트; 결과와 실제 호출 이력 확인. 의존: P0와 P1-02. 유료 사용에는 사전 예산 합의가 필요하다.
- [ ] **P1-05 검색·추가 확인.** 먼저 허용된 공개 출처와 문서 메타데이터 검색만 지원한다. 출처 날짜·버전·수집일·hash·권리를 보존하고 문서 부족을 명시한다. 임의 URL 수집은 사설 IP·내부 주소·리다이렉트 우회 차단 후 검토한다. 큰 벡터 DB는 검색 평가에서 필요가 확인될 때만 추가한다.
- [ ] **P1-06 설계와 계산의 타당성.** 현재 합성 고정 표본수 비교를 실제 설계 권고와 분리한다. 공개 수치에서 임상 모수를 자동 확정하지 않는다. DROID/MERIT 등의 도입은 원 논문의 전제·구현·독립 재현·통계 전문가 검토 후 결정한다. **완료 조건:** 관측값/가정/추정값 분리, 지표 사건과 분모 명시, 경계값·seed·Monte Carlo 오차 테스트. Monte Carlo 오차를 임상 추정의 불확실성으로 표현하지 않는다.

## P1 — 재현·저장·안전한 서비스

- [ ] **OPS-01 배포 구조 결정.** 현재는 정적 웹 + 로컬 Python이다. 원격 계산을 위해 Python 서비스와 인증/저장소를 설계하거나 호스팅 환경에 맞는 별도 실행 계층을 검증한다. 정적 사이트 설정만으로 Python이 실행된다고 가정하지 않는다. **완료 조건:** 인증된 원격 요청, 제한 초과·실패·재시도, 저장과 결과 재조회가 배포 환경에서 동작한다. 호스팅 비용·데이터 위치 승인 전 구매하지 않는다.
- [ ] **OPS-02 사례·실행 저장.** source/claim/issue/run/사용자 수정 이력의 스키마와 migration을 만든다. 원본 불변성, 실행 입력·버전·seed·결과, 재실행과 저장 결과 재생의 차이를 기록한다. 현재 UUID는 영구 감사 기록이 아니다. **완료 조건:** 새로고침/프로세스 재시작 후 결과 복구, 중복 실행 방지, 이전 결과 보존.
- [ ] **OPS-03 접근·기밀·삭제.** 인증, 역할별 사례 접근, 로그 최소화, 파일 보존/삭제, 백업 복구, 기업별 분리, 업로드 권한을 결정·시험한다. 실제 환자 수준 자료는 초기 범위에서 제외한다. 친구의 미리보기 공유 권한도 별도 확인한다. 외부 공유 범위는 임의로 넓히지 않는다.
- [ ] **OPS-04 CI와 새 환경 재현.** GitHub Actions에 Python·웹 테스트, Ruff, 타입 검사, build를 넣는다. 원문 fixture를 공식 URL/hash로 안전하게 준비하는 방법과 skip 범위를 명시한다. Node 24·Python 3.12 및 lockfile을 사용하고 새 clone에서 확인한다. 현재 CI는 아직 만들지 않았다.
- [ ] **OPS-05 경고·성능·접근성.** Python deprecation, MUI 번들 경고, 500 kB 초과 JS를 확인하고 화면별 지연 로딩을 검토한다. 색상 대비·키보드·포커스·표/원문 접근성을 점검한다. 의존성과 공개 페이지 재배포 라이선스 검토 기록도 남긴다.

## P1 — 심사와 고객에게 보여줄 증거

- [ ] **EVAL-01 평가자료 동결.** 개발 사례와 독립 평가 사례를 시험/protocol family 단위로 분리한다. 오류 유형·주석 지침·정답 변경 이력을 고정한다. 개발자가 만든 정답과 전문가 합의 정답을 구별한다.
- [ ] **EVAL-02 전문가 검토 확보.** 서로 독립적으로 원문을 검토할 관련 전문가를 확보하고 불일치를 합의한다. 최초 50개 항목부터 점검할 수 있다. 제안서의 10개 이상 사례·200개 이상 항목은 미달성 목표이며 인력 확보 후 실행 규모를 확정한다.
- [ ] **EVAL-03 기준선·기능 제거 비교.** 동일 자료와 가능한 한 같은 모델/호출 예산으로 단일 LLM, RAG, TrialBoard를 비교한다. 원문 검증·문맥 연결·반론을 각각 뺐을 때 차이도 기록한다. 모델/API가 없는 현재 단계에서는 수행 완료로 표시하지 않는다.
- [ ] **EVAL-04 측정과 실패 공개.** 분모·집단·시점 등 치명 오류, 인용 위치 정확도, 추출 정확도, 적절한 보류와 답변 범위, 사람이 수정한 항목을 측정한다. 사용자 검토시간은 원문 재확인 시간까지 포함한다. 표본 수와 실패 사례를 공개하며 자동 테스트 169개를 임상 정확도 지표로 사용하지 않는다.

## P2 — 브랜드·본선·사업화

- [ ] **BRAND-01 심볼 로고.** 두 기존 안은 미승인 기록으로 유지한다. 이름 글자만이 아니라 단독으로 식별되는 심볼을 만들고, 흑백·16/24/32 px·가로/세로 조합에서 확인한다. 채택 후 SVG 원본과 간격/색상 규칙을 만들어 앱에 적용한다. 사용자 승인 전 최종 로고로 바꾸지 않는다. 상표·도메인 확인은 별도이며 법적 안전성을 보장하지 않는다.
- [ ] **FINAL-01 공식 공지 재확인.** 본선 일정, 심사 항목, 제공 API/사용 제한, 외부 자료·저작권 조건, 제출 양식/파일/분량/시연 요건을 공식 페이지에서 다시 확인하고 확인일을 남긴다. 예선 전문가 실제 점수는 공개되지 않으면 추정값을 사실처럼 쓰지 않는다.
- [ ] **FINAL-02 제출 패키지.** 검증된 구현 상태로 제안서와 README를 갱신하고 필요 형식의 문서·슬라이드·영상·재현 가이드를 준비한다. 정상·분모 오류·근거 결측 세 데모를 실제 실행으로 보여준다. 저장 결과 재생과 실시간 실행을 구분한다. 본선 제출 자체는 별도 사용자 지시 후 한다.
- [ ] **BIZ-01 고객 문제 확인.** 후보 바이오텍의 담당 직무, 현재 검토 방식, 반복 빈도, 실제 산출물, 비용 지불 주체를 인터뷰한다. 기업 파일 사용 권한과 기밀 조건을 먼저 합의한다. 외부 연락·파일 전달은 별도 요청 없이 수행하지 않는다.
- [ ] **BIZ-02 제한된 유료 파일럿.** 특정 약물·질문·자료 범위·검수 기준·사람의 최종 책임을 정한다. 시간 절감과 오류 발견의 증거가 확보되면 계약형 도입 또는 내부 AI팀 협업을 논의한다. 계약금·수익·우승을 보장하지 않는다.

## 당장 하지 않을 것

전 암종·전 모달리티 지원, 환자별 처방, 승인/성공 확률 예측, 대규모 OCR, fine-tuning, Kubernetes, 전용 벡터 DB, 무제한 에이전트 실행, 근거 없이 더 복잡한 시뮬레이션. 기존 코드 삭제가 새 코드의 우월성을 입증하지는 않는다. 제품의 차이는 실제 업무 검토와 독립 평가로 확인한다.
