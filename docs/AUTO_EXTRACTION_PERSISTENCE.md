# 자동 추출 저장·등록 결과표·통합 보고서

2026-09-16. 최신 사용자 요청: 자동화를 완성할 때까지 이어서 구현.

## 이번에 연결한 범위

약물명·전송 동의 → 모호한 약물/적응증 범위만 확인 → 조사/인용 브리핑 → 공개 PDF 준비 →
원본·희소 페이지 입력 저장 → 대회 모델 추출·규칙 대조·필요시 반론 → 남은 질문과 보고서.
등록부의 실제 결과표도 같은 조사 스냅샷에서 읽어 표시한다. 새 수동 입력란은 없다.
단, **복수 설계 생성·시뮬레이션까지 자동 완성한 것은 아니다.**

### 저장과 실행

- `research-automation/1`, SQLite `research_automation`: 조사별 불변 입력 1개/추출 실행 1회.
- 원본 PDF 다운로드 영수증·바이트 SHA256/크기, 조사·약물·적응증·NCT·출처를 서버에서 대조한다.
- `pdf-evidence-window/1`의 원래 페이지·span ID·좌표·선정/미보관 범위를 보존한다.
- 브라우저 텍스트가 PDF와 일치하는지는 서버가 독립 재추출하지 않으며 `textVerifiedAgainstPdf:false`다.
- 준비/진행/최종 보고서를 저장한다. 중복 실행 409, 공용 모델 슬롯 429, 재시작 때 실행 중이던 기록은 INTERRUPTED.
- 기록 복구는 GET만 사용한다. 모델 자동 재시도·개인 Codex fallback 없음.
- 조사 최대 2회 + PDF 추출/반론 최대 2회 = 총 최대 4회. PDF repair 0회, 추출 예산 120초.
- 원문 준비 POST만 최대 4MB. 기존 작은 API 요청 제한은 유지한다.
- 자동 경로는 기존 수동 PDF 프로젝트(연속 1~40페이지)와 다른 계약이다. 무리하게 같은 뷰어/설계 입력으로 주입하지 않는다.

### 등록부 결과표

`registry-result-tables/1`: 해당 NCT 원본 스냅샷 SHA256 검증 후 outcome groupId와 measurement/denominator를 연결한다.
보고 수치·단위·분석집단·기간·정의·class/category·구간값·JSON pointer를 보존한다.
안전성은 serious/other adverse events 및 all-cause mortality를 별도로 표시한다.
통합 집단을 용량별로 나누지 않고, 비율로부터 사건 수를 역산하지 않으며 SAE를 Grade ≥3로 바꾸지 않는다.
상한은 outcome 50개/중첩 항목 20개/결과 100행/안전성 집단 20개이며 생략 가능성을 표시한다.

새 수집에서는 `REGISTRY_RESULTS` 출처를 만들어 이후 모델 입력 후보에도 포함한다.
수집 발췌 최대 17,500자 안에서 완전한 행을 보존하지만, 기존 모델 검토 입력은 출처당 4,500자 제한이므로
**모든 결과 행을 모델이 읽었다고 주장하면 안 된다.** 새 결과표 출처를 포함한 실제 모델 브리핑 품질 재평가는 아직이다.
기존 저장 브리핑은 수정하지 않으며 결과표가 당시 입력에 없었다는 안내를 화면/보고서에 붙인다.

### UI·보고서

- 실제 추출 이벤트·검사 상태, 미승인 관측 초안, 원문 인용/PDF 원래 페이지 링크.
- 등록 결과표에서 시점·하위 항목을 행에 표시하고 긴 원문 맥락은 펼침으로 확인.
- 브리핑/추출 범위/등록 결과표/남은 질문을 하나의 Markdown으로 내려받는다.
- 모델이 생성한 해석, 등록된 실제 수치, PDF 추출 실패를 서로 구분한다. 임상 승인/시뮬레이션 수행을 주장하지 않는다.
- 원문·진행 상태 저장/복구는 Sites 저장 원칙에 맞추되 기존 Python/SQLite/MUI와 로컬 실행을 유지했다. 배포하지 않았다.

## 실제 검증

1. 기존 조사 `07438cdb-8633-4d11-b857-39d4b466f8ce`: SAP 43페이지, 40페이지 보관,
   후보 3개/입력 15문구 → 대회 추출 1회 2,080보고 토큰 → 관측 0개/NEEDS_EVIDENCE 저장·복구.
2. Chrome 새 입력 `sotorasib` → 공개 검색 72건 중 20건 저장 → NSCLC 범위 1회 확인 →
   조사 `b183262a-4890-492c-b5b7-77cdf11969d2`, NCT04933695.
   범위 확인 뒤 약 37초, 작업 이벤트 77개, 근거 79개/인용 쟁점 7개/KOL 질문 7개.
   조사 2회 17,012보고 토큰 + SAP 추출 1회 2,080토큰. PDF 관측 0개로 정상 보류.
3. 이번 합계 모델 4회, 응답에서 보고된 21,172토큰. quota 헤더의 실제 누적 총량과 동일하다는 뜻은 아니다.
4. 실제 저장 스냅샷에서 결과 24행/안전성 6행을 복구. 첫 ORR은 두 용량 통합 분석으로 보고되어
   용량별 효능으로 분리하지 않았다. 안전성은 별도 용량 집단을 그대로 유지했다.
   결과표 연결은 위 새 실행 이후 추가했고 모델 호출 없이 GET/프런트 계약으로 검증했다.
5. API 재시작 후 브라우저 기록 재열기·결과표 펼침·원본 맥락/안전성 배치 확인. 추가 모델 0회.
   보고서 생성은 실자료를 사용해 자동 검증했다. 다운로드 클릭·모바일 전체·새 영상 QA는 아직이다.

Python **636개**, 웹 **839개**, Ruff, TypeScript/Vite 빌드 통과. 합성 테스트는 임상 성능 검증이 아니다.
기존 MUI `use client`/큰 번들 청크/테스트 의존성 deprecation 경고 유지.
키 값 매칭 검사에서 저장소 파일 일치 없음. 키는 승인된 저장소 밖 파일에만 유지.
기존 WIP/DB 보존, commit/push/배포 없음.

## 아직 자동화가 끝나지 않은 이유·다음 순서

1. 결과표의 전체 행·집단·분모·각주를 모델 입력과 구조화 근거 계약으로 연결해야 한다.
   현재는 원문 표 표시 및 제한된 브리핑 입력 후보이고, 검증된 설계 파라미터가 아니다.
2. 결과 논문/등록부 우선 정책: SAP/프로토콜은 계획 문서라 관측 결과 추출 0개일 수 있다.
   현재 최대 후보 3개 문구만 추출 입력에 쓰는 것도 실제 결과 확보 한계다.
3. 근거 기반 값과 에이전트 제안 가정을 분리한 복수 설계 초안/승인/계산 연결.
   기존 `user_declared_hypothetical`을 에이전트가 선언하거나 전문가 승인 플래그를 자동 채우면 안 된다.
4. 여러 약물·결과 없음·서버 중단·접근 제한 사례, 모바일/키보드/최종 시연 및 독립 임상 평가.

전체 계획 추정 **78%**, 기업 도입 **25%**, 오차 최소 ±10%p. 자동 수집/근거 DB 영역만 +1.
나머지 임상 평가·설계 자동 완주 점수는 올리지 않았다.
