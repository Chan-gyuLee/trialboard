# TrialBoard · 3분 시연 리허설 대본

2026-09-15. 팀 내부 제안이며 공식 발표 시간·제출 요건을 확인한 문서는 아니다.
목표는 근거 검토, 비교 제한, 별도 합성 설계의 변화와 회의 질문을 명확히 보여주는 것이다.

## 준비

- 로컬 `http://127.0.0.1:5173/`, API `uv run python -m trialboard.api --enable-designs --enable-agent-demo`.
  이미 켜져 있으면 중복 실행하지 않는다. 발표 직전 소스 수정/HMR·서버 재시작을 하지 않는다.
- 공개 모델 저장 기록 → ‘발표 집중 모드’ → ‘근거를 구조화’에서 시작.
- 아래 경로는 **이전 실제 모델 기록 + 현장 합성 재계산**이다. 새 모델 호출 시간을 포함하지 않는다.
  실제 실행 시 별도 동의가 필요하다. 공개2요청은 이번 단일 실측 약52초이며 시간 보장은 아니다.
- 먼저 ‘시연 준비 확인’을 누른다. 이 검사는 모델 호출/로그인 검사가 아니다. [실행/중단 점검 기록](LIVE_DEMO_REHEARSAL.md).
- 1440px에서 숫자와 질문을 확인한다. 프로젝터 높이에 따라 질문으로 한 번 스크롤한다.

## 클릭과 멘트

| 구간 | 화면·클릭 | 제안 멘트 |
| --- | --- | --- |
| 0:00–0:15 | 공개 기록의 관측 카드 | “설계 검토에서 무엇을 근거로 말할 수 있는지 분리합니다. 지금은 이전 실제 모델 실행 기록입니다.” |
| 0:15–0:50 | 85% 카드 → 연결된 원문 | “85%와 96%가 보입니다. 하지만 두 용량의 성적일까요? 대상군과 분모를 원문에 연결해 확인합니다.” |
| 0:50–1:15 | 비교의 허점을 검토 → 반론 근거 | “모델은 치료 이력이 다른 코호트라는 제한을 짚습니다. 없는 용량 정보나 사건 수를 채워서 비교하지 않습니다.” |
| 1:15–1:35 | 모르는 것은 보류 → 다음: 합성 설계 비교 | “관측값은 남기되 비교 결론은 보류하고 질문을 넘깁니다. 이제 다른 합성 사례입니다. 앞의 수치를 가져온 계산은 아닙니다.” |
| 1:35–2:15 | A55/B65 → 두 설계 재계산 | “독성 우려를 높였을 때 환자를 두 배로 늘리는 것이 답일까요? 기준·변경과 두 설계 조합을 각각 1만 번 계산합니다. 보류 빈도는 98.5%, 99.8%입니다. 성공이나 허가 확률은 아닙니다.” |
| 2:15–2:45 | 아래 KOL 질문 | “보류는 실패율이 아닙니다. 한계 초과 군 선택도 함께 봅니다. 증원 전 용량 범위·중단 기준을 재검토할지, 추가 환자 부담을 어떻게 판단할지 회의 질문으로 연결했습니다. 이 부분은 규칙 기반 초안입니다.” |
| 2:45–3:00 | 일반 화면 → 회의 브리핑 저장 | “근거·가정·계산·확인 질문을 구분해 남깁니다. 최종 판단을 대신하는 것이 아니라, 다음 의사결정에서 검토할 내용을 명확하게 만듭니다.” |

여유가 있으면 ‘B만 독성 우려’ → 이전 결과 표시/저장 잠금 → 재계산 → 질문 변화를 보여준다.
A12/B45에서 한계 초과 군 선택 빈도는 각 군30명 2.4%, 60명 0.6%다.
수치는 합성 입력/seed에 따른 것이며 모델 정확도 증거가 아니다.

## 실패·지연 대응

- 새 모델 호출 지연: 중단 상태를 감추지 않는다. “실시간 호출은 중단하고, 표시된 이전 실행 기록으로 설명하겠습니다.”
- 합성 계산 실패: 성공 화면으로 자동 대체하지 않는다. 보관한 파일을 보여준다면 ‘사전 계산 기록’이라고 명시한다.
- 반복 클릭·발표 중 설치·인증 파일 열기를 하지 않는다. 대회 키를 화면/파일에 노출하지 않는다.
- 이 대본은 타이머 리허설/영상 완료가 아니다. 실제 리허설·발표 환경·공식 요건 확인이 남았다.
