## 이번 범위

- 기본 화면: 약물명 또는 NCT 하나, 고정 목적 ‘용량 비교를 위한 근거·KOL 브리핑’, 공개 자료/대회 전송 동의 하나.
- 검색에서 범위가 모호하면 약물·적응증을 한 번 고른다. 검색 가능한 등록 표현 선택이며 별칭·병용약·유사 적응증을 임의 통합하지 않는다.
- 동일 범위의 시험이 여러 개면 결과/문서 접근성 점수로 임시 조사 시작점을 선택하고 이유를 공개한다. 임상 중요도 순위나 모든 시험 통합 분석이 아니다.
- 기존 검색 → 다중 출처 수집 → AI 계획 → 후속 검색 → AI 인용 검토 → 저장 결과 API를 연결한다. 범위 확인 후 첫 검색을 반복하지 않는다.
- 대회 provider/지원 모델/키 준비 상태를 검사한다. 요청 최대 2회, 자동 재시도·개인 Codex 전환 없음.
- 화면에는 실제 서버 작업 이벤트, 공개된 조사 계획, 경과시간과 단계별 상태를 표시한다. 내부 사고 전문이나 가짜 진행률을 만들지 않는다.
- 인용 연결 쟁점·KOL 질문을 주 화면에, 인용문·선정 이유·작업 기록을 펼침 영역에 둔다. 기존 세부 도구는 보조 메뉴로 이동했다.
- 최근 결과 열기는 저장된 조사/검색 GET만 사용한다. 이전 개인 Codex·수집 전용·MOC 기록을 새 대회 실행으로 표시하지 않는다.

## 진단 변경과 다음 재개

실행 중인 서버에는 이전 코드가 올라와 있어 위 실패의 정확한 분류는 저장되지 않았다.
계획 스키마, 없는 출처 ID, 허용되지 않는 후속 검색어 등의 어느 검증이 실패했는지는 아직 확정하지 않는다.

`trialboard/research/agent.py`에 안전한 실패 코드와 `validation` 상태를 추가했다.
응답을 받은 뒤 검증에 실패해도 `RECEIVED` 및 사용량을 보존한다. 오류 원문·모델 원문·키는 저장하지 않는다.
모델 프롬프트·스키마·공급자나 예산을 이번 변경에서 바꾸지는 않았다.
구조화 출력도 내용의 정확성을 보장하지 않으므로 출처/인용 검증을 우회하지 않는다.
[공식 Structured Outputs 안내](https://developers.openai.com/api/docs/guides/structured-outputs).

다음은 README의 `--agent-provider dacon --prompt-dacon-key` 명령으로 서버를 재시작하고
키를 사용자가 비표시 입력한 뒤 제한된 실제 실행을 확인하는 것이다. 기존 키를 파일/채팅/프런트엔드에 옮기지 않는다.
현재 API 프로세스는 키와 함께 유지했다. 새 진단 및 이전 정규화 계약은 재시작 후 적용된다.
