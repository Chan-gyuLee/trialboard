# 분리된 숫자와 %의 검토 기록

2026-09-16 · 좁은 첫 지원 범위 · 임상 표 자동 이해나 전문가 승인 아님.

## 바뀐 흐름

PDF 추출 문구가 `36`과 `%`로 나뉘어도 원문 값을 `36%`로 덮어쓰지 않는다.
숫자 인용과 단위 인용을 별도로 보존하고, 사람이 확인한 해석값 `36%`를 추가한다.
이 해석은 수정 이력, JSON 복구, 로컬 프로젝트 저장, 규칙 재검증, AI 재검토 입력,
설계 비교의 입력 검증, 검토/회의 Markdown에 연결된다.

1. 필드 검토에서 ‘보고된 비율 · 건수 미보고’ 관측값의 ‘보고 비율’을 선택한다.
2. 원문 숫자 문구를 기본 인용으로, 별도의 `%` 문구를 보조 근거 ‘단위’로 연결한다.
3. ‘숫자와 %가 따로 추출됐나요?’에서 해당 단위를 선택한다.
4. 점추정치이며 같은 셀·환자군이라는 두 항목을 원문에서 직접 확인한다.
5. 해석을 연결하고 기본 원문으로 돌아가 사유·원문 대조 확인과 함께 수정값을 기록한다.

해석을 연결하는 버튼만 누르면 편집 중 상태다. 최종 수정 기록과 프로젝트 저장은 별도다.
원문 숫자, 단위, 해석값은 서로 다른 역할이다. 사건 수를 비율에서 역산하지 않는다.

## 계약과 제한

- `pdf-field-review/3`, 선택 필드 `Value.normalization`, 방법 `adjacent-percent/1`.
- v1/v2 파일은 그대로 읽으며 새 메타데이터가 없는 기존 직렬화 결과를 유지한다.
- 원문 전체가 단독 숫자, 단위 문구 전체가 `%`인 경우만 지원한다. 범위는 0–100%다.
- 같은 페이지, 숫자 오른쪽 간격 -0.002–0.04 페이지 폭, 세로 겹침 최소 50%를 요구한다.
- 가까운 같은 줄에서 CI/confidence/p value/신뢰구간 문구가 탐지되면 거부한다.
  이는 완전한 통계 표현 판독이 아니며 누락된 표현·잘못된 PDF 추출은 판별하지 못한다.
- 사용자 확인 두 항목은 실제 boolean true만 허용한다. 신원·전문성·실제 대조 여부는 인증하지 않는다.
- 표 머리글, 다른 열/페이지, 범위·CI 경계, 용량 단위 변환, 분모·집단 자동 연결은 미지원이다.
- 원본 PDF의 바이트 hash와 내보낸 문구/좌표의 일관성을 검사한다. 서버가 PDF를 다시 추출해
  좌표나 의미의 진위를 검증하는 기능은 아니다.
- 재검증 결과의 `normalized_rates`와 AI 입력의 `user_normalized_rates`는 원래 extraction과 분리된다.
  AI 최초 추출은 아직 이 계약을 생성하지 않는다. 설계의 확률 가정도 비율로 자동 채우지 않는다.
- 보류된 행은 해석값 전달에서도 제외한다. 과거 이력의 단위/숫자가 변조되면 복구·재검증을 거부한다.

## 확인한 범위

자동 검사: 합성 계약의 정상 해석, 잘못된 해석값/단위/위치/CI, 확인값 강제 변환,
구버전 강등, 보류 제외, 원문 불변, Python↔브라우저 재검토 교환, 프로젝트 재열기.
브라우저: 기존 MOC PDF → 비율 관측값 추가 → 보고 비율 선택 → 새 안내와 기록 비활성 상태,
사유 입력 및 새 패널/버튼 간격을 데스크톱에서 직접 확인했다.
**성공 해석의 전체 UI 저장·복구 및 모바일 QA는 이번에 완료하지 않았다.**
모델·외부 검색 호출 0회. 실제 임상 문서의 정답률 검증과 구분한다.

현재 켜져 있던 API 프로세스는 이전 코드다. 새 백엔드 계약 적용에는 API 재시작이 필요하다.
대회 키는 기존 서버 메모리에만 있으므로 재시작할 때 기존 비표시 입력 절차로 다시 넣는다.
이번에는 해당 프로세스와 키를 유지했고 별도 테스트 프로세스에서 새 코드를 검증했다.
