# 설계 비교·KOL 작업공간

2026-09-14. 코드 기준 구현. 기존 배포 사이트에는 아직 반영하지 않았다.

## 사용자가 하는 일

1. 자료 검토 → PDF를 열고 필드 검토를 진행하거나 같은 PDF의 저장한 검토를 복구한다.
2. **설계 비교·KOL** 탭으로 이동한다. 넓은 화면에 설계 입력 / 결과 비교 / KOL 회의가 나뉜다.
3. 재검증 결과에서 질문을 연결하거나, 원래 추출·재검증 질문을 그대로 입력한다.
4. 원문 용량군 2–4개를 추가하고 각 군의 반응·이상반응 관측값을 하나씩 연결한다.
5. 표본수가 다른 설계 2–4개와 가정 시나리오 1–6개를 입력한다. 확률은 0–1이다.
   임상적 기본값·표본수 추천은 없다. 원문 관측 비율을 참확률로 복사하지 않는다.
6. 설계 입력 JSON을 내려받아 [CLI](DESIGN_COMPARISON.md)로 계산하거나 아래 로컬 연결을 사용한다.
7. 결과를 가정별로 비교한다. 표본수, 선택·보류·가정상 한계 초과 군 선택 빈도, Monte Carlo SE를 표시한다.
8. KOL 질문에 사용자 답변 메모·담당자·다음 행동·변경 사유를 기록하고 회의 JSON/Markdown을 보관한다.

기존의 CSV 기반 ‘가정 실험’은 별도 합성 예제다. 이 문서의 작업공간은 **현재 PDF의 필드 검토에 연결**된다.
현재 설계 차이는 고정 표본수뿐이다. 임상 프로토콜·적응형 시험·권장 용량을 자동 생성하지 않는다.

## 선택적인 로컬 계산

저장소에서 한 터미널, web 디렉터리에서 다른 터미널을 연다.

```bash
uv run python -m trialboard.api --enable-designs
```

```bash
cd web
npm run dev
```

- Node 24. 웹 주소는 `http://127.0.0.1:5173` 또는 `http://localhost:5173`이다.
- Vite가 `/api`를 `127.0.0.1:8000`에 중계한다. 다른 원격 주소·배포 사이트에서는 이 기능을 실행하지 않는다.
- 기본 API 실행은 PDF 계산을 **비활성화**한다. `--enable-designs`를 명시한 경우만 경로를 연다.
- 에이전트에서 시작한 검토는 최초 에이전트 결과 파일을 연결한다. 원문 JSON·PDF·검토 이력은 현재 화면에서 묶는다.
- 직접 추가한 검토는 약물·적응증·시험 문맥을 입력한다. 질문은 설계 입력과 동일하게 사용한다.
- AI 의견을 반영하려면 **여기에도 현재 완료된 AI 재검토 파일을 명시적으로 연결**한다.
  다른 패널에서 열어 본 파일이나 이전 파일을 자동 탐색하지 않는다. 없으면 미제공으로 표시한다.
  연결 후 검토가 바뀌면 과거 AI 파일을 자동 생략하지 않고 교체/명시적 해제 전 실행을 막는다.
- PDF·검토·가정·연결 파일을 **내 컴퓨터의 Python 서비스로 전송한다는 체크박스 동의** 후 계산한다.
  화면 입력이나 문맥·연결 파일이 바뀌면 동의를 다시 받는다.
- API는 원본 PDF hash와 현재 검토를 다시 검사한 뒤 계산한다. 파일 저장·모델 호출·API 키 사용이 없다.
- 다른 PDF/질문/이력, 미확인·보류, 문맥 충돌, 관련 AI 비교 한계는 거부 또는 계산 차단한다.
- 취소/60초 대기 제한은 브라우저의 응답 채택을 중단한다. 서버의 이미 시작한 계산을 강제 종료하는 것은 아니다.
- localhost 경계는 사용자 인증이나 기업용 보안 체계가 아니다. 환자 정보·기업 기밀자료를 넣지 않는다.

## 결과와 회의 메모의 버전

입력 가정·표본수·사유 또는 필드 확인 이력이 바뀌면 기존 계산과 회의 메모를 현재 결과로 표시하지 않는다.
미기록 필드 편집도 동일하게 차단한다. 새 계산 성공 시 기존 결과/메모가 바뀌므로 UI에서 보관 여부를 확인한다.
자동 저장은 하지 않으며 브라우저를 닫기 전에 필요한 JSON을 직접 내려받아야 한다.

- `design-brief/1`: 현재 PDF·전체 검토 이력 hash에 연결한 사용자 입력. 입력 JSON 복구 지원.
- `design-comparison/1`: 원문/검토/설계/엔진 hash, 실제 가정과 표본수, 규칙·선택적 AI 기록, 계산·KOL 의제.
- `kol-meeting-notes/1`: 전체 비교 결과의 hash에 묶인 사용자 메모. 질문별 최대 40회, 전체 200회 수정 이력.
- `trialboard-meeting-packet/1`: 비교 결과와 메모를 함께 저장한다. 같은 PDF·같은 검토를 먼저 복구해야 다시 열 수 있다.

메모 상태는 미해결 / 답변 메모 있음 / 추가 확인 필요다. ‘전문가 승인’ 상태는 없다.
추가 확인에는 담당자와 다음 행동, 답변 기록에는 답변, 모든 수정에는 사유가 필요하다.
메모가 계산 차단을 해제하거나 가정·원문 값을 자동 변경하지 않는다. 답변에 따라 가정을 바꾸면 다시 계산한다.
설계 가정 자체의 자동 수정 이력/다중 실행 프로젝트 저장은 아직 없다. 실행별 JSON을 별도로 보관한다.

회의 Markdown에는 원문 인용·페이지·관측값, 사용자 가정, 표본수·결과·MC SE, 질문·메모·전체 수정 이력과 제한을 넣는다.
JSON에는 원문 텍스트와 검토 이력이 포함되므로 공유 범위를 확인한다. 파일 hash는 작성자나 실행의 진위를 인증하지 않는다.

## 검증 범위

- Python 출력 → 웹 입력 검증: 현재 버전, 근거 참조, 계산 조합, 확률 합계/반복 수/참값 집계/MC SE/차이/질문 참조.
- Python/JavaScript의 `0.0`, 작은 지수 표기 차이는 `brief_canonical` 원문 hash와 파싱된 입력 구조를 함께 검사한다.
  이 필드가 없는 초기 설계 결과는 현재 CLI로 재생성해야 한다.
- 웹 입력 → 실제 Python 계산 → 웹 결과 읽기, 회의 JSON 복구, 변경된 검토/AI/출처·한도·오류 회귀 검사.
- 별도 작은 표본 이항 전수열거 코드로 고정 배정 시뮬레이션 선택·보류 빈도를 대조한다. 임상 타당성 검증은 아니다.
- [합성 시연 절차](DEMO_REHEARSAL.md)는 실제 PDF 파싱과 로컬 HTTP 계산을 통과했다.
- 권한 적용 후 로컬 스크린샷·PDF 업로드/렌더링·필드 검토 진입 확인. macOS 파일 선택창 제어 문제로 **회의 복구 이후 클릭/반응형/키보드 QA는 미완료**다.
